经官方仓库核对

十分钟，运行你的第一个 Harness。

从 Web UI 启动，到模型、工作区和第一项任务；然后再理解 profile、配置叠加与插件。每一步都标明真实行为，而不是把安装命令当成完整教程。

开发者预览：官方明确提示会发生破坏兼容性的变更。生产使用前请固定版本并阅读发行说明。核对基线：官方提交 47f9438，2026-08-13。
01 / START

在项目目录启动 Web UI

先安装 Node.js，再从准备作为默认文件系统位置的项目目录运行。首次执行会初始化 web profile；默认地址是 127.0.0.1:3080。

npx @deepseek-ai/dsh web

注意：启动目录只是默认文件系统位置。新的 Web UI 仍未选择工作区。

02 / MODEL

配置模型，不要把密钥写进项目

打开 Settings → Models，在 DeepSeek 卡片保存 API Key。修改会在下一次请求生效，无需重启。密钥是只写的：界面保存后只接收脱敏描述。

密钥位置

$DSH_HOME/.credentials.yaml

设置仅保留 credential reference，不保存明文副本。

其他提供方

可以添加目录提供方，或填写小写 Provider ID、Base URL、协议、凭证和至少一个模型来接入自定义兼容端点。

03 / WORKSPACE

选择工作区，再发起任务

点击 Choose workspace，添加并选中项目目录。未选择工作区时，消息输入区保持不可用。随后创建会话并发送一个可验证的小任务。

Summarize this repository and identify its main packages.

Agent 可以读取和修改文件、运行命令、委派工作并维护计划；当前权限策略要求审批时，Web UI 会先询问。

04 / PROFILES

选择运行方式

DSH 启动的是 profile：按顺序组合插件 bundle，再叠加用户配置。Web 是别名；headless 适合一次性任务。

命令用途
dsh web启动 Web profile
dsh --profile headless "job"执行一个持久化会话，打印最终答案后退出
dsh --profile web --port 8080把后续参数交给 Web 应用
dsh --profile web --dump-config不启动应用，检查最终组合配置
05 / EXTEND

理解配置顺序，再安装插件

组合顺序是：bundle patches → profile 的 cordis.patch.yml → $DSH_HOME/cordis.patch.yml → 命令行 --patch。后面的层覆盖前面的层。

dsh plugin --profile web add <package>

插件命令把参数转交给 profile 目录中的 pnpm。第三方包先按生态页的来源、权限、配置与回滚清单审查。
