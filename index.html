使用 Web UI

用 DeepSeek Harness 启动你的第一个智能编程任务。本指南将带你完成模型配置、工作区选择和首次运行。

i
开始之前

建议使用 Node.js 22.19+ 或 24+（与上游源码工作区一致），并准备 DeepSeek API Key 和一个允许 Agent 读取的本地项目。

安装与启动#

在终端中运行以下命令。DSH 会在当前目录启动服务，并打印 Web UI 的访问地址。

Terminal
$ npx @deepseek-ai/dsh web
Web UI → http://127.0.0.1:3080
公开预览版本

截至 2026-08-16，npm 的 latest 与 next 都指向 0.1.0-rc.6，而当前上游默认分支 manifest 仍为 rc.5。未指定版本的 npx 会跟随 dist-tag；自动化脚本应固定确切版本。

运行一次 Headless 任务#

Headless profile 适合 CI 或脚本：它创建一个全新的持久 Session，提交任务，等待 Agent 完全空闲并 flush 日志，然后把最后一个非空 Assistant 文本打印到 stdout。

Terminal
$ npx @deepseek-ai/dsh --profile headless "run the tests and summarize failures"

最终 turn 原因为 completed 时进程以 0 退出，否则以 1 退出。随附 Headless 组合不会启动 HTTP Server、Web Runtime 或浏览器 Client，成功路径也不会向 stderr 写入内容；缺少任务文本属于用法错误。

启动前检查组合配置#

配置问题不必等到服务启动才发现。dump-default-config 只展开 bundle 默认层；dump-config 还会叠加 profile、本机 DSH_HOME patch 和命令行 patch，并为每一行标注来源。

Terminal
$ npx @deepseek-ai/dsh --profile web --dump-default-config
$ npx @deepseek-ai/dsh --profile web --patch ./extra.yml --dump-config

Dump 不运行应用参数提供方，因此展示的是解析 Web 的 host/port 等参数之前的配置；同一次调用若还包含应用参数会被拒绝。Patch 替换目标行的整个 config，而不是递归合并字段。

配置模型#

打开右上角的 设置 → 模型，选择 DeepSeek，输入 API Key 并保存。模型变更会在下一次请求时生效，无需重启服务。

    进入模型设置

    点击设置图标，在侧栏选择「模型」。

  2. 2
    添加凭证

    选择服务提供方，并粘贴你的 API Key。

  3. 3
    确认凭据与路由

    绿色圆点只确认具名凭据已经配置；还要在会话模型选择器中确认所选路由可用。

凭据不会返回浏览器

API Key 是只写字段。保存后前端只会收到脱敏描述符；明文保存在 $DSH_HOME/.credentials.yaml，settings 中只保存凭据引用。

自定义提供方

公司网关或自建 OpenAI 兼容端点可通过「添加自定义提供方」配置。Provider ID 会被请求、会话、默认模型和凭据引用使用，因此保存后应视为永久标识；展示名称、URL、协议和模型仍可修改。

MISSING_CREDENTIAL在模型页保存密钥，或提供配置引用的环境变量。
UNKNOWN_MODEL重新选择已配置模型，或在自定义提供方中添加模型。
401 /models检查凭据；不提供模型发现端点时应手动录入模型。

首次启动与模型就绪诊断#

首次使用引导不会把“页面上存在模型名称”误当成模型已经可调用。只要任意已注册路由拥有已配置的具名凭据，或该路由使用 Bedrock、Vertex ADC 等原生认证，引导就会自动完成；否则才提示填写 DeepSeek 官方密钥。

会话选择的 provider 当前必须有活跃适配器；否则输入框会被阻塞并提示重新选择模型。

模型目录只是建议列表，不是路由白名单：一个未列出的模型仍可能由适配器解析，而目录中可见的休眠提供方也可能暂时不可调用。真正发送 prompt 时，宿主会再次执行权威检查，并以 model-unavailable 拒绝不可路由的选择。

引导跳过不代表配置成功

适配器缺失、配置能力只读或联接失败时，凭据步骤会直接让位，Models 页面仍是诊断入口。保存密钥后无需重启；DeepSeek 路由会在下一次调用时重新解析凭据。

会话模型选择如何收敛#

/model 与输入框的模型入口共用同一份会话级目录，通过 Host 提交完整的 provider、model 与 reasoning effort。打开选择器会刷新目录；提供方元数据失败以内联不可选行呈现，其他可用分组仍能继续选择。

Host 选择才是真源

目录只负责呈现。当已选 provider/model 不再出现在公布分组中，路由选择仍可保持有效，但触发器回退为 Select model，也不会显示陈旧 Effort。

旧响应不能覆盖新选择

目录加载与选择操作共用单调代次。选择失败会保留上一次选择和可用分组；较旧请求即使迟到也不能回写新状态。

重连重新建立目录

连接重置会丢弃常驻目录投影，再拉取 Host 恢复的选择；未变化的选择子结构保持稳定，避免无意义的 UI 抖动。

目录缺失不等于输入必须阻塞

只有 Host 明确报告 routable: false 才禁用输入框；首次加载前或加载失败后的 null 不阻塞。已寻址的 subagent 不公开模型选择入口，也拒绝目录刷新和选择操作。

选择工作区#

点击「选择工作区」，添加你启动 dsh 时所在的项目目录。工作区决定 Agent 能够读取和修改的文件范围。

注意

选择工作区前，会话输入框保持禁用。请勿将包含敏感凭证的目录设为工作区。

工作区列表如何收敛#

Workspace 与 Session 列表各有独立的 pending → ready 基线。基线请求进行时到达的新增、更新、移除和顺序帧不会丢失，而是在响应之上重放；重连后的新基线会接纳其他客户端在离线期间提交的持久顺序。

拖拽先乐观显示

Workspace 拖拽会立即安装本地顺序，再等待 Host 确认。只有最新请求的回声可以结算它，更新的 Host 顺序帧又优先于较旧回声。

失败回到已确认值

最新排序请求被拒时，列表恢复最近一次 Host 确认的顺序，不会倒退到更早、且仍未提交的某次拖拽。

删除不会被迟到帧复活

已移除的 Workspace id 在当前进程保留删除标记，延迟到达的 changed 帧不能重新插入它；删除成功后相关 Session 转入 Ungrouped。

Workspace 的拖拽顺序始终由 Host 持久化。Session 顺序则取决于视图：真实 Workspace 的手动排序可写回 Host，Ungrouped 与跨 Workspace 的单列表没有共同记账，只保存在当前浏览器。

列表顺序不是目录权限

重排、折叠或删除 Workspace 注册记录都不会移动项目目录，也不会删除 Session 日志。它们只改变 Host 记账与浏览器投影。

工作区目录如何选择#

目录选择不是浏览器自行读取磁盘，而是由宿主提供稳定的能力。自适应后端只在启动时判定一次：本机回环访问、非 SSH 且存在可用桌面会话时使用原生系统对话框；远程、无显示或情况不明确时使用应用内浏览器。

Native

在宿主屏幕打开系统选择器。macOS 使用 osascript，Linux 使用 Zenity 或 KDialog，Windows 使用 IFileOpenDialog；取消返回空结果，中止会终止原生进程。

Browse

由宿主列举绝对路径中的目录，适合远程客户端。每层默认最多 1000 项，只返回目录并按名称排序，也可以创建一个经过校验的子目录。

浏览范围不是沙箱

当前 Browse 后端没有限定根目录，工作区创建也接受任意已有目录；目录选择器只负责交互体验，真正的写入边界仍由权限和沙箱策略决定。

运行第一个任务#

新建一个会话，然后尝试发送一个目标明确、可以验证的任务：

总结这个仓库，列出它的主要模块，并解释各模块之间的关系。

Agent 可以读取文件、执行命令并维护计划。当某项操作超出当前权限策略时，Web UI 会先请求你的批准。

New Session 与空白会话复用#

进入某个 Workspace 的 New Session 时，客户端先寻找该 Workspace 记账中的既有空白会话；只有同时满足 blank、cwd 等于 Workspace 路径、且 id 属于其 sessionIds 才复用，否则由 Host 创建新的 Session、Agent 与 cwd。

目标有明确优先级

新会话优先使用显式选择的 Workspace，其次是当前 Session 所属 Workspace，再其次是最近活跃 Workspace；完全没有 Workspace 时进入未选择的空白页面。

Host 接受才算使用

首条 prompt 的 RPC 成功意味着消息已进入 Host 日志，此时 blank 单向变为 false。首讯被拒时保持 blank，之后仍可安全复用。

占位行不是历史

空白 Session 保留在运行时 store，但普通列表隐藏它；临时“新会话”行没有时间、菜单或可复制标题，首条提示落地后才开放重命名、fork 与归档。

只匹配 cwd 不足以复用

路径相同但不在目标 Workspace 记账中的空白 Session 不会被接管。成员关系与 blank 位都来自 Host 投影，避免不同工作区意外共享同一会话。

侧边栏会话行的注意力状态#

Session 行把当前需要用户处理的交互归为等待审批、计划待审或等待回答，并使用琥珀色警告点。运行中使用蓝色指示器；悬浮卡片与视觉隐藏文本会给出相同的本地化状态，而不是只靠颜色传达。

请求在打开前已跟踪

Manager 按稳定请求 id 缓冲 requested 与 resolved 帧，即使 Session 对象尚未实例化。回放重复项会被替换，已解决项会被移除。

交互优先于运行

待处理交互是会话行的主要状态，优先于自身运行指示。审批与普通问题并发时，第一个待回答问题优先，以匹配输入框路由。

重连只恢复仍待处理项

pendingInteraction 只在当前连接代次有效；断线时清空，mux 重新打开后的权威回放不会复活已经结算的请求。

子代理 Session 行在共享侧边栏隐藏，但可见 parent 会聚合不间断 subagent 谱系中的运行后代数量。普通 fork 会开启独立子树，不计入聚合；主要交互或自身运行都不存在时，后代活动才优先于绿色未查看完成提醒。

父行变蓝不代表父 Agent 在运行

蓝色可能来自运行中的子代理。悬浮与无障碍文本会报告确切后代数量，最后一个后代停止后，先前的未查看完成提醒会重新出现。

Session 的仅追加事件日志#

SessionEvent 日志是一次 Agent 交互的唯一真源；模型消息历史、UI 状态和回放结果都从同一序列派生，不存在另一份单独维护的 transcript。每条事件都有连续 seq 和毫秒时间戳，payload 必须是无损 JSON。

01Turn

一次排队输入的生命周期；拒绝或空输入也可能只有 start/end 而没有模型步骤。

02Step

一次模型调用及其请求的工具执行；重试会打开新的编号步骤。

用户消息、组装后的 Assistant 消息和工具结果形成模型可见表层。

Agent 投递、空闲与取消#

Agent 的公开句柄把所有输入路由到持久 Inbox。next-turn 保存普通后续轮次，next-step 保存最近步骤要消费的 steering 或注入上下文；每条消息拥有稳定 MessageId，并记录插入、认领或丢弃事实。

followup

唤醒 Agent，并让该消息成为自己轮次中的唯一普通输入。

steer

运行中在最近的下一步骤进入；空闲时会主动开启一个轮次。

inject

为下一次 pre-step 排队模型可见上下文，但不会自行唤醒空闲 Agent。

cancel 只中止当前活动并默认清理排队与 steering；keepInbox 可以保留尚未开始的工作。whenIdle 等待整个 Agent 达到真正静止，包括取消后的收敛、替换工作和 maintenance task，而不是确认某一条消息已经得到回答。

拥有 Handle 才拥有销毁能力

创建或恢复 Agent 的调用方拿到 AgentHandle；dispose 会停止 loop、等待退出、注销 Agent、移除内存 Session，最后展开整个 Agent scope。普通 registry 查询只返回不可销毁的 Agent。

运行中的实时消息队列#

Web UI 的 Queue 是实时控制面，不是从聊天记录猜出来的视图。宿主在队列变化及重连时发送完整的 session/queue 快照；每项由稳定的 MessageId 寻址，因此编辑、删除和插话都只作用于那一次入队。

Queue

保留为下一轮输入，当前轮次结束后按 FIFO 领取。取消 Web 会话中的活动轮次会保留这些待处理项。

Steer

尝试在最近的下一步骤插入用户指引；若窗口已经关闭，则安全退回普通 Queue，不丢失草稿。

Context

审批通知、任务完成和附件快照等注入上下文在领取前不向用户界面展示。

队列只有一项时直接显示，多项时默认折叠并可逐项编辑、删除或严格 steer。若 Agent 已经领取目标项，操作会收敛为“已开始投递”，客户端不会靠轮次状态擅自移除或重发消息。

Queue 编辑与严格插话#

QueueDock 中每个普通会话条目都是一行预览，但预览文本不等于完整消息。内联编辑器只能无损处理纯文本，因此包含图片或其他非文本块的条目仍可查看、删除和严格 steer，却会禁用编辑按钮。

纯文本编辑是事务

进入编辑后，删除与严格 steer 按钮替换为保存和取消；Enter 保存，Escape 取消。编辑进行中列表保持展开，不会把操作目标折叠掉。

严格 steer 转移原消息

Agent 运行时，这项操作把稳定 MessageId 指向的不可变完整消息原子转移到当前 next-step 窗口，而不是重新发送扁平化文本预览。

Subagent 行保持只读

已寻址 subagent 的继续执行传输不支持 Queue 变更，所以可见行不提供编辑、删除或严格插话，不伪造宿主无法兑现的操作。

待处理 steering 从 QueueDock 隐藏后，会立即在 Chat 尾部显示为用户样式气泡；Host 等对应的持久 user/message 进入 mux 流才退役临时项。交接因此没有空档或重复，并能从同一权威在重连和回放后恢复。

已关闭窗口不是发送失败

如果严格 steer 输给已经关闭的 next-step 窗口，原条目留在 Queue 中正常投递；如果驱动器已经认领它，投递已经开始。这两种已收敛竞态不显示错误，只有传输或未知故障才会报告失败。

权限与审批#

Harness 把沙箱模式和审批策略作为两项独立机制。权限预设只是在产品层把两者组合成一个选择器；执行时仍由各自服务单独强制。

沙箱模式

read-only只读文件变更被拒绝，读取保持可用。
workspace-write工作区写入仅工作区和平台临时目录可写；默认搭配 ask。
danger-full-access完整访问不添加文件围栏；默认搭配 never。

文件系统围栏会在目标规范化后检查可写根，并在写入前重新规范化以缩小符号链接竞态。不过它是可信进程中的策略围栏，不是针对恶意宿主代码的内核安全边界。

一次性审批

审批结果只有 allowed-once、rejected、cancelled 和 unavailable。每次决定都会写入成对审计事件；没有应答者或应答失败时默认拒绝。never 策略会在交互分发前确定性拒绝请求。

权限预设与 custom 状态#

Permission Preset 只是把沙箱模式与审批策略这两个独立强制旋钮包装成一个客户端选项。预设自身不执行隔离，也不替代审批；切换时仍通过各自服务的规范 setter 写入日志。

workspace-write

默认组合为工作区写入加 ask，适合交互式开发。

danger-full-access

默认组合为完整访问加 never，只应在受控环境中使用。

custom

当两个旋钮不匹配任何声明预设时派生显示；它不是可选择的目标。

当前值从 Session 日志中实际生效的旋钮推导，而不是盲信最后一次选择。若多个预设共享相同组合，仍匹配的最后选择优先；否则按声明顺序选择首个匹配项。重新选择当前预设不会追加任何事件。

审批的完整链路#

每一次审批请求都有全新的 ApprovalRequestId，用于把 approval/asked 与 approval/decided 配成一组。请求只携带 Agent、工具名、可选 call id 与理由；工具参数仍由已经流式展示的调用负责，避免 UI 渲染第二份可能漂移的数据。

01Policy

never 在应答者运行前直接拒绝；ask 才进入组合链。

→
02Waterfall

UI 或 ACP 应答者可认领请求，否则交给下一个；异常与非法返回值归一为 unavailable。

→
03Audit

只有 asked 与 decided 都越过日志提交点，结果才会返回调用方。

只有 allowed-once 会放行

取消信号会立即撤回问题，迟到的答案被丢弃。审批审计事件不会进入模型 transcript；模型只看到工具派生结果和最新的运行时上下文快照。

审批如何接管输入区#

审批等待期间，ApprovalPanel 取代普通 InputBar 占据同一个 composer 位置，用琥珀色状态条展示理由、与运行中工具调用参数配对的命令行，以及一次性的拒绝或允许按钮。未决审批不会再在消息流中留下只读占位卡。

01Project

运行时把审批与问题统一投影为 pendingInteraction；Session 尚未实例化时，侧边栏也能显示待处理状态。

→
02Answer

用户在 composer 接管面板中作答，响应值携带审计关联，不从工具参数复制第二份可能漂移的数据。

→
03Restore

收到 approval/resolved 广播后等待落定，原输入栏恢复；迟到或重复响应不能重新打开已解决请求。

当前没有“始终允许此类”

持久授权仍需要独立的授权存储设计；当前审批面板只能允许一次或拒绝。不要把一次允许解释为以后同类工具都会自动通过。

编辑器底部的 Access 选择器是另一条路径：普通安全预设会提交权限命令；选择 Full access 时必须先经过页面内风险确认，勾选确认项前启用按钮不可用。取消、Escape、关闭或点击遮罩都不会提交权限变更。

E2B 远程执行运行时#

E2B provider 让文件系统、Bash、PTY 和 LSP 共享同一个短暂远程 Linux 沙箱，而 Cordis 服务、Agent、Session 日志、LLM 请求与 SDK 缓冲仍留在宿主进程。宿主 API Key 只用于创建 SDK 连接，绝不会注入沙箱环境。

01Own

共享 owner 创建远程 cwd 和权限为 0700 的私有适配器目录。

→
02Adapt

远程 fs 与 subprocess provider 复用同一个句柄和进程命名空间。

→
03Dispose

先停止新操作并清理进程，再删除沙箱；超时同样会删除全部状态。

远程 cwd 不是同步或包含边界

本地工作区不会自动上传或同步回来；把宿主路径写进 cwd 只会远程创建同名目录。命令仍能访问沙箱中的其他路径，网络策略沿用 E2B 基础镜像。

创建第一个插件#

本地开发时，通过 patch 层加载绝对路径，并以 Web profile 启动：

Terminal
$ pnpm dsh web --patch ./scratch-plugin/cordis.yml

开发一个 Tool#

工具插件通过 inject = ['tools'] 声明依赖，再用 defineTool 同时定义参数校验、规范输出和模型可见的渲染结果。

01声明输入

Parameters 会推导并校验 execute 的参数。

02返回规范值

execute 返回由 output schema 约束的数据。

03渲染模型内容

render 将规范值转换为模型真正看到的结果。

Code Mode 的嵌套工具调用树#

Chat 按 call id 配对根工具调用与结果，再把 Code Dispatch 的 start 与 settlement 折叠进该根 Context。每个 ToolCallBlock 通过 subCalls 按启动顺序递归拥有 child；child 不会成为独立 Chat 根记录。

缺少开始事件仍可呈现

如果 start 位于尚未加载的更早历史，已到达的 settlement 仍会显示，只把 callTime 留为 null，不伪造启动时刻。

更新保持兄弟身份

一次 child 更新只复制从该节点到根的祖先链；未变化 sibling 保持对象身份，避免整棵调用树无谓重绘。

异常边不污染树

会形成环或超过固定 256 层上限的 parent-child 边会被消费，但不会修改投影，阻止恶意或损坏日志制造无限递归。

UI 从 root 递归遍历同一份标准调用块，每个原子调用都走同一个 keyed tool view slot；没有专用视图的工具使用通用卡片。Trajectory 为自身 target 独立组装同一种嵌套契约，不读取 Chat 的树。

业务 UI 不拥有调用拓扑

工具插件只注册 wire 名称与原子视图，不应自行配对事件或重建 transcript。Runtime 决定 root/subcall 关系与生命周期，Conversation view 决定它在聊天流中的位置。

配置 Schema#

插件通过同名的 TypeScript Config 类型和 Schemastery schema 接受配置。默认值属于 schema；无效配置应在插件加载时立即失败，而不是运行到一半才降级。

config.ts
export interface Config {
  timeoutMs: number
  mode: 'fast' | 'accurate'
}

export const Config = Schema.object({
  timeoutMs: Schema.number().default(30000),
  mode: Schema.union(['fast', 'accurate']).default('fast'),
})
判断标准不同部署是否可能需要改变这个值？如果是，它就应该是配置字段，而不是硬编码常量。

修改 cordis.yml 会触发插件热替换：旧实例先卸载并清理 effects，新实例再使用已校验的配置加载。

事件系统#

事件是插件间松耦合通信的核心机制。Cordis 提供四种模式，它们的执行与返回规则不同：

emit同步广播

执行所有监听器，忽略返回值。

bail同步短路

首个有效返回值会停止后续监听器。

serial异步顺序

按注册顺序等待，同样支持短路。

waterfall包装流水线

监听器包装下游返回值，形成处理链。

Waterfall 的关键规则

监听器必须调用 next() 才会继续下游；不调用会有意短路整条流水线，适合拦截器和网关。

Cordis 事件通常采用 namespace/action 命名。持久化的 turn/*、step/* 和 tool/* 是会话事件类型；观察它们时应监听 session/event 并检查 event type。

插件生命周期#

每个插件运行在独立 Fiber 中。依赖未就绪时等待，加载成功后进入 ACTIVE；必需服务消失时自动卸载，服务恢复后重新加载。

PENDING→LOADING→ACTIVE→UNLOADING→DISPOSED

ctx.on()、工具注册和 ctx.effect() 都由 Fiber 追踪，卸载时自动撤销。若多个清理步骤存在先后依赖，应放入同一个 effect 的 disposer 中串行执行。

Web Client 模块与启动图#

带浏览器界面的插件通过 package.json 的 dsh.client 声明加入 Web 启动图。Host 把每个 bundle 的地址、内容哈希、依赖边和预取标记组合进 window.__DSH_BOOT__；浏览器必须先验证整张图，才会启动任何模块。

01Scan

以 cordis.yml 所在目录解析包和 client 导出，启动阶段聚合报告所有损坏项。

→
02Serve

每个 bundle 从专用插件路由返回；未知 id 明确 404，不会落入 SPA HTML。

→
03Activate

immediately 只负责预取和登记，真正的激活顺序由 Fiber 依赖等待决定。

单个 bundle 的 rev 来自内容哈希，整图 rev 会随任一行变化。开发时 HMR 重新哈希并通过 SSE 广播；生产图不含 HMR。插件元数据会按包名缓存，因此插件集合变化需重启，单纯重建 bundle 则走 rebuilt 通知。

UI Slots：声明、选择与清理#

Client bundle 到达浏览器后，通过 Slot 注册表把组件贡献到已有界面。一次注册同时声明目标 slot、可渲染的子 slot、可选 store seat 与业务注入；这张声明表既是类型契约，也是运行时授权边界。

声明即授权

组件只能注册到已经声明的 slot，也只能渲染注册时列出的子 slot。未声明目标、重复子声明或跨 scope 复用同一 handle 都会在注册时失败。

Chain 由条目提名

每个 chain 条目提供纯 selector；按可选升序 priority、再按注册顺序检查，第一个返回非空值的条目获选，否则调用 owner fallback。

状态由运行时绑定

核心只传递裸 snapshot source；React selector hook 在 renderer 中绑定。Store actions 会移除 draft 参数后交给组件与 inject factory。

生命周期会收回整棵贡献

注册 disposer 不只移除当前组件，还会递归撤销它声明的子 slot、贡献记录与 store 挂载。声明代次与普通条目版本分开计数，让运行时识别过期授权。

模块可加载不代表 Slot 合法

Client Module Loader 负责下载、物化与 HMR invalidate；SlotCore 独立验证布局所有权。插件必须同时满足模块图和 slot 声明，不能靠运行时碰巧存在的组件路径绕过授权。

跨插件的 Slot 声明注入#

贡献方可以独立于声明方启动：调用声明注入后，目标 slot 已存在就同步执行回调，否则进入等待。声明被移除时回调 effect 同步释放，稍后重新声明会再次执行；贡献方自己的 fiber 卸载也会取消等待或撤销活跃贡献。

声明代次驱动

专用的单调 declaration epoch 只在声明出现或消失时递增。普通条目变化不会重启注入，但折叠后立即重建仍会触发新一代回调。

多项注册成事务

回调可返回一个 disposer，或由 generator 依次 yield 多个注册。中途 setup 失败会回滚已完成项，正常 teardown 则按逆序执行。

直接注册仍严格

注入 API 负责等待声明；直接向尚未声明的 slot 调用 register 仍立即抛错，不会隐式创建布局位置。

同一 tick 内先释放旧授权

声明绑定的 teardown 与注册账本变更同步发生，因此后续注册不会与旧声明持有的资源短暂重叠。这让 HMR 和条件布局切换保持确定性。

Client HMR 的替换顺序#

开发模式下，Host 轮询启动图中的客户端 bundle；只有内容 rev 真正变化才通过系统 SSE 发出 rebuilt 帧。浏览器把多个重建排入串行队列，避免两个插件替换过程交错。

01Stage

先 invalidate 缓存并 prefetch 新 bundle；此时旧 fiber 仍在服务，新 factory 只完成登记。

→
02Drain

从注册表删除旧项，等待旧 fiber 完全释放，再移除该插件拥有的样式标签。

→
03Mount

refresh 重新导入并挂载，随后等待新 fiber；启动失败会直接显露给 Loader 状态。

提供方 fiber 的激活代次包含服务 uid，因此替换服务提供方会由 Cordis 自动级联重载依赖方，不需要浏览器额外分析依赖图。没有 bundle watcher 时 SSE 链路保持空闲，不会伪造重建。

Bundle HMR 失败不会回滚

失败重载会让配置项进入 FAILED，而不是恢复旧 bundle；这不同于用户 patch 热重载的最后可用树策略。插件 React 状态也会随全新组件与 fiber 丢失，但连接、运行时和 Session 数据层不受影响。

用插件清单核对运行拓扑#

设置中的「插件」页面是当前 Cordis Loader 树的只读快照。它首次打开时才查询 Host，跳过结构性 group 行，并按 Loader 顺序列出条目 ID、模块标识、有效启用状态和根 Fiber 阶段。

active运行中根 Fiber 已经完成加载并处于活动阶段。
pending / loading尚未就绪依赖或初始化仍在进行，不能只凭配置行判断能力已经可用。
failed / unloading失败或退出中条目存在于 Loader，但其运行生命周期并非可服务状态。
null没有存活 Fiber快照无法区分从未启动、已结束或其他历史原因。

插件页支持按模块短名和条目 ID 搜索，但没有修改能力、失败历史或实时订阅；重新打开 Settings 才会取得新快照。它回答“现在加载成什么样”，而 --dump-config 回答“配置由哪一层引入”，两者要结合使用。

运行清单不提供来源归因

清单不会告诉你条目来自 bundle、profile、DSH_HOME patch 还是命令行 override。需要追踪来源时，请检查带逐行来源标注的生效配置；需要失败堆栈时，请查看 Host 启动日志。

Scope 路由与生命周期所有权#

Scope 用同一个注册上下文同时表达“哪个 Agent 能看见这项贡献”和“谁负责在生命周期结束时拆除它”。不透明的 ScopeKey 只按对象身份比较；事件使用路由载体过滤，但真实业务对象仍作为显式参数传递。

Global layer

立即存在，保存所有 Agent 都可见的具名与匿名注册项。

Scoped layer

按需创建，近层同名条目遮蔽全局项；读取本身不会意外创建状态。

Quiescent dispose

并发 dispose 会等待同一个完全停稳边界，精确撤销该 Scope 拥有的贡献。

同一层的具名条目保持插入顺序；匿名条目即使值相等也拥有独立身份。只有整个作用域层的所有 table 都为空时才回收它，避免删除一个注册表时误伤兄弟表。

Web Server 的路由与暴露边界#

GUI 的 HTTP Server 只是浏览器载体，不理解 Agent loop。请求先匹配 exact 路由，再匹配最长 prefix，最后交给唯一 fallback；重复路由或第二个 fallback 会在组装时直接报错。

127.0.0.1默认回环只供本机浏览器访问，是默认监听姿态。
0.0.0.0显式网络暴露服务本身没有 TLS、认证或 Origin 策略，会暴露给所在网络。
port: 0系统分配端口操作系统选择空闲端口，服务公开最终监听值。

静态 SPA fallback 对路径穿越返回 403、非 GET/HEAD 返回 405，未知扩展资源不会伪装成 JavaScript。关闭时同时停止监听并强制关闭 SSE 等长连接，避免插件卸载永久挂起。

Web API 的传输与安全边界#

Web API 使用 HTTP POST 承载上行 unary/respond，并以两条只向浏览器发送消息的 WebSocket 承载 mux 与 host 事件。每个请求先校验信封，再按方法校验业务载荷；响应回显原 rpcId。业务错误留在 RPC 结果中，HTTP 状态只表达传输层结果。

01JSON gate

所有 API POST 必须声明 application/json，否则在分发前返回 415；跨站简单请求因此不能直接触发有副作用的方法。

→
02Origin gate

原生目录选择、设置、凭据和本地文档操作属于特权面，浏览器载体将它们限制在回环地址的同源请求；应用内目录浏览仍经过 Host 与 Origin 信任栅栏。

→
03Host gate

路径由宿主根据预设 ID 或无路径操作解析；浏览器载荷不能指定任意文件去打开。

不要把监听地址当成认证

底层 Web Server 本身不提供 TLS 或用户认证。需要远程访问时，应在可信反向代理后增加 HTTPS 和访问控制，并审查诊断错误是否适合向多用户公开。

Host 原生打开与桌面可见性#

host.openPath 把已由 Host 解析的路径交给操作系统默认应用：macOS 使用 open，Windows 使用 Invoke-Item，桌面 Linux 使用 xdg-open。共享 runner 直接 spawn 可执行文件并传递参数，不拼接 shell 字符串；取消会传播到原生子进程。

能力声明

host.describe.canOpenPath 根据显式 nativeOpen、注入 opener 或平台显示探测发布；断线时客户端清空该能力，不沿用旧判断。

WSL 路径交接

Linux 路径先经 wslpath -w 转成 Windows 或 UNC 路径，再交给 Windows 应用，包括 HTML、SVG 等浏览器文档。

浏览器双重门禁

界面只有在页面来自 loopback 且 Host 同时声明能力时才呈现原生操作；请求仍受同源与特权方法栅栏约束。

Loopback 不能证明桌面属于操作者

SSH 端口转发可能让远端 Host 看见来自 127.0.0.1 的请求，却把窗口打开在无人值守的服务器桌面。无头 macOS/Windows、WSL interop 不可用或 Linux display 探测失真时，也应在网关设置 nativeOpen: false，以关闭原生交接。

WebSocket 就绪与断线恢复#

浏览器分别连接 /api/events.mux 和 /api/events.host。两条连接都只接收文本帧，客户端不会在 socket 上发送业务请求；直接用普通 GET 访问会得到 426，也没有浏览器 SSE 回退。

01Open

新 generation 同时打开两条下行流，并调用 host.describe 验证 HTTP 上行可达。

→
02Publish

就绪后才发布该 generation 的 Host 能力描述并触发业务层重新同步基线。

→
03Rebuild

任一流结束都会使整代失效，两条流一起重建；旧代响应不能覆盖新状态。

连续失败采用带抖动的指数退避：首次上限 500ms，逐次翻倍，最高 10 秒；成功连接后尝试计数归零。断线时 Host 能力描述会清空，因此目录选择和本地打开等消费者不会沿用过期能力。

反向代理必须支持 WebSocket Upgrade

代理若只转发普通 HTTP，页面资源和 POST 可能正常，但两条事件流无法就绪。应允许上述两个路径升级，并避免把 426 当成可缓存的应用响应。

01Describe

→

Lookup provider 卸载后，wire 声明仍保留，因此请求会明确返回 unavailable，而不会把身份字符串误当普通对象。Client 只看见显式导入并挂载的 Remote namespace；业务服务实例和 JavaScript Proxy 都不会跨边界。

当能力需要可替换提供方时，Harness 将它拆成三个角色。只有完整组合才构成一个 capability seam；单独一个角色并不完整。

01Service Definition

←
02Service Provider

→

LLM 适配器#

新的模型提供方通过继承 LlmAdapter 并实现异步 stream() 接入。适配器把统一请求转换成提供方 API，再把流式响应转换成 Harness 的 StreamChunk。

block-start→text/tool deltas→block-end→usage→finish
  • 每个 block-start 必须有对应的 block-end。
  • index 从 0 递增，用于标记内容块顺序。
  • usage 必须在 finish 之前；finish 必须是最后一个分片。
  • 不支持的字段应抛出带稳定 code 的 LlmError，不得静默丢弃。

流式协议、失败与重试#

文本、推理和多个工具调用可以在同一响应中交错，index 把 delta 归属到对应内容块；block-end 携带完整块。共享 BlockAssembler 同时记录原始分片并组装最终 Assistant 消息，避免各消费方自行实现不一致的 fold。

Normalized failure

抛出的传输错误和流内错误统一为可序列化 LlmFailure，按稳定 code 路由。

One call, one attempt

适配器必须关闭 SDK 自带重试；Agent 恢复会开启新的、持久且编号明确的步骤。

Frozen policy

请求选定路由时捕获不可变重试策略，后续替换 Provider 不会改变进行中的恢复。

远程流有有限的 idle timeout；上下文溢出统一映射为 CONTEXT_WINDOW_EXCEEDED，空 completion 映射为可重试的 EMPTY_RESPONSE。Provider 的 retry-after 只是事实，不是自动重试决定。

TokenUsage 计数互不重叠

未缓存 input、cache read、cache write 三项相加才是计费输入；reasoning tokens 已包含在 output 中，汇总时不能重复计算。

默认重试策略与界面状态

未显式配置时使用 normal 策略：只对 EMPTY_RESPONSE、RATE_LIMIT、SERVER、TIMEOUT 和 TRANSPORT 最多重试两次，退避从 500ms 增长到最多 10 秒并加入 10% 抖动。有效且未超过上限的 Provider Retry-After 会替代本地延迟。

normal

有限预算，只重试明确允许的失败码；格式错误凭据和认证失败不会默认反复请求。

always

每次模型请求失败都无限重试，直到成功、取消或插件释放，包括永久性认证和配额错误。

cancel

取消会中止退避；尚未开始的新尝试不会写入 retry-started，界面显示已取消状态。

Web UI 把连续尝试折叠为一条稳定状态行，显示倒计时、当前次数与有限上限或 ∞。每个调度事件仍持久保留；失败步骤未完成的流式尾部会被移除，终态失败则留在轮次边界供排查。

重试可能重复计费

每次重试都是新的 Provider 请求，可能再次计费输入 token。模型不会看到失败分片、延迟或 Provider 错误；认证错误的界面文案也不会回显提供方返回的凭据片段。

持久重试提示的状态转换#

相邻尝试的 retry 事件在 Chat 中合并为一条稳定弱化行，并用最新尝试更新；底层运行时快照与 Session 日志仍保留每个事件。后续尝试成功后，这条恢复历史也不会消失。

scheduled

收到 retry 后、匹配的 retry-started 到达前显示计划状态。倒计时从浏览器收到事件的时刻起算，向上取整且至少显示 1 秒，避免 Host 时钟偏差。

started / cancelled

后续 started 事实把提示推进为已开始；若所属 Step 或 Turn 先关闭，则成为已取消。Host running 位只控制实时动画，不改写持久事实。

terminal error

未进入重试的 turn/end 错误生成持久内联节点；尚未定稿但可见的 Assistant 输出会冻结在旁边，而不是被当作完整回答。

AUTH 只脱敏显示副本

可能包含凭据片段的 Provider 文案在界面中统一替换为 API key is invalid，原始诊断仍保留在会话日志供本地排查。刷新、分页与恢复使用同一组 Definition，不会让已移除的失败分片重新出现。

输出达到 max-tokens 时

max-tokens 是独立的轮次结束原因，不等于正常完成、错误或取消。只要本轮任一步骤达到输出上限，即使插件随后继续执行并正常结束，整个轮次仍保留截断标记。

已完成内容块

完整结束的文本或推理块会保留为 Assistant 内容，并继续出现在历史中。

未完成工具调用

截断的参数不能安全执行，因此不会发布 tool/call，也不会产生半个外部副作用。

空回答

仍记录空的 assistant/message 完成锚点和可用的 usage，但空内容不会进入派生模型 transcript。

Web UI 在该轮位置显示持久警告，保留已经生成的可见输出，并建议发送“继续”开启新轮次。事件不携带具体 token 数字，因此提示不会猜测上限；刷新、历史分页和恢复后仍能重建相同状态。

不要把“继续”当成同一次请求

继续是一条新的用户消息和新的 Provider 调用，会使用当前模型配置并产生新的用量。若经常截断，应调整模型或 Agent 的 maxTokens，同时确保不超过提供方实际输出容量。

Agent 动态扩展运行时#

自引用 Cordis 工具让 Agent 先检查活的服务、API、事件和 Client slots，再定义并运行临时动态包。cordis_define 只做语法预检和登记；所有副作用都推迟到显式 cordis_run。

inspect先查询契约把编译期 API 目录与当前活服务取交集，避免凭空猜测接口。
define → run版本化实验Host 半先在 node:vm 中求值；Client 半必须由打开的页面确认并装载。
stop / undefine完全撤销停止会释放 Fiber 贡献；删除还会忘掉全部不可变 Package 版本。

动态包只存在于共享进程内存，不写插件文件、不修改 cordis.yml，也不会跨重启恢复。每个操作按定义它的 Session 校验归属；其他会话读取时表现为不存在。

VM 隔离不是安全边界

Host 半仍可通过获准的 fs、web、bash 等服务影响运行时，应当像授予 Bash 一样慎重。带 Client 半的 run 在无人打开页面时会一直等待，直到调用轮次取消；同步 vm timeout 也不约束逃逸出的异步函数体。

Code Runtime 与结构化绑定#

Code Runtime 是可替换的可选 seam，用宿主提供的异步 bindings 执行模型编写的程序。程序作为 async function body 运行，可使用顶层 await 和 return；打印日志与完成值一起形成已解析的结果。

01Bind

→
02Run

后端显式声明 TypeScript 或 Python 语言，以及 worker/process/container 基底。

→
03Resolve

日志、可选完成值和失败分类都通过正常结果返回，而不是拒绝 Promise。

异常、预算超时、调用方 abort、worker 退出、非 JSON 输出和结果超限是彼此独立的失败类型。输出超限会明确失败而非塞入替代文本；停止 runtime 时必须终止并等待全部运行结算。

Isolation 只是诊断标签

worker-thread、process 或 container 描述执行基底，不构成安全承诺。Bindings 仍是程序调用宿主能力的入口，必须只暴露确实授权的函数。

Settings 的三层解析#

用户设置按 namespace 分节，每个生效值依次叠加 Schema 默认值 → 组合层 base → 用户分节。cordis.yml 仍保存部署组合；Settings 只承载允许用户编辑的子集。

3用户覆盖 · update / replace / mutate
2组合层 base · 部署方默认
1Schema defaults · 类型与表单

update 合并稀疏 patch；replace 整体替换并让缺失字段重新继承；持有脱敏视图的 UI 必须使用路径级 mutate，避免覆盖自己从未看到的 secret 字段。每次写入都带 revision，可拒绝过期页面的并发覆盖。

生效时间是产品提示

live owner 观察变更并热应用；restart owner 只在构造时读取。外部编辑无效时，运行中的 namespace 保留最后一个已验证值。

安全更新与并发收敛#

settings.describe 返回 resolved、base 与 user 三层的脱敏快照、secret 槽位状态和原始用户分节的单调 revision。secret 值不搭乘任何响应，只能沿写入请求单向进入 Host。

改一个字段

使用 settings.mutate 的路径级 set / unset，并附带最近的 expectedRevision。

页面已经过期

Host 返回 settings-conflict 和新旧 revision，不覆盖已经提交的写入；客户端重新读取后再让用户决策。

外部或断线变更

客户端在首次读取前先监听更新，并在 settings/document-updated 或连接重置后重新读取；迟到的旧响应不能覆盖较新的发布值。

不要用脱敏结果重建整个分节

网络 descriptor 从未包含 secret 明文；据此调用 replace 会把不可见的 secret 当成缺失并删除。当前脱敏 walker 也不能证明所有 union、intersection 或 transform 内的 secret 都安全，因此暴露到协议的 namespace 只应使用可验证遍历的 schema。

Schema 草稿、覆盖与客户端校验#

settings.describe 把 Host 使用的 schemastery schema 序列化给浏览器，schema-form 再将其重建为活校验器。页面因此能在写入前用与 Service Definition 同源的规则校验整份用户分节草稿。

不可变路径编辑

setPath 物化中间对象；deletePath 删除用户层字段，使解析值重新继承组合 base 与 schema 默认值。

覆盖按存在性判断

字段只要出现在原始用户草稿中就算已覆盖，即使它恰好等于默认值；这与 Settings 的分层语义一致。

无法解析就降级

nodeAtPath 只沿 object 属性和 dict inner 探测节点；找不到路径时返回 undefined，功能表单必须进入明确的降级路径。

当前没有通用 React 表单生成器，各功能围绕草稿辅助函数手写控件。校验返回整份草稿的第一条失败消息及 $.path，不会自动把多项错误分发到每个字段。

序列化 Schema 是可执行信封

schemastery 重建回调时会执行动态函数，因此只能接受提供当前页面的同一受信任 Host 所发送的 schema。secret 控件仍必须保持只写：初始为空，只展示是否已配置，空草稿不能清除已有密钥。

设置文件的热重载与最后可用快照#

settings-file 用一份 YAML 或 JSON 文档承载所有 namespace。启动时存在但非法的文档会让插件明确失败；运行期外部编辑若不可读、不可解析或无法通过某个 namespace 校验，则告警并保留对应的最后可用值，不拖垮进程。

写前重新读取

每次 persist 都在锁内先读取最新磁盘文本并发布差异，再基于它渲染，因此能并入 watcher 防抖窗口、漏报事件和其他进程写入。

YAML 叶子级修改

只改动变化的 map 叶子，保留未触碰节点的注释、锚点与排版；数组和其他非 map 值整体替换，JSON 则整体重新序列化。

同一操作队列

watcher 刷新与各 namespace 写入逐个执行；ready 时再对账一次启动竞态，内容等于最后文本的自写事件直接抑制。

删除设置文件会发布空用户文档，让所有 namespace 回退到 base 与 schema 默认值。卸载会先关闭 watcher，再等待已排队和进行中的文档操作完全停稳，此后不再发布。

Watcher 不是持续轮询

读取路径不会自行重复 stat；若底层 watcher 真正漏掉事件，外部变更要到下一次文件信号、下一次写入或重启时才会被并入。磁盘已经非法时，产品写入会拒绝，而不是覆盖用户尚未修复的文本。

凭据引用与热轮换#

配置文件只保存形如环境变量名的 CredentialRef，明文由 Credentials provider 管理。LLM Adapter 在每次请求前重新解析引用，不跨操作缓存，因此轮换后的密钥会在下一次请求生效，无需重启。

resolve

只向受信任消费方返回非空值及来源层；空字符串始终视为未配置。

describe

UI 只看到 configured、source 与 writable，永远拿不到凭据值。

set / unset

只修改 provider 管理的可写层；被只读环境变量遮蔽时明确拒绝。

不要把 Secret 放进 Settings

Secret schema 字段在所有网络 descriptor 中都必须脱敏。模型配置引用凭据名，而不是复制 API Key。

本地凭据文档的权限与信任边界#

本地 provider 把受管值保存为 $DSH_HOME/.credentials.yaml 中从引用名到字符串的纯 YAML mapping。非 mapping 根、非法 POSIX 名称、非字符串、空值、重复键或语法错误都会整体拒绝，不会静默跳过坏条目。

仅属主权限

目录以 0700 创建，文档以 0600 原子提交。POSIX 上发现任何 group/other 权限位都会在解析内容前失败，并提示 chmod 600。

补丁式写回

写入在锁内重读并修改已解析文档，保留未触及条目的格式和注释；删除条目也会删除紧邻其上方、属于该条目的注释。

整体热替换

外部编辑成功后先替换完整快照，再逐引用发布 credentials/updated；删除的磁盘条目不会残留在内存。

运行期文档非法或不可读时告警并保留最后可用快照，文件不存在则视为空存储；启动期同样的问题会明确失败。Windows 无可用 POSIX mode 检查，因此跳过权限位验证，而不是伪造安全结论。

0600 挡不住同 UID 的 Agent

bash 与文件工具以同一 OS 用户运行，workspace-write 主要限制修改而非所有读取；现有沙箱不会特别隔离这份文档。Harness 只是不把解析路径告诉模型、也不把受管密钥放进进程环境。这是审慎设计，不是强隔离；需要阻止 Agent 读取提供方密钥时，应使用进程外钥匙串或 KMS 类 provider。

冻结的启动环境与来源优先级#

产品 CLI 启动时把环境冻结成带来源的不可变快照。Harness 自己解析面向用户的值时读取该快照，而不是压平后的 process.env，因为只有快照能区分每个值来自哪一层。

3process · 启动 shell / CI / 容器的本次明确意图
2project-env · 调用目录的 .env
1user-env · $DSH_HOME/.env 机器默认值

getFrom 可以拒绝某些来源层，但不能改变剩余层的可信顺序。变量名按平台规则匹配：POSIX 区分大小写，Windows 不区分大小写，避免同名变量因拼写大小写而错误越级。

只在启动时发现

只读取调用目录和 Harness home，不搜索父目录；启动后修改 shell 环境或 Web 中切换 Workspace 都不会改变快照。

文件值仍会物化

非 bootstrap 变量也写入 process.env 供 Loader 和第三方库使用，因此快照并不是子进程隔离边界。

凭据再加一层

本地 Credentials 的顺序是继承环境 → 受管 .credentials.yaml → project-env → user-env；受管写入会覆盖旧的两个 .env 后备值。

选择工作区不会加载它的 .env

项目环境绑定 Harness 的 invocation cwd，而不是随后由 Agent 选择的工作区。否则模型在会话中途切换目录，就可能间接改变宿主配置和凭据来源。

Glob、Grep 与结果预算#

文件发现工具使用 npm 随包交付的 ripgrep 二进制，并通过 Subprocess seam 以固定 argv 启动；不依赖宿主预装 rg，也不经过 shell。启动时强制 no-config，避免继承的 RIPGREP_CONFIG_PATH 注入预处理器。

glob

查找文件路径并包含 hidden/ignored 文件；不含斜杠的 pattern 会匹配任意深度 basename。

grep

按 rg JSON 解析正则匹配并按文件分组，避免依赖冒号拆分。

spill

内联页面达到路径、匹配或行字节上限时，尽力保存完整格式化结果。

原始 stdout 超过传输预算会以 SEARCH_RAW_OUTPUT_OVERFLOW 失败并要求缩小查询；退出码 1 只是成功的空结果。搜索进程的 cwd 必须与文件系统工作区共置，否则返回路径无法保证能被 read 继续读取。

Shell 与持久 Terminal#

两者都能运行命令，但生命周期不同。默认使用 Shell 完成有边界的一次性操作；只有任务需要交互式 stdin、REPL、开发服务器或持续终端状态时，才打开 PTY Terminal。

Shell foreground

等待命令结束，分别报告退出码、信号、超时与调用方取消；非零退出是正常结果，不是基础设施异常。

Shell background

立即转成通用 job；没有执行器超时，通过增量游标读取输出，并可请求终止整个进程组。

PTY Terminal

保留 shell 状态和 scrollback，支持发送输入、分页读取、信号、列出与显式关闭。

返回不代表命令退出

terminal_send 因 inferred_idle 或 timeout 返回时，顶层 PTY 仍可能运行。应检查 session status，并在不再需要时调用 terminal_close。

Harness 会清除子进程环境中的凭据及继承的 DSH_* 名称，再合并本次受管环境快照。输出超过内存预算时只内联尾部，并用私有 spill 文件保留完整流的恢复信息。

子进程、流与进程树终止#

Subprocess seam 为 Bash、LSP、PTY 和 ACP 提供同一个底层进程世界。Spawn spec 没有隐藏默认值：argv、cwd、三条 stdio、环境、宽限期和取消信号都由调用方明确给出，argv 永远不经过 shell 解释。

pipe协议流把原始 Readable/Writable 交给 LSP JSON-RPC 或 ACP ndjson 等协议消费者。
inherit直接诊断子进程输出直接进入 Harness 自己的描述符。
collect有界收集内存只保留尾部，可选 spill 保存有上限的完整流。

收集读取使用全流字节 offset，多个读取者不会抢走彼此的数据。终止以整棵进程树为范围：POSIX 先发 SIGTERM，等待 grace period 后升级 SIGKILL；Windows 使用 tree termination。最终 outcome 只报告退出码和信号，超时或取消原因由拥有 deadline 的调用方分类。

LSP 精确代码导航#

文本搜索适合普通浏览；当同名符号含义不清，或修改前必须确认精确定义、实现和引用时，使用只读 lsp 工具。它只公开四种闭合操作：

goToDefinition跳转定义

定位当前符号的定义位置。

findReferences查找引用

返回引用并始终包含声明本身。

goToImplementation查找实现

从接口或抽象符号定位实现。

hover类型信息

读取语言服务器给出的 Markdown 或纯文本说明。

模型输入使用从 1 开始的 UTF-16 行列坐标；没有对准符号可能得到空结果。Provider 按文件扩展名确定性选择，没有匹配项时返回 LSP_UNAVAILABLE。LSP 是可选能力，不属于 Agent loop 主干。

斜杠命令#

用户命令由插件注册，交互式客户端负责发现并针对确切 Agent 执行。输入形如 /plan、/export；处理器直接返回 UI 结果，不创建用户消息、不启动模型轮次，也不产生工具结果。

发现

UI 获取名称、说明和可选输入提示，不接触处理器函数。

执行

注册表解析名称并保留命令后的原始输入，同时传入取消信号。

审计

已接纳命令写入配对的 command/run 与 command/done 日志事件。

语法错误或未知命令不会写日志。Agent scope 中的同名定义会遮蔽全局命令；插件卸载时注册自动撤销。

输入触发器与模糊发现#

浏览器的 ui-input-trigger 在光标处按词边界和 guard tier 检测 /、@ 等触发器，再把分组候选与 pick 回调路由到注册 source。前置加号也复用同一控制器，只以合成 selection 打开 command source，不建立第二套菜单。

候选竞争

source 按 order 和注册顺序分组；新查询会取消旧请求并以 generation 阻止迟到结果覆盖当前菜单，单个 source 失败只记录诊断。

键盘裁决

空格与 Enter 按注册顺序询问 source，第一个明确应答胜出。命令菜单支持不区分大小写的子序列模糊排序，但真正提交仍要求精确命令名。

可访问焦点

菜单采用 combobox 模式，焦点留在 textarea，高亮通过 aria-activedescendant 表达；指针选择在 mousedown 完成，避免失焦竞态。

只属于浏览器呈现层

触发检测、菜单、launcher 和 notice 本身不进入会话日志，也不增加模型 token。只有 pick 之后执行的 Host 命令或插入到普通提示词中的引用文本，才产生各自领域的后续效果。

Codex 与 Claude Code Hooks#

Hooks 桥接器把现有 Codex 或 Claude Code command hook 配置映射到 Harness 的类型化拦截点。它们是兼容层；需要完整类型、更多控制或稳定扩展时，应直接编写 Cordis 插件。

PreToolUse工具前决策

Codex 子集支持阻塞；Claude Code 子集还可返回 ask。

PostToolUse / Stop反馈与续行

工具后可阻塞或追加反馈；Stop 阻塞会 steer 下一步。

不是完整协议复刻

桥接器只运行同步 command hook，且各自只支持官方协议的一个子集。配置在进程加载时读取一次；不支持的事件或字段不会自动获得原产品语义。

Session 内定时提醒#

schedule_create 支持延时一次、绝对时间一次和固定速率重复三种规则。记录持久在原 Session 中，到期后排队一个普通 follow-up；不会发送外部通知，也不会唤醒 cold Session。

提醒只在拥有它的 Agent live 且完全 idle 时交付，从不打断当前轮次。一次性提醒优先；多个到期的重复提醒会合并进同一个 follow-up。交付是尽力而为的至少一次，不是恰好一次。

Workflow 与 Ralph#

workflow 让模型编写 JavaScript 编排脚本，按阶段启动多个 Subagent 并返回结构化 JSON。它适合用户明确要求的大型多 Agent 编排；一两个委派仍应使用普通 Subagent。

Ralph

固定前台循环，每轮启动一个没有对话 seed 的全新 Agent，以共享工作区和有界报告交接状态。

Goal

同一 Agent、同一 Session 内跨轮持续推进，适合普通长期目标，不等同于 Ralph。

完成声明仍需验证

Ralph 的 complete 或 blocked 来自 worker 报告，没有独立评估器。普通 child 失败会终止运行而不会自动重试；取消后局部输出也不会伪装成成功。

Token 计量#

Token Meter 回放当前会话的耐久日志，生成一次不可变的请求压力与 surface 定价快照。它区分完整请求/响应压力 totalTokens 和仅当前模型表层的启发式总量 surfaceTokens。

usage baseline

最近成功请求具有相同规范 envelope，且 Provider usage 足够覆盖启发式锚点。

estimated baseline

没有可安全复用的 usage 时，用固定启发式重新估算完整 envelope 与 surface。

surface delta

相对匹配基线的有符号变化，可同时表示上下文增长与压缩后的缩减。

每个 surface node 记录事件 seq 和估算 token，但数组顺序才是模型表层的权威顺序；压缩替换节点的 seq 可能比排在它后面的旧节点更大。

如何解读 Context Meter

输入框旁的占用圆环只在“预计下次请求 token”和当前模型容量都已知时出现。标题使用 projectedTokens：从最近一次 Provider 输入用量出发，再按此后 surface 的新增、替换或压缩做启发式增减。

pressureTokens

最近一次已完成请求的输入压力，等于未缓存输入、cache read 与 cache write 之和；流式输出期间不会变化。

projectedTokens

预计下一次提示词规模。压缩一落地就会下降，无需等待新一轮 Provider usage。

contextBreakdown

按系统提示词、工具和消息给出约略组成，固定使用“4 字符约 1 token”加结构开销。

百分比不是账单，也不是准入闸门

预计 token、模型容量和组成明细来自独立的后写覆盖投影，并非同一次请求的原子快照。CJK 文本和大型 JSON Schema 可能被明显低估，明细相加也不保证等于标题数字。

统计栏的计费输入为未缓存输入、cache read 和 cache write 三项之和，缓存命中率用 cache read 除以该总量；reasoning token 已包含在输出中，不能重复相加。缺少完整 timing 或 usage 的步骤会从 TTFT 和吞吐计算中退出，而不是用猜测值补齐。

Trajectory 调试视图#

Trajectory 把用户、助手、工具与嵌套子工具事件按轮次排成可检查的执行轨迹。选择一行可查看 token、耗时、输入、输出与计时；独立压缩显示在轮次之间，带编号的压缩仍留在所属轮次。

长历史按需加载

视图从当前尾部开始，只挂载可见行和少量缓冲；到达顶部或时间轴省略号时再加载更早一页，不为尚未加载的前缀虚构耗时。

时间轴可缩放检查

拖选闭区间会筛出与它重叠的记录；滚轮缩放，放大后右键拖动平移。助手条分别呈现已记录的 TTFT 与解码时间。

流式跟随尊重阅读

初始状态与流式更新停在尾部；用户向上滚动后暂停跟随，新事件不会抢走旧记录的检查位置。

Trajectory 与 Chat 各自投影

Trajectory 从共享 Session 原始事件组装自己的记录，也保留因取消而冻结的助手与工具步骤；它不读取或修改 Chat 会话快照。搜索、折叠、选择与请求汇总只覆盖当前已经加载的窗口。

进行中不虚构耗时

部分响应和运行中的工具只显示开始标记与运行状态，完成前不会绘制假定时长。时间线与记录选择也只存在于当前页面，不提供可分享的锚点深链接。

Subagent 委派#

Subagent seam 让父 Agent 通过具名 Provider 委派工作。Provider 可以在同一进程、独立进程、ACP、Codex 或 Claude Code 中运行，但父级看到的启动与结果约定保持一致。

Foreground前台一次性

父级等待最终结果，返回前总会释放子级运行资源。

Background task后台一次性

立即返回 job id，之后通过通用 Task 接口收集或取消。

Continuable可继续子级

拥有持久 Session，可接收后续消息并在需要时冷恢复。

同级委派可以并发执行，结果仍按模型调用顺序提交。子级继承父级显式沙箱覆盖，但审批策略固定为 never，避免无人处理的提权请求。

Todo 列表#

todo_write 属于当前 Agent 会话，每次调用都提交完整列表快照，而不是增量修改。条目只有三种状态：

尚未开始

持久 Goal#

Goal 用于一个需要跨多个轮次持续推进的同会话目标。它与普通 Todo 不同：Goal 有 phase、revision、Round 上限和明确的暂停、恢复、完成与阻塞生命周期。

模型必须读取精确 goal id 与 revision 后再更新。困难或不确定不是阻塞；只有同一阻碍连续达到配置阈值后才能报告 blocked。

工具 Guardrails#

Guard 插件通过 tools/execute 流水线增加可靠性策略，不改变具体 Tool 的实现。当前常见的两类保护是协作式超时与重复调用提醒。

⏱

协作式，不是硬终止
↻

按 Agent 统计同一工具和规范化参数的连续调用，在 3、5、8 次等阈值注入逐级提醒。

不受跟踪的记录类工具对重复链透明，因此在两次相同调用之间写 Todo 不会掩盖循环。各 Subagent 的重复链彼此隔离。

截止时间与重复链的精确语义#

只有声明预算才超时

策略零配置，只读取工具自己的 ToolDefinition.timeoutMs。未声明预算的工具原样执行；声明预算也意味着该工具承诺转发 exec.signal。

拒绝调用也参与计数

重复检测位于 post-execute，因此被 pre-execute 拒绝后仍反复提交的相同调用也会推进链；这正是需要提醒的循环。

参数键是完整规范值

对象键深度排序后再序列化，所以属性顺序不同仍视为相同；提醒中的参数预览有长度上限，但检测始终比较完整值。

用户新提示词会重置对应 Agent 的重复链；持久会话恢复会从空链开始，而 compaction 不会重置当前进程内的链。提醒只在精确达到配置阈值时注入，超过最高阈值后不会每次继续追加。

两种 Guard 都不是硬停止

Timeout 只是向协作工具发出中止信号，忽略信号的实现仍可能继续运行；Repeat Reminder 只追加带来源的 user context，保留原工具结果且不否决调用。多个 execute 包装层的注册顺序还决定截止时间覆盖整次重试还是单次尝试。

后台任务#

长时间运行的 Bash 与 Subagent 共用后台任务运行时。启动后会立即得到形如 bash-1 或 subagent-2 的 job id，再通过统一接口查看状态、增量读取输出、等待完成或请求终止。

running

生产方持有执行资源，任务可读取新输出。

stopping

终止请求已发出，等待生产方释放资源。

终态不可逆，并记录结束时间与详细原因。

输出读取使用单一消费游标：流式任务每次返回上次读取后的增量，只有最终输出的任务则在结束后重复返回同一结果。任务访问按拥有者 session 授权；Agent 被释放时，其任务会被取消并等待清理完成。

取消不是瞬间完成

浏览器中的会话搜索#

侧边栏搜索把快速本地匹配与 Host 正文检索组合成一个扁平结果列表。标题和 Workspace 子串按不区分大小写立即匹配；非空查询经过 250 ms 防抖后，再加入按相关性排序的对话内容结果与摘要片段。

输入先规范化

查询移除 NUL，最多保留 500 个 UTF-16 代码单元，并保证不会在截断处拆开代理项对。只含空白的查询不会发起正文搜索。

旧请求主动取消

每次新查询都会中止前一个 Host 请求。搜索状态属于当前 UI 所有者，不写入共享 Session 列表，因此页面必须自行抑制迟到响应。

远程失败仍可降级

正文检索失败时，标题与 Workspace 的本地匹配继续显示，并附带警告。结果最多展示 20 条，过宽查询会提示进一步缩小。

结果定位到 Session，不定位到事件

打开命中项不会清除当前查询，也不会跳到摘要对应的日志事件。当前搜索没有模糊匹配或事件深链接；正文后端采用字面 token 或短语语义。

会话标题的生成与固定#

标题是后写覆盖的持久日志状态。内置 fallback 或可选 Provider 会根据合格的人类文本消息生成标题，并记录精确的来源消息 seq；用户手动重命名后，标题会被固定，后续自动生成停止调度。

服务接纳结果时会验证来源 seq、规范化非空文本并执行 UTF-8 字节上限。即使辅助 LLM 最终失败，请求记录仍能还原当时模型实际看见的输入与路由。

会话分支、归档与删除边界#

Fork 不会在任意半成品事件处截断。消息下方的分支操作只在已完成轮次的最后一条 Assistant 文本上启用；宿主把事件锚点推进到该位置之后的首个 turn/end，确保子会话继承完整轮次。

Fork

继承种子历史、cwd、最近模型选择和谱系，再加入源 Workspace。开放轮次不能分支，也不会悄悄退回更早轮次。

Rename

显式标题会写入日志并固定，之后的自动标题不能覆盖。Fork 后客户端会把标题尾部编号递增。

Archive

只把 Session ID 加入全局归档集合，从所有分组和搜索视图隐藏；日志与 Workspace 记账保持不变。

当前没有删除 Session 或取消归档控件

删除 Workspace 只删除注册记录，目录与 Session 日志仍保留，相关会话会进入 Ungrouped。归档同样不是删除；当前 Web UI 没有查看或恢复已归档会话的入口。

若 Fork 已成功发布子会话、但加入 Workspace 或自动改名失败，错误仍会携带并保留已创建的子会话，客户端先完成对账再报告失败，避免重试时产生重复分支。

消息底部操作何时出现#

Chat 不会给每一个 Assistant 节点复制一套操作栏。复制、时钟与分支组成的 IconActions 只挂在已结束轮次中最后一条带文本内容的 Assistant 消息下，让一个完整轮次只有一个明确操作锚点。

中间内容没有 chrome

轮次中间的叙述、纯 Think 节点，以及仍在生成步骤的轮次都不显示消息操作栏，避免把半成品误当成稳定分支点。

分支要求完整尾部

即使操作栏可见，只有同时位于已完成轮次最后一个 transcript 节点时才启用分支；成功后递增继承标题并打开子会话。

用户气泡保持只读

已发送的用户消息保留复制和时钟，但没有编辑或分支操作；当前 Host 对已消费输入也没有对应的重写语义。

失败不切走源会话

如果 fork 或自动改名失败，源会话继续保持选中。界面不会打开一个尚未完成对账的目标，也不会静默退回更早轮次重试。

归档集合如何跨标签页收敛#

归档状态是 Host 注册表级的完整 Session ID 集合。Workspace 基线、本地归档 RPC 回声和其他标签页触发的 changed 帧都会安装整份集合，而不是对旧数组追加或删除一项。

新快照覆盖过期基线

若归档集合在 workspace.list 请求进行中更新，新集合会保留并压过随后返回的旧基线，避免短暂恢复已经归档的行。

当前选择统一清空

正在查看的 Session 一旦进入归档集合，投影就切回 New Session。此规则同时覆盖本地操作、其他标签页通知和离线期间变更后的重连。

隐藏不等于移除

归档行从 Workspace 分组、Ungrouped、平铺列表与内容搜索中全部消失，但 Session 摘要仍留在运行时 store，日志与记账席位也不改变。

Archive 不弹确认框

当前 Web UI 直接提交这项非破坏性操作；失败只写入控制台诊断，列表保持原样。成功后目前没有查看或取消归档入口，因此仍应确认选中的是正确会话。

会话持久化与恢复#

内存中的仅追加 SessionEvent 日志是真源，Persistence seam 负责把同一组事件耐久保存；它没有另造一套“持久化事件”。元数据 header 与日志分开保存，记录格式版本、cwd、父会话、seed 边界、委派深度和 Agent preset。

01后台批量追加

同步事件通知只复制到会话控制器，固定窗口内的事件合并成耐久批次。

02语义检查点

模型请求、顶层工具副作用与下一步开始前执行 flush，失败则阻止继续。

03冷恢复

崩溃留下的开放轮次不会被截断，而是补记 interrupted 结束事件后回放。

持久化意图不等于恰好一次

工具调用可能已经产生外部副作用、但结果尚未落盘。恢复时 Harness 会写入 TOOL_OUTCOME_UNKNOWN，要求先验证状态；有副作用的 Provider 应尽量把 call id 用作幂等键。

JSONL 后端为每个会话维护可选 Zstandard 压缩的追加日志；SQLite 后端则把每个事件存成一行。格式版本过新、过旧或遇到未知的必需事件时会明确拒绝恢复，而不是静默丢失语义。

会话投影与冷读取#

Session Projection 把仅追加事件日志折叠成供客户端直接消费的完整领域状态。每个领域只注册同步的 init → apply → view 纯计算单元；框架统一订阅已提交事件，客户端从不自行重放领域事件。

03Cache

状态版本与 seq 写入耐久缓存，冷会话只回放缺失尾部。

缓存是性能层而不是真源：版本变化或日志因崩溃修复而缩短时，旧行会失效并回退到完整重放。写后缓存失败只记录警告，下一次检查点或冷读会自愈；插件卸载后，其投影 key 会从快照中消失。

Chat 节点的增量组装#

每个 Session 把连续事件窗口交给 ConversationNodeAssembler。插件用稳定的 kind/id 在唯一 start 事件创建 State，再折叠关联 update；Assembler 统一维护 Context 索引、只读前序查询和引用稳定的 Turn/Step Location。

实时 append 只命中一次

每个新事件只对各 Definition 求值一次，并且只更新匹配的 Context，不为一条尾部事件重扫整份历史。

向前分页保留旧身份

加载更早页面时只匹配新 prepend 事件；已有 Context、节点和 keyed value 保持不变，只有前序依赖或 Location 事实变化的项才重放。

完整替换有明确边界

只有首次 open、权威 resync 或序列 gap repair 才替换完整窗口。普通内容更新只通知受影响的 node key，结构变化才重建顺序关系。

Assistant 的每个流式 chunk 都会更新 Definition State，但物化请求最多每个 animation frame 一次；final message 与 Turn/Step 关闭则立即发布。prepend 只增加行，不替换已经存在的 keyed 节点。

业务节点不能扫描 Chat 集合

Definition 只根据当前事件匹配稳定业务 id，并保证 update 可按日志 seq 回放；renderer 只消费最终 Node data 与受限 Location。否则分页和 HMR 会产生与加载顺序相关的结果。

Chat 滚动壳与编辑器几何#

无会话、空白会话和活跃会话复用同一个根滚动容器、Hero 与编辑器子树；会话出现时，标题栏和主体只填入各自 outlet，不会替换 textarea 或编辑器 seat。Workspace 切换因此能保留草稿、焦点相关状态与 DOM identity。

滚动条槽始终预留

data-conversation-scroll 无条件保留自己的 scrollbar gutter。无论记录是否足够长、当前切到 Chat 还是 overlay 视图，输入卡片都不会横向跳动。

编辑器栈属于同一宿主

统计 dock、输入 dock 与输入栏组成 sticky 栈，和流动排版的会话视图共用滚动容器；切换视图不会换掉一棵平行的 composer 树。

草稿滚轮在边缘接力

限高 textarea 有可滚内容时先在自身滚动；到达顶部或底部后，滚轮再交给会话宿主，避免长草稿把整页滚动永久截断。

不要把预留入口当成分页功能

Assembler 已支持向前 prepend 历史并保留节点身份，但普通 Chat 的 assistant 逐消息分页目前仍只是设计 slot，尚未实现。现有 IconActions 只出现在已结束轮次最后一条有文本的 Assistant 消息下。

上下文消息的来源展开项#

写入日志的非用户消息不会伪装成普通对话气泡。Chat 默认把它折叠成 DisclosureRow：标题先显示运行时投影的角色——注入显示“上下文注入”，召回显示“跨会话召回”——再附上持久来源记录中的生产者名称。

不展开也能辨认来源

生产者标签可区分 skill 目录、Workspace 指令文件和被召回会话；来源没有名称时只显示角色，不猜测生产者。

已知形态按语义展示

instructions 在正文上方列出已对账文件；catalog 展示来源记录的条目，而不是直接倾倒面向模型的正文。

未知形态仍可检查

未声明、当前版本不认识或字段不足时使用 opaque 内容区：保留真实换行展示模型所见文本，并列出剩余来源字段。

展开内容自适应高度，最高 141px，超出后在内部滚动；它不会合成工具状态或摘要。这个 opaque 路径是正式默认协议，而非错误兜底，因此恢复、fork 或外部写入的历史即使缺少当前生产插件，也仍能渲染。

Steering 不添加虚构标记

持久或待处理的中途引导继续使用用户气泡样式；transcript 唯一的 steering 线索是它位于轮次中途。界面不会写入日志里不存在的来源或状态。

实时 Think 行与阅读保护#

Think 行默认折叠，但流式阶段并非停在一条过时摘要上。当 reasoning 块位于消息流尾部时，折叠标题从结算后的首行切换为当前最新的非空行，让用户无需展开就能确认推理仍在推进。

这是展示策略，不是额外推理数据

界面只在运行时已经投影出的 reasoning 内容中选择摘要和滚动位置；它不会生成、补写或推断模型没有输出的思维过程。

非会话数据的领域存储#

设置、索引等不属于对话事件日志的数据进入 Storage subsystem。枢纽只负责注册后端和挂载数据形式，不执行 IO；领域层声明名称、格式版本、global slot、表和 zod schema，再按部署路由到 JSON 或 SQLite 后端。

JSON backend

每个 unit 原子重写一份人类可读文件，适合体量较小、更新不频繁的数据。

SQLite backend

在单个数据库中逐行存储文档，适合频繁更新和更多记录。

Domain API

同步读取权威内存态；写入先持久化，再更新内存并发出变更事件。

同一领域的写入按顺序排队。后端写入失败时内存保持不变，因此读取不会领先于介质；格式版本不匹配或已存记录不符合 schema 会在打开领域时立即失败。

配置文件的原子替换与跨进程锁#

Settings 文件和本地 Credentials 使用共享的 atomic-write 原语：在目标同目录以 wx 独占创建随机临时文件，带着显式 mode 写完后再用 rename 替换目标。读取方因此只会看到旧内容或完整新内容。

抗临时路径劫持

不可预测的同级文件加独占创建拒绝跟随预埋 symlink；rename 替换链接本身，不会写穿到链接目标。

权限随新 inode 提交

新文件从创建起就使用调用方声明的 mode，替换权限过宽旧文件时无需先暴露再 chmod；Settings 和 Credentials 使用 0600。

读改写需要锁

withFileLock 以同级 .lock 文件跨进程串行化写入方，指数退避后超时失败；读取方不参与锁竞争。

写锁让不同 namespace 或不同凭据条目的并发编辑不会互相丢失，但两个写入者修改同一键仍是后写胜出。遗留锁不能按年龄自动删除，因为无法区分崩溃进程和暂停但仍存活的持锁者。

原子不等于崩溃持久

这个共享原语不对文件或目录执行 fsync，断电或系统崩溃后 rename 仍可能回退；启动时提供方会重新读取并发布磁盘状态。领域 Storage 的 JSON 后端另有带 fsync 的提交路径，不能据此反推 Settings 或 Credentials。

超大工具结果与 Spill#

当工具返回的纯文本超过内联预算时，Spill policy 保存完整 UTF-8 内容，并用首尾预览、不透明定位符、准确字节数和后端给出的检索提示替换模型结果。模型不会被迫为完整大结果支付上下文成本，但仍能按需读取。

full tool text→private spill artifact→head + tail preview→retrieval hint

本地后端使用会话 id 的摘要作为私有目录，并以排他、仅所有者可读写的方式创建随机文件。调用方提供的文件名只是命名提示，永远不会被当作路径；定位符同样是不透明句柄。

尽力而为的降级

如果磁盘满、权限不足或后端不可用，Spill policy 会保留原始内联结果，不会把已经成功的工具调用改成错误。Fork 会继承日志中的旧定位符，但不会复制或重新归属已有产物。
