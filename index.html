使用 Web UI

用 DeepSeek Harness 启动你的第一个智能编程任务。本指南将带你完成模型配置、工作区选择和首次运行。

i
开始之前

建议使用 Node.js 22.19+ 或 24+（与上游源码工作区一致），并准备 DeepSeek API Key 和一个允许 Agent 读取的本地项目。

安装与启动#

在终端中运行以下命令。DSH 会在当前目录启动服务，并打印 Web UI 的访问地址。

Terminal
$ npx @deepseek-ai/dsh web
Web UI → http://127.0.0.1:3080
公开预览版本

截至 2026-08-16，npm 的 latest 与 next 都指向 0.1.0-rc.6，而当前上游默认分支 manifest 仍为 rc.5。未指定版本的 npx 会跟随 dist-tag；自动化脚本应固定确切版本。

运行一次 Headless 任务#

Headless profile 适合 CI 或脚本：它创建一个全新的持久 Session，提交任务，等待 Agent 完全空闲并 flush 日志，然后把最后一个非空 Assistant 文本打印到 stdout。

Terminal
$ npx @deepseek-ai/dsh --profile headless "run the tests and summarize failures"

最终 turn 原因为 completed 时进程以 0 退出，否则以 1 退出。随附 Headless 组合不会启动 HTTP Server、Web Runtime 或浏览器 Client，成功路径也不会向 stderr 写入内容；缺少任务文本属于用法错误。

启动前检查组合配置#

配置问题不必等到服务启动才发现。dump-default-config 只展开 bundle 默认层；dump-config 还会叠加 profile、本机 DSH_HOME patch 和命令行 patch，并为每一行标注来源。

Terminal
$ npx @deepseek-ai/dsh --profile web --dump-default-config
$ npx @deepseek-ai/dsh --profile web --patch ./extra.yml --dump-config

Dump 不运行应用参数提供方，因此展示的是解析 Web 的 host/port 等参数之前的配置；同一次调用若还包含应用参数会被拒绝。Patch 替换目标行的整个 config，而不是递归合并字段。

配置模型#

打开右上角的 设置 → 模型，选择 DeepSeek，输入 API Key 并保存。模型变更会在下一次请求时生效，无需重启服务。

  1. 1
    进入模型设置

    点击设置图标，在侧栏选择「模型」。

  2. 2
    添加凭证

    选择服务提供方，并粘贴你的 API Key。

  3. 3
    确认凭据与路由

    绿色圆点只确认具名凭据已经配置；还要在会话模型选择器中确认所选路由可用。

凭据不会返回浏览器

API Key 是只写字段。保存后前端只会收到脱敏描述符；明文保存在 $DSH_HOME/.credentials.yaml，settings 中只保存凭据引用。

自定义提供方

公司网关或自建 OpenAI 兼容端点可通过「添加自定义提供方」配置。Provider ID 会被请求、会话、默认模型和凭据引用使用，因此保存后应视为永久标识；展示名称、URL、协议和模型仍可修改。

Provider 认证、发现与图片能力#

模型配置包含三个彼此独立的契约：路由如何认证、目录如何发现模型，以及每个模型允许哪些输入。模型能出现在选择器中，不证明这三层都已经成立；真正请求会按所选 Provider 的适配器与不可变配置快照执行。

01Authenticate

普通 API 路由解析具名凭据；Bedrock、Vertex、Azure 与 Codex 等原生协议还分别依赖 AWS、ADC、api-version 或 OAuth，不能靠一个通用密钥字段补齐。

→
02Discover

获取可用模型只查询表单当前的端点和凭据，候选项先进入草稿；目录提供方直接使用已安装 catalog，不发网络请求。

→
03Declare

手动模型默认只接受文本；视觉模型必须在自己的 input 或路由 defaultInput 中显式声明 image，Harness 不会探测端点模态。

模型级 input 优先

解析顺序是模型条目、已安装 catalog、路由 defaultInput；路由默认值只是最后回退，不会收窄 catalog 已知的图片能力。

少声明会提前拒绝

未声明 image 时，Harness 会在发送前点名模型并拒绝图片；为自定义视觉模型补充 input: [text, image] 后开启新会话再试。

多声明会污染当前会话

若端点实际不支持图片，Provider 会在用户消息已持久化后失败，同一会话会持续重发它；应切换到真实视觉模型、fork 到图片之前，或新建会话。

“获取可用模型”不是保存

OpenAI 兼容发现只支持能以 GET /models 与 Bearer 凭据完整描述的协议。选择返回项只修改表单草稿，保存设置后才注册路由；不支持发现的端点应手动填写模型。

能力声明是部署方的断言

input 与 defaultInput 不会验证远端真实能力。保守的纯文本默认会较早失败；错误授予 image 则会在轮次中途失败并留下持久消息，后果更难恢复。

MISSING_CREDENTIAL在模型页保存密钥，或提供配置引用的环境变量。
UNKNOWN_MODEL重新选择已配置模型，或在自定义提供方中添加模型。
401 /models检查凭据；不提供模型发现端点时应手动录入模型。

首次启动与模型就绪诊断#

首次使用引导不会把“页面上存在模型名称”误当成模型已经可调用。只要任意已注册路由拥有已配置的具名凭据，或该路由使用 Bedrock、Vertex ADC 等原生认证，引导就会自动完成；否则才提示填写 DeepSeek 官方密钥。

01Configured

设置中存在 provider profile，模型页可以编辑它；这不等于适配器正在提供路由。

→
02Credential

绿色状态只表示具名引用已经存储；环境提供的只读凭据同样有效，原生认证则不显示圆点。

→
03Routable

会话选择的 provider 当前必须有活跃适配器；否则输入框会被阻塞并提示重新选择模型。

模型目录只是建议列表，不是路由白名单：一个未列出的模型仍可能由适配器解析，而目录中可见的休眠提供方也可能暂时不可调用。真正发送 prompt 时，宿主会再次执行权威检查，并以 model-unavailable 拒绝不可路由的选择。

引导跳过不代表配置成功

适配器缺失、配置能力只读或联接失败时，凭据步骤会直接让位，Models 页面仍是诊断入口。保存密钥后无需重启；DeepSeek 路由会在下一次调用时重新解析凭据。

会话模型选择如何收敛#

/model 与输入框的模型入口共用同一份会话级目录，通过 Host 提交完整的 provider、model 与 reasoning effort。打开选择器会刷新目录；提供方元数据失败以内联不可选行呈现，其他可用分组仍能继续选择。

Host 选择才是真源

目录只负责呈现。当已选 provider/model 不再出现在公布分组中，路由选择仍可保持有效，但触发器回退为 Select model，也不会显示陈旧 Effort。

旧响应不能覆盖新选择

目录加载与选择操作共用单调代次。选择失败会保留上一次选择和可用分组；较旧请求即使迟到也不能回写新状态。

重连重新建立目录

连接重置会丢弃常驻目录投影，再拉取 Host 恢复的选择；未变化的选择子结构保持稳定，避免无意义的 UI 抖动。

目录缺失不等于输入必须阻塞

只有 Host 明确报告 routable: false 才禁用输入框；首次加载前或加载失败后的 null 不阻塞。已寻址的 subagent 不公开模型选择入口，也拒绝目录刷新和选择操作。

输入阻塞如何保持可恢复#

知道某个会话无法发送消息的功能包，可以通过 conversation.blocks 向输入区推送带本地化理由的 block。InputBar 仍复用原来的 textarea，只把它设为禁用并将理由显示为 placeholder，不会换入另一棵临时表单树。

模型 seat 保持可用

在会话 block 姿态中，模型选择是唯一不锁住的控件，因为当前声明的阻塞都依靠重新选择可路由模型解除；同时锁住它会形成无法自救的界面。

依赖方向避免反向耦合

ui-model-selection 等功能包依赖 ui-conversation 并主动注册阻塞；会话壳不反向读取各功能包内部状态。

无 Workspace 优先

如果会话 block 与未选择 Workspace 同时成立，界面使用无 Workspace 姿态，因为选择工作区是发送前更早的前提。

Block 只是客户端提示，不是安全边界

即使浏览器已经禁用输入，Host 在真正接收 prompt 时仍会执行权威路由检查并拒绝不可服务的选择；前端状态不能替代宿主验证。

选择工作区#

点击「选择工作区」，添加你启动 dsh 时所在的项目目录。工作区决定 Agent 能够读取和修改的文件范围。

注意

选择工作区前，会话输入框保持禁用。请勿将包含敏感凭证的目录设为工作区。

工作区列表如何收敛#

Workspace 与 Session 列表各有独立的 pending → ready 基线。基线请求进行时到达的新增、更新、移除和顺序帧不会丢失，而是在响应之上重放；重连后的新基线会接纳其他客户端在离线期间提交的持久顺序。

拖拽先乐观显示

Workspace 拖拽会立即安装本地顺序，再等待 Host 确认。只有最新请求的回声可以结算它，更新的 Host 顺序帧又优先于较旧回声。

失败回到已确认值

最新排序请求被拒时，列表恢复最近一次 Host 确认的顺序，不会倒退到更早、且仍未提交的某次拖拽。

删除不会被迟到帧复活

已移除的 Workspace id 在当前进程保留删除标记，延迟到达的 changed 帧不能重新插入它；删除成功后相关 Session 转入 Ungrouped。

Workspace 的拖拽顺序始终由 Host 持久化。Session 顺序则取决于视图：真实 Workspace 的手动排序可写回 Host，Ungrouped 与跨 Workspace 的单列表没有共同记账，只保存在当前浏览器。

列表顺序不是目录权限

重排、折叠或删除 Workspace 注册记录都不会移动项目目录，也不会删除 Session 日志。它们只改变 Host 记账与浏览器投影。

工作区目录如何选择#

目录选择不是浏览器自行读取磁盘，而是由宿主提供稳定的能力。自适应后端只在启动时判定一次：本机回环访问、非 SSH 且存在可用桌面会话时使用原生系统对话框；远程、无显示或情况不明确时使用应用内浏览器。

Native

在宿主屏幕打开系统选择器。macOS 使用 osascript，Linux 使用 Zenity 或 KDialog，Windows 使用 IFileOpenDialog；取消返回空结果，中止会终止原生进程。

Browse

由宿主列举绝对路径中的目录，适合远程客户端。每层默认最多 1000 项，只返回目录并按名称排序，也可以创建一个经过校验的子目录。

浏览范围不是沙箱

当前 Browse 后端没有限定根目录，工作区创建也接受任意已有目录；目录选择器只负责交互体验，真正的写入边界仍由权限和沙箱策略决定。

运行第一个任务#

新建一个会话，然后尝试发送一个目标明确、可以验证的任务：

总结这个仓库，列出它的主要模块，并解释各模块之间的关系。

Agent 可以读取文件、执行命令并维护计划。当某项操作超出当前权限策略时，Web UI 会先请求你的批准。

New Session 与空白会话复用#

进入某个 Workspace 的 New Session 时，客户端先寻找该 Workspace 记账中的既有空白会话；只有同时满足 blank、cwd 等于 Workspace 路径、且 id 属于其 sessionIds 才复用，否则由 Host 创建新的 Session、Agent 与 cwd。

目标有明确优先级

新会话优先使用显式选择的 Workspace，其次是当前 Session 所属 Workspace，再其次是最近活跃 Workspace；完全没有 Workspace 时进入未选择的空白页面。

Host 接受才算使用

首条 prompt 的 RPC 成功意味着消息已进入 Host 日志，此时 blank 单向变为 false。首讯被拒时保持 blank，之后仍可安全复用。

占位行不是历史

空白 Session 保留在运行时 store，但普通列表隐藏它；临时“新会话”行没有时间、菜单或可复制标题，首条提示落地后才开放重命名、fork 与归档。

只匹配 cwd 不足以复用

路径相同但不在目标 Workspace 记账中的空白 Session 不会被接管。成员关系与 blank 位都来自 Host 投影，避免不同工作区意外共享同一会话。

侧边栏会话行的注意力状态#

Session 行把当前需要用户处理的交互归为等待审批、计划待审或等待回答，并使用琥珀色警告点。运行中使用蓝色指示器；悬浮卡片与视觉隐藏文本会给出相同的本地化状态，而不是只靠颜色传达。

请求在打开前已跟踪

Manager 按稳定请求 id 缓冲 requested 与 resolved 帧，即使 Session 对象尚未实例化。回放重复项会被替换，已解决项会被移除。

交互优先于运行

待处理交互是会话行的主要状态，优先于自身运行指示。审批与普通问题并发时，第一个待回答问题优先，以匹配输入框路由。

重连只恢复仍待处理项

pendingInteraction 只在当前连接代次有效；断线时清空，mux 重新打开后的权威回放不会复活已经结算的请求。

子代理 Session 行在共享侧边栏隐藏，但可见 parent 会聚合不间断 subagent 谱系中的运行后代数量。普通 fork 会开启独立子树，不计入聚合；主要交互或自身运行都不存在时，后代活动才优先于绿色未查看完成提醒。

父行变蓝不代表父 Agent 在运行

蓝色可能来自运行中的子代理。悬浮与无障碍文本会报告确切后代数量，最后一个后代停止后，先前的未查看完成提醒会重新出现。

Session 的仅追加事件日志#

SessionEvent 日志是一次 Agent 交互的唯一真源；模型消息历史、UI 状态和回放结果都从同一序列派生，不存在另一份单独维护的 transcript。每条事件都有连续 seq 和毫秒时间戳，payload 必须是无损 JSON。

01Turn

一次排队输入的生命周期；拒绝或空输入也可能只有 start/end 而没有模型步骤。

→
02Step

一次模型调用及其请求的工具执行；重试会打开新的编号步骤。

→
03Surface

用户消息、组装后的 Assistant 消息和工具结果形成模型可见表层。

原始 assistant chunks 会完整记录以保证流式回放；组装后的 assistant message 才进入派生历史。完整 request header 记录模型、系统提示词与工具 schema，只有配置变化时再写一份新快照，因此任意请求都能从日志重建。

如何阅读持久事件目录#

生成的 Persistence Catalog 扫描核心 SessionEventMap 和仓库内插件的 declaration merging，列出每一种持久事件的 payload、JSDoc、声明位置与 surface 标记。它回答“日志里允许出现什么”，而子系统页面解释“这些事件为何出现、如何折叠”；Cordis 事件则是另一条实时控制通道，所有日志提交只通过统一的 session/event 通知观察者。

surface进入模型派生历史只有 user/message、assistant/message 与 tool/result 属于封闭的 SurfaceEventType；它们可以携带 sourceEventSeqs 和 surfaceOp。
log-only持久但不进入 transcript边界、流式分片、审批、设置和领域状态仍可回放与审计，却不会直接生成模型消息，也不能携带 surface 替换元数据。
append追加到表层尾部正常用户、助手和工具结果按顺序加入；事件 seq 单调递增，但表层顺序应由投影规则读取，不能自行按来源引用重排。
replace替换已有表层区间压缩等生产方可用闭区间替换节点，并在 sourceEventSeqs 中覆盖所有被遮蔽节点，让回放保留可追溯来源。
信封强制可恢复

每条事件拥有 type、会话内单调 seq、epoch 毫秒 time 与可无损 JSON 化的 data；Session.append 在写入边界强制序列化契约。

未知必需事件必须拒绝

读到当前构建不认识的 type 时默认拒绝重建。只有写入方明确标为 ignorable: true 的纯信息记录才能跳过，宁可过度拒绝，也不恢复残缺状态。

格式版本不承诺兼容

当前 SESSION_FORMAT_VERSION 为 0。更高版本应提示升级 Harness，更低版本若没有迁移路径也会拒绝，不能把无法理解的数据误报为损坏。

端到端请求旅程：控制、执行与投影#

一次输入不会从 Web 直接变成一条模型消息。Host 或 SDK 先通过 Agent handle 把输入交给持久 Inbox，默认 driver 领取后打开 Turn；每个获准 Step 从 Session 日志派生历史，组装系统提示词与工具 Schema，再调用 LLM 和工具流水线。可回放结果写回同一条日志，Web 与 SDK 只从事件流建立各自投影。

01Ingress

→
02Admit

Agent loop 唤醒并打开 turn/start，领取输入后进入 agent/pre-step；插件仍可放行、改写或拒绝本步骤。

→
03Execute

获准后记录 step/start 与 user/message，组装 request，消费 llm/stream，并把 Assistant 与工具执行结果写入日志。

→
04Project

每条持久事实经 session/event 广播；Chat、Trajectory 与 SDK transcript 都从日志重建，turn/end 后状态回到 idle。

SessionEvent持久事实域仅追加日志保存输入、边界、模型输出、工具结果和领域状态；需要跨重载、恢复或 fork 存活的事实必须落在这里。

消息没有进入执行

模型看到了错误上下文

检查持久 request header、已进入表层的 user/message、系统提示词与工具 Schema；不要从 Chat 的视觉排列反推真实请求。

界面与运行结果不一致

比较 Session baseline、连续 seq、session/event 增量与重连后的投影。修复投影或缺口恢复，不要让 UI 另建一份可写真源。

Turn 与 Step 不是同一层

Turn 表示从领取输入到不再欠工作的一次责任区间，可以包含零个或多个 Step；Step 才是一次模型请求及其工具调用。首批输入被 pre-step 拒绝或改写为空时，仍可能留下完整的 turn/start 与 turn/end，而没有 step/start。

模型可见内容必须已经记录

任何进入模型请求的内容都应能从 Session 日志重建。若新的上下文只存在于实时事件或内存变量，刷新、恢复和 fork 会生成不同请求；应先定义持久事件及其投影，再把它加入提示词。

Agent 投递、空闲与取消#

Agent 的公开句柄把所有输入路由到持久 Inbox。next-turn 保存普通后续轮次，next-step 保存最近步骤要消费的 steering 或注入上下文；每条消息拥有稳定 MessageId，并记录插入、认领或丢弃事实。

followup

唤醒 Agent，并让该消息成为自己轮次中的唯一普通输入。

steer

运行中在最近的下一步骤进入；空闲时会主动开启一个轮次。

inject

为下一次 pre-step 排队模型可见上下文，但不会自行唤醒空闲 Agent。

cancel 只中止当前活动并默认清理排队与 steering；keepInbox 可以保留尚未开始的工作。whenIdle 等待整个 Agent 达到真正静止，包括取消后的收敛、替换工作和 maintenance task，而不是确认某一条消息已经得到回答。

拥有 Handle 才拥有销毁能力

创建或恢复 Agent 的调用方拿到 AgentHandle；dispose 会停止 loop、等待退出、注销 Agent、移除内存 Session，最后展开整个 Agent scope。普通 registry 查询只返回不可销毁的 Agent。

运行中的实时消息队列#

Web UI 的 Queue 是实时控制面，不是从聊天记录猜出来的视图。宿主在队列变化及重连时发送完整的 session/queue 快照；每项由稳定的 MessageId 寻址，因此编辑、删除和插话都只作用于那一次入队。

Queue

保留为下一轮输入，当前轮次结束后按 FIFO 领取。取消 Web 会话中的活动轮次会保留这些待处理项。

Steer

尝试在最近的下一步骤插入用户指引；若窗口已经关闭，则安全退回普通 Queue，不丢失草稿。

Context

审批通知、任务完成和附件快照等注入上下文在领取前不向用户界面展示。

队列只有一项时直接显示，多项时默认折叠并可逐项编辑、删除或严格 steer。若 Agent 已经领取目标项，操作会收敛为“已开始投递”，客户端不会靠轮次状态擅自移除或重发消息。

Queue 编辑与严格插话#

QueueDock 中每个普通会话条目都是一行预览，但预览文本不等于完整消息。内联编辑器只能无损处理纯文本，因此包含图片或其他非文本块的条目仍可查看、删除和严格 steer，却会禁用编辑按钮。

纯文本编辑是事务

进入编辑后，删除与严格 steer 按钮替换为保存和取消；Enter 保存，Escape 取消。编辑进行中列表保持展开，不会把操作目标折叠掉。

严格 steer 转移原消息

Agent 运行时，这项操作把稳定 MessageId 指向的不可变完整消息原子转移到当前 next-step 窗口，而不是重新发送扁平化文本预览。

Subagent 行保持只读

已寻址 subagent 的继续执行传输不支持 Queue 变更，所以可见行不提供编辑、删除或严格插话，不伪造宿主无法兑现的操作。

待处理 steering 从 QueueDock 隐藏后，会立即在 Chat 尾部显示为用户样式气泡；Host 等对应的持久 user/message 进入 mux 流才退役临时项。交接因此没有空档或重复，并能从同一权威在重连和回放后恢复。

已关闭窗口不是发送失败

如果严格 steer 输给已经关闭的 next-step 窗口，原条目留在 Queue 中正常投递；如果驱动器已经认领它，投递已经开始。这两种已收敛竞态不显示错误，只有传输或未知故障才会报告失败。

运行中会话的键盘投递#

键盘提交会同时检查所寻址会话是否正在运行、是否支持 steering，以及 Host-backed 的 busyEnter 偏好。空闲时 Enter 与 Cmd/Ctrl+Enter 都执行普通 Queue；在上述可编辑状态中，Shift+Enter 始终只换行。

繁忙主会话交换两个手势

默认 Enter 为 Queue、Cmd/Ctrl+Enter 为 Steer；偏好切到 Steer 后两者互换。设置保存在同一用户 home 的 settings.yaml，可跨 Web 端口复用。

空草稿可严格插入整队列

繁忙且支持 steering 时，空草稿按 Cmd/Ctrl+Enter 会依 FIFO 把所有待处理项逐一严格 steer；普通 Enter 仍无操作，placeholder 会在可用时提示手势。

Subagent 始终只 Queue

已寻址 subagent 的继续执行传输不公开 steering；即使正在运行，Enter 与 Cmd/Ctrl+Enter 都走它唯一支持的 Queue 路径。

偏好只影响键盘手势

发送按钮和其他非键盘提交始终使用 Queue。Composer 的 Steer 是尽力而为：如果 next-step 窗口在接纳前关闭，消息会成为下一轮 Queue 唤醒，不报假失败，也不丢失草稿事务。

权限与审批#

Harness 把沙箱模式和审批策略作为两项独立机制。权限预设只是在产品层把两者组合成一个选择器；执行时仍由各自服务单独强制。

沙箱模式

read-only只读文件变更被拒绝，读取保持可用。
workspace-write工作区写入仅工作区和平台临时目录可写；默认搭配 ask。
danger-full-access完整访问不添加文件围栏；默认搭配 never。

文件系统围栏会在目标规范化后检查可写根，并在写入前重新规范化以缩小符号链接竞态。不过它是可信进程中的策略围栏，不是针对恶意宿主代码的内核安全边界。

Sandbox Policy 为每次调用解析完整策略：显式获批模式优先于 Session 日志最后一条 sandbox/mode，后者再优先于部署默认值；workspaceRoot 来自创建时冻结的 Session cwd，并先按文件系统语义解析再做词法规范化。

它们不表达网络、进程、设备、凭据或普遍读取隔离。Windows 的 Everyone 授权与 NTFS 硬链接仍可能形成外部写入口，且受限进程可读取调用者能读的文件；容器、microVM 与远程沙箱必须成组替换 fs、shell 等能力 Provider。

事故复盘：无害通知为何被误判成沙箱崩溃#

较旧 Landlock ABI 会先打印精确的信息行 landlock-run: partial enforcement (older Landlock ABI)，再正常执行子进程；真正的 launcher 失败则打印另一条 landlock-run: 致命诊断，不执行子进程并以 125 退出。旧分类器只看共享前缀再配任意非零退出，把来自两个主体的事实错误关联起来。

1成功的空搜索ripgrep 没有匹配时正常返回 1，却因前面的 partial 通知被误报为 SANDBOX_UNAVAILABLE。
2子进程自己的错误无效 pattern 等普通失败同样可能被冒充成 runner 故障。
125退出码仍不足以归因子进程也能自行选择 125；必须同时存在排除通知后的致命 runner 行。

约束从未被削弱，也没有命令在无约束状态下运行。stderr 仍是带内归因通道，受限子进程可以伪造相同证据；多项合取减少误报，但不能证明写入者身份，带外状态协议仍是独立加固方向。

02返回规范值

03渲染模型内容

一份声明同时约束类型与运行时#

defineTool 用统一的值 Schema DSL 描述参数和规范输出，支持 JSON 标量、数组、对象、不受约束的 json，以及必须恰好命中一个分支的 oneOf。必填参数通过属性上的 required 标记声明。

参数根默认开放

parameters 映射是隐式开放对象；原始 JSON Schema 对象也遵循开放默认值。只有显式对象把 additionalProperties 设为 false 时才拒绝未声明键，空的封闭对象只接受空对象。

Default 只是一条注解

系统不会替调用补默认值。缺少必填字段、类型不符、枚举无效与嵌套违规都会成为 INVALID_ARGS；工具正文或后置策略返回错误形状则成为 INVALID_TOOL_OUTPUT。

类型深度不限制校验深度

InferValue 在 16 层容器内保留精确 TypeScript 类型，之后回退为 JsonValue；编译和运行时验证使用显式工作栈，仍会遍历完整的有效深层 Schema。

oneOf 要求唯一匹配

它至少包含两个分支，一个值必须恰好通过其中一个；同时匹配多个分支也算失败。enum 与 const 只能使用和节点类型一致的 JSON 标量。

不支持的关键字不会假装生效

注册表先验证所支持的原始 JSON Schema 子集，并用带路径的错误拒绝未知或错误组合。通过原始 API 注册的工具仍需自行验证输入，但输出 Schema 始终由注册表强制执行。

为什么工具 Schema 目录必须启动真实插件#

上游 docs/tool-catalog.md 汇总随产品发布的模型可见工具：系统提示词最终提供的 name、description 与 JSON Schema parameters。它描述模型的输入契约，不替代执行局部的规范输出 Schema。

Boot, not AST

生成器在隔离的真实 Context 中启动每个工具插件，再读取 ctx.tools.schemas；运行时枚举、拼接描述、配置名称和原始 MCP Schema 都无法仅靠源码静态推断。

Completeness guard

磁盘上的 packages/*/tool-* 必须全部出现在启动 manifest 中；任何包遗漏，或启动后一个工具都没有注册，都会让生成检查失败。

default默认配置快照每个包通常按默认配置启动；必填但无默认值的分支由生成器明确选择并在包说明中披露。

附加上下文必须等整批工具结算

所有 tool/result 按调用顺序写入后，活动批次才把 additionalContexts 作为 FIFO user/message 注入，避免上下文插进调用与结果之间。Code Mode 子调用把上下文延迟到父级 run_code 结果之后，并记录自己的 tool/code-dispatch。

拒绝与异常也会收敛成一个结果

审批拒绝会跳过工具正文但继续经过后置与收尾阶段；流水线抛错或结果无法无损快照时，外层规范化会生成 isError 结果。这样 Session、模型与 UI 共享同一份不可变权威结局。

规范值、模型内容与 UI 展示各有边界#

一个 Tool 的成功结果不是一段字符串：execute 先返回由 output schema 约束的规范 JSON 值，render 再把它投影为模型可见 content，可选 presentationMeta 则生成可持久回放的 UI 元数据。

规范值只活在执行局部

注册表在渲染前对值做无损快照、校验和冻结，策略与 Code Mode 可以消费它；Session 不持久化该值，因此日志回放不能重新执行 render 来推导旧结果。

模型内容进入权威日志

最终 content、失败状态与结构化错误身份写入 tool/result，成为模型历史与审计材料。后置策略替换 value 时必须重新校验并重新渲染，替换 content 则保留原规范值。

展示元数据随结果回放

顶层调用可从已校验参数和值纯计算 meta，并交给 presentResult；Code Mode 嵌套分派不计算它。presentCall 与 presentResult 返回 undefined 时，UI 使用通用卡片回退。

呈现函数必须是纯函数

pending 卡片只能依赖调用参数，completed 卡片只能依赖参数和持久结果。它们在实时运行与日志回放都会执行，不能读取瞬时服务状态或产生副作用；旧日志参数校验失败时应安全回退。

替换 content 不是保密边界

内容重写只改变模型和日志看到的投影，执行流水线中的规范值仍可能被编程消费者读取。若某个值绝不能交给下游，应阻止结果或替换 value，而不是仅遮盖文本。

并行正文，顺序提交#

同一步骤中的连续安全调用进入有界滚动池，默认最多重叠 10 个；独占调用会等待当前池完全排空，单独执行，并阻止后面的调用越过它。把上限设为 1 即恢复完全串行分派。

并发必须明确选择

只有 isConcurrencySafe 对已解析参数确切返回 true 才进入并行池。工具未知、隐藏、未声明分类器、参数无效、分类器抛错或返回其他值时一律按独占处理。

完成快不等于先提交

后一个工具可以先完成正文，但它的 post-execute、tool/result 和 additionalContexts 必须等待前序槽位结算。模型历史因此始终与模型发出的调用顺序一致。

尚未启动会重新分类

每次补充滚动池前都会读取当前可见定义；前序结果导致注册表变化时，后续调用可以即时变成独占屏障，而不会沿用过期分类。

并发安全是状态所有权承诺

选择并行的工具正文不能修改父级拥有的可变状态；共享状态上的竞态必须可交换，或在冲突时安全拒绝。并发池只提升允许重叠的工作，不改变策略与日志契约。

取消不会遗弃已经启动的正文

取消会停止补充池并等待已启动调用 settle，再按顺序提交它们及其上下文；尚未分派的模型调用会得到 ABORTED_BEFORE_DISPATCH 合成结果，保证 transcript 仍然配对完整。

限制继承面，不删除子级自有能力#

ToolRestriction 是 Agent 作用域对继承工具的实时视图过滤器。它先处理部署全局层和祖先作用域贡献，再叠加当前作用域自己的注册，因此委派子级仍能保留 report 等完成自身协议所需的本地工具。

多个限制只会继续收窄

同一作用域链上的 allow 与 deny 掩码取交集，任何后来的限制都不能恢复先前已隐藏的继承工具。限制的 disposer 只撤销自己那一层过滤。

Allow 与 Deny 面向未来不同

deny 只排除登记时点名的全局工具，因此后来新增且未点名的工具仍可见；allow 只保留名单成员，未来出现的新名称默认不可见。

本地工具在过滤后合并

当前作用域自注册工具不会被继承过滤器删除，也不能在 restriction 中点名。保留的 run_code 传输同样位于过滤之外，应限制它所暴露的末端工具。

无效限制会在注册时失败

普通全局 Context 不能安装 Agent 限制；空掩码、未知名称、作用域本地名称和保留传输名称都会抛错。工具集合变化后，下一次请求使用新的可见 schema。

可见性过滤不是授权系统

Restriction 降低模型能发现和直接调用的能力及 schema token 成本，但不建立安全主体或资源权限。真正的执行授权仍由审批、Guard、沙箱和具体服务边界负责。

Code Mode 的嵌套工具调用树#

Chat 按 call id 配对根工具调用与结果，再把 Code Dispatch 的 start 与 settlement 折叠进该根 Context。每个 ToolCallBlock 通过 subCalls 按启动顺序递归拥有 child；child 不会成为独立 Chat 根记录。

缺少开始事件仍可呈现

如果 start 位于尚未加载的更早历史，已到达的 settlement 仍会显示，只把 callTime 留为 null，不伪造启动时刻。

更新保持兄弟身份

一次 child 更新只复制从该节点到根的祖先链；未变化 sibling 保持对象身份，避免整棵调用树无谓重绘。

异常边不污染树

会形成环或超过固定 256 层上限的 parent-child 边会被消费，但不会修改投影，阻止恶意或损坏日志制造无限递归。

UI 从 root 递归遍历同一份标准调用块，每个原子调用都走同一个 keyed tool view slot；没有专用视图的工具使用通用卡片。Trajectory 为自身 target 独立组装同一种嵌套契约，不读取 Chat 的树。

业务 UI 不拥有调用拓扑

工具插件只注册 wire 名称与原子视图，不应自行配对事件或重建 transcript。Runtime 决定 root/subcall 关系与生命周期，Conversation view 决定它在聊天流中的位置。

工具详情：底层接缝存在，产品入口尚未接线#

聊天流中的工具卡片已经可用：Conversation 按同名节点分发调用，组装后的 Web bundle 交给 ui-tool 渲染递归调用树、专用视图、通用卡片与 render-intent。这里展示的是消息流中的调用状态，不等于已经开放一套可导航的详情检查器。

详情席位已经声明

详情壳层可以把当前选中的调用交给 conversation.details.tool；如果没有匹配 renderer，只有这个席位保留原始结果回退。

ChatViewInjected.openDetails 虽已实现，但组装后的应用没有调用方。用户无法从工具卡片进入该详情壳层，原始结果回退也因此不可达。

导航能力尚未交付

当前不要预期 Input、Output、Metadata 标签切换，Prev/Next 调用步进，或从详情直达 Trajectory 的深链接。

不可达不代表事件丢失

工具调用仍按原位置出现在聊天流，Runtime 仍维护标准 root/subcall 投影；缺的是详情入口及其导航交互。排障时可使用独立的 Trajectory 视图检查事件，但不能把它描述为工具卡片已经提供的深链接。

插件通过同名的 TypeScript Config 类型和 Schemastery schema 接受配置。默认值属于 schema；无效配置应在插件加载时立即失败，而不是运行到一半才降级。

config.ts
export interface Config {
  timeoutMs: number
  mode: 'fast' | 'accurate'
}

export const Config = Schema.object({
  timeoutMs: Schema.number().default(30000),
  mode: Schema.union(['fast', 'accurate']).default('fast'),
})
判断标准不同部署是否可能需要改变这个值？如果是，它就应该是配置字段，而不是硬编码常量。

修改 cordis.yml 会触发插件热替换：旧实例先卸载并清理 effects，新实例再使用已校验的配置加载。

事件系统#

事件是插件间松耦合通信的核心机制。Cordis 提供四种模式，它们的执行与返回规则不同：

emit同步广播

执行所有监听器，忽略返回值。

bail同步短路

首个有效返回值会停止后续监听器。

serial异步顺序

按注册顺序等待，同样支持短路。

waterfall包装流水线

监听器包装下游返回值，形成处理链。

Waterfall 的关键规则

监听器必须调用 next() 才会继续下游；不调用会有意短路整条流水线，适合拦截器和网关。

Cordis 事件通常采用 namespace/action 命名。持久化的 turn/*、step/* 和 tool/* 是会话事件类型；观察它们时应监听 session/event 并检查 event type。

插件生命周期#

每个插件运行在独立 Fiber 中。依赖未就绪时等待，加载成功后进入 ACTIVE；必需服务消失时自动卸载，服务恢复后重新加载。

PENDING→LOADING→ACTIVE→UNLOADING→DISPOSED

ctx.on()、工具注册和 ctx.effect() 都由 Fiber 追踪，卸载时自动撤销。若多个清理步骤存在先后依赖，应放入同一个 effect 的 disposer 中串行执行。

Context、Registry 与 Fiber 如何协作#

Cordis 的三个对象回答不同问题：Context 决定“这个位置能解析到哪些服务”，Registry 决定“插件何时可以创建或重跑”，Fiber 决定“这次插件实例拥有哪些状态与副作用”。它们不是三份容器；Registry 创建 Fiber，Fiber 持有扩展自父级的 Context，服务代理再按该 Context 的隔离标签解析实现。

Context作用域化服务视图普通属性通过服务解析器读取。extend 只增加子级元数据，isolate 为指定服务切换标签，intercept 为下游插件叠加服务配置；三者都不修改父 Context。
Registry插件入口与依赖调度plugin 先按 Config 校验参数，再创建 Fiber；inject 简写会等待所有必需服务，并在任一实现变化时卸载后重新运行回调。
Fiber一次加载的所有权单元保存已校验配置、必需服务实现快照、生命周期状态和 effect；await 等待当前转换并重新抛出启动错误，dispose 等待清理完全结算。
必需能力使用 inject

声明依赖让插件在实现活跃后才启动，并在实现撤回时自动失活。加载顺序由能力可用性形成，不应靠配置行先后碰运气。

可选探测使用 get

ctx.get(name) 不要求 inject，默认只返回提供方 Fiber 当前活跃的实现；调用方必须处理 undefined，也不会因实现变化自动重跑。

提供服务必须归属 Fiber

ctx.provide 注册的实现只有在提供方活跃后才对同一隔离作用域可见；disposer 或 Fiber 卸载会撤销它并唤醒依赖方。

失败、并发与清理的防御性模式#

这些不是抽象风格建议，而是 DeepSeek Harness 从已经发布或差点发布的缺陷类别中提炼出的实现规则。共同目标是让失败事实保持完整、资源真正停稳，并让不可信输入无法跨越边界。

正交事实分别上报

超时、signal 与 exitCode 可以同时成立；例如进程捕获终止信号后仍以 0 退出。不得用一个标志的分支决定是否记录另一个标志。

公共边界先规范化

同一失败可由实现抛错或终止分片表达，公共 Runtime 应先统一成约定形态；middleware 与消费者自身缺陷仍保持异常，不能混成 Provider 失败。

异步状态不等于单次结果

followup 没有逐消息完成值，status 和 whenIdle 也可能覆盖队列、steering 与注入工作。自动化调用方必须明确自己观察的完整活动区间。

Dispose 必须等待完全停稳

只发终止或 abort 信号便返回会留下孤儿任务。清理应先关闭监听与通知注册，再等待子进程退出和所有工作达到 quiescence。

分发器隔离回调异常

一个用户监听器抛错不能 reject 它所在的核心 Promise，也不能饿死后续监听器；分发循环应逐项捕获并记录。

敏感环境与临时路径默认不可信

子进程环境应移除名称中包含 KEY、SECRET、TOKEN 或 PASSWORD 的值；spill 与临时文件使用 0700 私有目录、随机名称、wx 和 0600。

删除链接，不要递归删除它指向的目录

可能是 symlink 或 Windows junction 的路径应先 lstat，再用 unlink 删除链接本身；只有确认是真实目录后才允许 recursive rm，避免沿链接越界删除目标。

UI Slots：声明、选择与清理#

Client bundle 到达浏览器后，通过 Slot 注册表把组件贡献到已有界面。一次注册同时声明目标 slot、可渲染的子 slot、可选 store seat 与业务注入；这张声明表既是类型契约，也是运行时授权边界。

声明即授权

组件只能注册到已经声明的 slot，也只能渲染注册时列出的子 slot。未声明目标、重复子声明或跨 scope 复用同一 handle 都会在注册时失败。

Chain 由条目提名

每个 chain 条目提供纯 selector；按可选升序 priority、再按注册顺序检查，第一个返回非空值的条目获选，否则调用 owner fallback。

状态由运行时绑定

核心只传递裸 snapshot source；React selector hook 在 renderer 中绑定。Store actions 会移除 draft 参数后交给组件与 inject factory。

生命周期会收回整棵贡献

注册 disposer 不只移除当前组件，还会递归撤销它声明的子 slot、贡献记录与 store 挂载。声明代次与普通条目版本分开计数，让运行时识别过期授权。

模块可加载不代表 Slot 合法

Client Module Loader 负责下载、物化与 HMR invalidate；SlotCore 独立验证布局所有权。插件必须同时满足模块图和 slot 声明，不能靠运行时碰巧存在的组件路径绕过授权。

跨插件的 Slot 声明注入#

贡献方可以独立于声明方启动：调用声明注入后，目标 slot 已存在就同步执行回调，否则进入等待。声明被移除时回调 effect 同步释放，稍后重新声明会再次执行；贡献方自己的 fiber 卸载也会取消等待或撤销活跃贡献。

声明代次驱动

专用的单调 declaration epoch 只在声明出现或消失时递增。普通条目变化不会重启注入，但折叠后立即重建仍会触发新一代回调。

多项注册成事务

回调可返回一个 disposer，或由 generator 依次 yield 多个注册。中途 setup 失败会回滚已完成项，正常 teardown 则按逆序执行。

直接注册仍严格

注入 API 负责等待声明；直接向尚未声明的 slot 调用 register 仍立即抛错，不会隐式创建布局位置。

同一 tick 内先释放旧授权

声明绑定的 teardown 与注册账本变更同步发生，因此后续注册不会与旧声明持有的资源短暂重叠。这让 HMR 和条件布局切换保持确定性。

用插件清单核对运行拓扑#

设置中的「插件」页面是当前 Cordis Loader 树的只读快照。它首次打开时才查询 Host，跳过结构性 group 行，并按 Loader 顺序列出条目 ID、模块标识、有效启用状态和根 Fiber 阶段。

active运行中根 Fiber 已经完成加载并处于活动阶段。
pending / loading尚未就绪依赖或初始化仍在进行，不能只凭配置行判断能力已经可用。
failed / unloading失败或退出中条目存在于 Loader，但其运行生命周期并非可服务状态。
null没有存活 Fiber快照无法区分从未启动、已结束或其他历史原因。

插件页支持按模块短名和条目 ID 搜索，但没有修改能力、失败历史或实时订阅；重新打开 Settings 才会取得新快照。它回答“现在加载成什么样”，而 --dump-config 回答“配置由哪一层引入”，两者要结合使用。

运行清单不提供来源归因

清单不会告诉你条目来自 bundle、profile、DSH_HOME patch 还是命令行 override。需要追踪来源时，请检查带逐行来源标注的生效配置；需要失败堆栈时，请查看 Host 启动日志。

Scope 路由与生命周期所有权#

Scope 用同一个注册上下文同时表达“哪个 Agent 能看见这项贡献”和“谁负责在生命周期结束时拆除它”。不透明的 ScopeKey 只按对象身份比较；事件使用路由载体过滤，但真实业务对象仍作为显式参数传递。

Global layer

立即存在，保存所有 Agent 都可见的具名与匿名注册项。

Scoped layer

按需创建，近层同名条目遮蔽全局项；读取本身不会意外创建状态。

Quiescent dispose

并发 dispose 会等待同一个完全停稳边界，精确撤销该 Scope 拥有的贡献。

同一层的具名条目保持插入顺序；匿名条目即使值相等也拥有独立身份。只有整个作用域层的所有 table 都为空时才回收它，避免删除一个注册表时误伤兄弟表。

Web Server 的路由与暴露边界#

GUI 的 HTTP Server 只是浏览器载体，不理解 Agent loop。请求先匹配 exact 路由，再匹配最长 prefix，最后交给唯一 fallback；重复路由或第二个 fallback 会在组装时直接报错。

127.0.0.1默认回环只供本机浏览器访问，是默认监听姿态。
0.0.0.0显式网络暴露服务本身没有 TLS、认证或 Origin 策略，会暴露给所在网络。
port: 0系统分配端口操作系统选择空闲端口，服务公开最终监听值。

静态 SPA fallback 对路径穿越返回 403、非 GET/HEAD 返回 405，未知扩展资源不会伪装成 JavaScript。关闭时同时停止监听并强制关闭 SSE 等长连接，避免插件卸载永久挂起。

事故复盘：不要在替代服务器上验收当前 GUI#

一次 Web Agent 会话修改了 GUI 源码，却不知道当前页面的规范 URL、服务进程和更新模式。它先把验收交回用户，再把裸 Vite 的 HTTP 200 当成成功，最后又在另一个端口启动完整 Host；这些证据都没有证明用户正在看的原页面已经改变。

build产物可以生成只证明源码能编译，不证明承载会话的进程已经读取新产物。
HTTP 200传输层可以响应裸 Vite 没有 Host 注入的 window.__DSH_BOOT__，即使返回 200 也可能只显示白屏。
manifest替代应用可以启动另一个 origin 拥有合法启动 manifest，仍不能证明既有页面完成刷新或 HMR。
01Identify

从 app:web-surface、DSH_WEB_URL 与 DSH_WEB_MODE 取得当前规范 URL 和真实模式。

→
02Update

生产模式重建并刷新既有 URL；开发模式按变更类型走 watcher、bundle 重建或页面刷新。

→
03Observe

由外部浏览器、HTTP、进程与会话日志共同证明请求的改动在同一 origin 生效。

独立 Vite 明确拒绝启动

apps/web 的裸服务模式在配置阶段失败；测试要求进程自然退出并插桩 Server.listen，不能用测试超时伪装成快速失败。

开发模式有两段链路

dsh web --dev 只挂载 HMR 接收端；同一源码检出中的 pnpm run dev:web 负责重建客户端插件 bundle，Web shell 与普通包变更仍需刷新。

长期进程必须受管

通过 shell & 启动会绕过任务身份、完成通知、结果收集和清理；确需替代服务时也必须使用受管后台生命周期。

验收目标必须保持同一 identity

成功构建、端口可达和启动 manifest 是三个独立事实。只有在明确的目标 origin 上，从外部观察到所请求的界面变化，才证明当前 GUI 已更新；替代服务不能代替这项证据。

Web API 的传输与安全边界#

Web API 使用 HTTP POST 承载上行 unary/respond，并以两条只向浏览器发送消息的 WebSocket 承载 mux 与 host 事件。每个请求先校验信封，再按方法校验业务载荷；响应回显原 rpcId。业务错误留在 RPC 结果中，HTTP 状态只表达传输层结果。

01JSON gate

所有 API POST 必须声明 application/json，否则在分发前返回 415；跨站简单请求因此不能直接触发有副作用的方法。

→
02Origin gate

原生目录选择、设置、凭据和本地文档操作属于特权面，浏览器载体将它们限制在回环地址的同源请求；应用内目录浏览仍经过 Host 与 Origin 信任栅栏。

→
03Host gate

路径由宿主根据预设 ID 或无路径操作解析；浏览器载荷不能指定任意文件去打开。

不要把监听地址当成认证

底层 Web Server 本身不提供 TLS 或用户认证。需要远程访问时，应在可信反向代理后增加 HTTPS 和访问控制，并审查诊断错误是否适合向多用户公开。

Host 原生打开与桌面可见性#

host.openPath 把已由 Host 解析的路径交给操作系统默认应用：macOS 使用 open，Windows 使用 Invoke-Item，桌面 Linux 使用 xdg-open。共享 runner 直接 spawn 可执行文件并传递参数，不拼接 shell 字符串；取消会传播到原生子进程。

能力声明

host.describe.canOpenPath 根据显式 nativeOpen、注入 opener 或平台显示探测发布；断线时客户端清空该能力，不沿用旧判断。

WSL 路径交接

Linux 路径先经 wslpath -w 转成 Windows 或 UNC 路径，再交给 Windows 应用，包括 HTML、SVG 等浏览器文档。

浏览器双重门禁

界面只有在页面来自 loopback 且 Host 同时声明能力时才呈现原生操作；请求仍受同源与特权方法栅栏约束。

Loopback 不能证明桌面属于操作者

SSH 端口转发可能让远端 Host 看见来自 127.0.0.1 的请求，却把窗口打开在无人值守的服务器桌面。无头 macOS/Windows、WSL interop 不可用或 Linux display 探测失真时，也应在网关设置 nativeOpen: false，以关闭原生交接。

WebSocket 就绪与断线恢复#

浏览器分别连接 /api/events.mux 和 /api/events.host。两条连接都只接收文本帧，客户端不会在 socket 上发送业务请求；直接用普通 GET 访问会得到 426，也没有浏览器 SSE 回退。

01Open

新 generation 同时打开两条下行流，并调用 host.describe 验证 HTTP 上行可达。

→
02Publish

就绪后才发布该 generation 的 Host 能力描述并触发业务层重新同步基线。

→
03Rebuild

任一流结束都会使整代失效，两条流一起重建；旧代响应不能覆盖新状态。

连续失败采用带抖动的指数退避：首次上限 500ms，逐次翻倍，最高 10 秒；成功连接后尝试计数归零。断线时 Host 能力描述会清空，因此目录选择和本地打开等消费者不会沿用过期能力。

反向代理必须支持 WebSocket Upgrade

代理若只转发普通 HTTP，页面资源和 POST 可能正常，但两条事件流无法就绪。应允许上述两个路径升级，并避免把 426 当成可缓存的应用响应。

TypeRT Remote 调用边界#

TypeRT 把 Host 服务方法生成成可验证的远程调用描述符。请求只发送 namespace、method 和具名 args；取消信号走传输载体，在业务参数之后注入，绝不会混进 JSON 参数。

01Describe

生成器固定参数顺序、wire 字段、lookup、context 和输入输出 codec。

→
02Bind

Gateway 把不透明 wire identity 解析回当前活的 Host 对象或作用域。

→
03Validate

调用前后都检查边界 schema，基础设施错误使用稳定分类。

Lookup provider 卸载后，wire 声明仍保留，因此请求会明确返回 unavailable，而不会把身份字符串误当普通对象。Client 只看见显式导入并挂载的 Remote namespace；业务服务实例和 JavaScript Proxy 都不会跨边界。

API Gateway 调用与撤回生命周期#

Remote 是生成时选定、运行时解析的一元 RPC。Client 装配只挂载明确选择的贡献；每次调用仍通过 Connection 的 /api 载体取得 Host 当前的描述符、lookup 与 Cordis 服务，因此热替换不会继续使用缓存的业务对象。

01Mount

ctx.remote.$mount() 校验严格 codec，并安装具体方法与可追踪的 remote.<namespace> 子服务。

→
02Invoke

Client 校验位置参数并组装具名 args；Host 再校验字段集合、解码 identity、解析实时接收者并检查返回值。

→
03Retract

贡献撤回会移除方法与描述符、中止进行中的调用，并让外部保存的陈旧函数句柄拒绝再次调用。

取消归 Connection 所有

AbortSignal 是描述符元数据，不属于 wire args。Client 将调用信号与挂载生命周期合并，Connection 负责请求关联和取消，Gateway 只在业务参数之后注入 signal。

故障保留所属层级

字段、codec、binding、lookup 与 context 故障在业务代码边界内明确分类；冷恢复失败和 ownership fence 可以保留原有 RPC error，而不折叠成笼统 internal。

严格约定不能静默降级

Host 曾注册的严格 endpoint 被撤回后直接失败，不回退到较弱的源码参数推断，避免热卸载悄悄降低校验强度。

Remote 不是通用流协议

Remote 只表达单请求、单结果的方法。会话事件、增量数据、分页与实体子流可以复用 Connection，但应使用各自的协议；未被 Gateway 认领的 /api endpoint 才回退给既有 API Proxy。

Host 事件如何进入 Client#

API Remotes 用一份显式 allowlist 选择可转发事件；同一个值同时派生 Host 转发循环和 ctx.remote.$on() 的合法 TypeScript 键面。事件签名仍由原始 owner 包的 Cordis Events 声明拥有，不在网关重写第二份可能漂移的类型。

01Select

Host 构建拒绝未声明、绑定 AgentScope 或并非单向形状的事件；加入名单意味着 payload 将原样跨边界。

→
02Forward

Connection 的 Host 下行流承载事件帧，Client Runtime 解码后交给 ctx.remote.$dispatch()；业务消费方只调用 $on()。

→
03Fan out

监听器按注册顺序调用；一个同步抛错或异步拒绝只被记录，不会阻断其他监听器或事件帧泵。

订阅属于 Fiber

每个订阅归创建它的 Cordis fiber 所有，fiber 卸载即自动释放；同一函数可以独立订阅多次，并分别撤回。

没有订阅就丢弃

$dispatch() 收到合法但无人监听的事件会直接丢弃。Client 不维护事件积压，也不把它转成可供后来订阅者读取的状态。

重连不会重放

转发事件没有 payload 投影、脱敏、Scope 化订阅或重放保证。需要恢复一致性的 UI 必须在订阅前读取权威基线，并把事件仅当作失效或刷新信号。

Allowlist 是数据披露边界

事件名与参数数组原样进入浏览器。新增转发项前应审查 owner 的全部参数是否适合暴露；需要裁剪、脱敏或耐久重放的数据，应建立独立协议，而不是直接加入名单。

ACP：面向程序的 Agent 入口#

Harness 的 ACP Server 通过 stdin/stdout 上的 JSON-RPC 把 Agent 暴露给自动化客户端。它是传输适配器，不是 Web UI 或通用能力 seam：stdout 只能写协议帧，诊断必须走 stderr。

01Initialize

协商协议版本，只公布文本提示词基线；不声称支持图像、音频、编辑器、终端、文件系统、MCP 或会话恢复能力。

→
02New & prompt

绝对 cwd 创建独立 Agent；文本块拼成一条用户消息，资源链接只展平为带方括号的引用，每个会话同时最多处理一个提示词。

→
03Settle

桥接层等待 Agent 整体空闲，再以 end_turn 或 cancelled 结算；关联轮次的模型错误则拒绝当前提示词。

只发送已提交文本

每个非空 assistant/message 文本块成为一个 agent_message_chunk。原始 token 分片、未提交重试输出、推理、工具活动、计划、标题与用量都不进入 ACP wire。

权限是一锤子买卖

桥接层按工具调用 id 提供一次性允许或拒绝选项，自动化客户端可以应答；模型只通过所属工具的常规结果得知结局，不会看到权限协议元数据。

多会话但不恢复

一个连接可拥有多个隔离会话，各有 workspace、提示词槽位与取消路径；当前只支持新建，不支持列出、加载、fork、删除或单独关闭。

取消与连接级清理#

session/cancel 只取消指定 Agent，并把它尚未结算的提示词标记为 cancelled；未知 session id 是无操作。取消不是整个共享 Context 的全局开关。

客户端断开和插件释放共用一次记忆化清理：先拒绝新工作并结算待处理提示词，只 drain 本连接拥有的 Agent 及其可继续后代，再并行释放 handle 并等待全部清理完成。其他前端拥有的 Agent 森林不会被带走。

stopReason 不是提示词专属轮次摘要

ACP 在整个自有活动期间转发已提交消息；提示词之后发生的 steering 或注入工作也可能参与，达到 token 上限的轮次仍可能在 Agent 最终空闲时以 end_turn 结算。需要完整推理、工具轨迹或持久日志时，应从 Session 系统读取，而不是从 ACP 响应反推。

事故复盘：100% 行覆盖为何仍漏掉 ACP 接线崩溃#

ACP Bridge 曾在真实编辑器首次调用 session/new 与 session/load 时分别崩溃，二者都显示 cannot get property ... without inject，但实际是两个独立机制。178 个单元测试和 100% 行覆盖都通过，因为测试绕过了真实 Loader 导出路径和真实 Fiber 调用拓扑。

Bug 1 · 默认导出丢失命名空间

模块同时导出 name、inject、Config、apply 和 export default apply。Loader 优先 unwrap default，得到没有元数据属性的裸函数，于是 apply 在未注入任何服务的 Fiber 中运行。

Bug 2 · Shadow 只向祖先查找

经另一 Fiber 的 traceable 代理调用 AgentLoop.resume 时，属性代理从 AgentLoop shadow 向祖先遍历，无法看见兄弟分支提供的可选 sessionPersistence。

同一错误字符串不是同一根因

删除默认导出修复 session/new 后，session/load 才暴露真正的 shadow 问题；Fiber 跟踪证明第一个异常发生在插件加载时而非请求处理器中。

namespace命名空间插件不要 default export保留 name、inject、Config、apply 的同级命名导出，让 Loader 读取完整模块元数据。
optional机会性服务使用 ctx.get未列入 static inject 的可选服务用拓扑无关的 ctx.get(name) 查找，并保留活跃状态检查。
required声明服务继续用属性访问已经属于插件 inject 集合的服务仍使用 ctx.service，让 Fiber 依赖等待和失活守卫保持生效。
01Load

无 API Key 的 e2e 通过真实 cordis.yml、Loader 和 stdio 子进程启动。

→
02Call

至少驱动 session/new 等不需要模型的核心 RPC，而不只检查 initialize 或 stdout。

→
03Resolve

TSX_TSCONFIG_PATH 固定到仓库 tsconfig，防止临时 cwd 静默加载陈旧 lib 产物。

行覆盖率不是交付路径覆盖率

手动构造 ctx.plugin({ name, inject, apply }) 会主动补回本应由模块导出携带的元数据；平铺根 Context 还会触发全局查找捷径。至少一个测试必须按用户真正使用的入口加载并调用插件。

能力的三种角色#

当能力需要可替换提供方时，Harness 将它拆成三个角色。只有完整组合才构成一个 capability seam；单独一个角色并不完整。

01Service Definition

定义 Cordis 服务以及 Request / Result 类型。

←
02Service Provider

实现本地、远程或沙箱中的具体行为。

→
03Consumer

把能力呈现为 Tool、API 或其他用户界面。

Provider 与 Consumer 都依赖 Definition，但彼此不依赖。只有角色需要独立演进或替换时才拆包；简单工具无需预防性拆分。

LLM 适配器#

新的模型提供方通过继承 LlmAdapter 并实现异步 stream() 接入。适配器把统一请求转换成提供方 API，再把流式响应转换成 Harness 的 StreamChunk。

block-start→text/tool deltas→block-end→usage→finish
  • 每个 block-start 必须有对应的 block-end。
  • index 从 0 递增，用于标记内容块顺序。
  • usage 必须在 finish 之前；finish 必须是最后一个分片。
  • 不支持的字段应抛出带稳定 code 的 LlmError，不得静默丢弃。

流式协议、失败与重试#

文本、推理和多个工具调用可以在同一响应中交错，index 把 delta 归属到对应内容块；block-end 携带完整块。共享 BlockAssembler 同时记录原始分片并组装最终 Assistant 消息，避免各消费方自行实现不一致的 fold。

Normalized failure

抛出的传输错误和流内错误统一为可序列化 LlmFailure，按稳定 code 路由。

One call, one attempt

适配器必须关闭 SDK 自带重试；Agent 恢复会开启新的、持久且编号明确的步骤。

Frozen policy

请求选定路由时捕获不可变重试策略，后续替换 Provider 不会改变进行中的恢复。

远程流有有限的 idle timeout；上下文溢出统一映射为 CONTEXT_WINDOW_EXCEEDED，空 completion 映射为可重试的 EMPTY_RESPONSE。Provider 的 retry-after 只是事实，不是自动重试决定。

TokenUsage 计数互不重叠

未缓存 input、cache read、cache write 三项相加才是计费输入；reasoning tokens 已包含在 output 中，汇总时不能重复计算。

默认重试策略与界面状态

未显式配置时使用 normal 策略：只对 EMPTY_RESPONSE、RATE_LIMIT、SERVER、TIMEOUT 和 TRANSPORT 最多重试两次，退避从 500ms 增长到最多 10 秒并加入 10% 抖动。有效且未超过上限的 Provider Retry-After 会替代本地延迟。

normal

有限预算，只重试明确允许的失败码；格式错误凭据和认证失败不会默认反复请求。

always

每次模型请求失败都无限重试，直到成功、取消或插件释放，包括永久性认证和配额错误。

cancel

取消会中止退避；尚未开始的新尝试不会写入 retry-started，界面显示已取消状态。

Web UI 把连续尝试折叠为一条稳定状态行，显示倒计时、当前次数与有限上限或 ∞。每个调度事件仍持久保留；失败步骤未完成的流式尾部会被移除，终态失败则留在轮次边界供排查。

重试可能重复计费

每次重试都是新的 Provider 请求，可能再次计费输入 token。模型不会看到失败分片、延迟或 Provider 错误；认证错误的界面文案也不会回显提供方返回的凭据片段。

持久重试提示的状态转换#

相邻尝试的 retry 事件在 Chat 中合并为一条稳定弱化行，并用最新尝试更新；底层运行时快照与 Session 日志仍保留每个事件。后续尝试成功后，这条恢复历史也不会消失。

scheduled

收到 retry 后、匹配的 retry-started 到达前显示计划状态。倒计时从浏览器收到事件的时刻起算，向上取整且至少显示 1 秒，避免 Host 时钟偏差。

started / cancelled

后续 started 事实把提示推进为已开始；若所属 Step 或 Turn 先关闭，则成为已取消。Host running 位只控制实时动画，不改写持久事实。

terminal error

未进入重试的 turn/end 错误生成持久内联节点；尚未定稿但可见的 Assistant 输出会冻结在旁边，而不是被当作完整回答。

AUTH 只脱敏显示副本

可能包含凭据片段的 Provider 文案在界面中统一替换为 API key is invalid，原始诊断仍保留在会话日志供本地排查。刷新、分页与恢复使用同一组 Definition，不会让已移除的失败分片重新出现。

输出达到 max-tokens 时

max-tokens 是独立的轮次结束原因，不等于正常完成、错误或取消。只要本轮任一步骤达到输出上限，即使插件随后继续执行并正常结束，整个轮次仍保留截断标记。

已完成内容块

完整结束的文本或推理块会保留为 Assistant 内容，并继续出现在历史中。

未完成工具调用

截断的参数不能安全执行，因此不会发布 tool/call，也不会产生半个外部副作用。

空回答

仍记录空的 assistant/message 完成锚点和可用的 usage，但空内容不会进入派生模型 transcript。

Web UI 在该轮位置显示持久警告，保留已经生成的可见输出，并建议发送“继续”开启新轮次。事件不携带具体 token 数字，因此提示不会猜测上限；刷新、历史分页和恢复后仍能重建相同状态。

不要把“继续”当成同一次请求

继续是一条新的用户消息和新的 Provider 调用，会使用当前模型配置并产生新的用量。若经常截断，应调整模型或 Agent 的 maxTokens，同时确保不超过提供方实际输出容量。

Agent 动态扩展运行时#

自引用 Cordis 工具让 Agent 先检查活的服务、API、事件和 Client slots，再定义并运行临时动态包。cordis_define 只做语法预检和登记；所有副作用都推迟到显式 cordis_run。

inspect先查询契约把编译期 API 目录与当前活服务取交集，避免凭空猜测接口。
define → run版本化实验Host 半先在 node:vm 中求值；Client 半必须由打开的页面确认并装载。
stop / undefine完全撤销停止会释放 Fiber 贡献；删除还会忘掉全部不可变 Package 版本。

动态包只存在于共享进程内存，不写插件文件、不修改 cordis.yml，也不会跨重启恢复。每个操作按定义它的 Session 校验归属；其他会话读取时表现为不存在。

VM 隔离不是安全边界

Host 半仍可通过获准的 fs、web、bash 等服务影响运行时，应当像授予 Bash 一样慎重。带 Client 半的 run 在无人打开页面时会一直等待，直到调用轮次取消；同步 vm timeout 也不约束逃逸出的异步函数体。

Code Runtime 与结构化绑定#

Code Runtime 是可替换的可选 seam，用宿主提供的异步 bindings 执行模型编写的程序。程序作为 async function body 运行，可使用顶层 await 和 return；打印日志与完成值一起形成已解析的结果。

01Bind

每个 namespace 成为程序全局对象，成员参数与返回值必须是无损 JSON。

→
02Run

后端显式声明 TypeScript 或 Python 语言，以及 worker/process/container 基底。

→
03Resolve

日志、可选完成值和失败分类都通过正常结果返回，而不是拒绝 Promise。

异常、预算超时、调用方 abort、worker 退出、非 JSON 输出和结果超限是彼此独立的失败类型。输出超限会明确失败而非塞入替代文本；停止 runtime 时必须终止并等待全部运行结算。

Isolation 只是诊断标签

worker-thread、process 或 container 描述执行基底，不构成安全承诺。Bindings 仍是程序调用宿主能力的入口，必须只暴露确实授权的函数。

Code Mode 只保留一个模型直连入口#

工具注册表在 code 与 both 模式下都会提供保留的 run_code 传输，并按当前 Runtime 语言生成 TypeScript 或 Python SDK。区别在于 both 同时公开普通工具 Schema，而 code 模式只允许模型直接调用 run_code。

直呼原生工具会提前失败

code 模式下，模型直接调用其他工具名会在执行创建阶段得到 UNKNOWN_TOOL，早于 pre-execute、审批与 Guard；错误会明确提示改从 run_code 程序内部调用。

SDK 子调用携带父级身份

程序中的绑定分派带有外层执行的 parent token，因此不受单入口限制，并重新进入完整工具流水线。成功返回规范 JSON 值，失败则成为只含 toolName 和 message 的 ToolCallError。

中间结果不进入对话

子调用会留下关联的 code-dispatch 事件供 UI 与审计使用，但派生模型历史只接收程序最终打印的日志和返回值。模型需要主动提取并汇总真正有用的信息。

生成 SDK 保持前缀稳定

可见工具按字典序生成精确参数与输出类型；工具集合和 Runtime 语言不变时，SDK 文本逐字节稳定。无法精确呈现的原始 Schema 会降级为 unknown 或 Any，而不会让提示词组装抛错。

程序失败不会回滚已经发生的副作用

运行结算会中止并排空未完成绑定，但已经执行的工具副作用仍然存在。子调用附加上下文会延迟到父级结果之后，即使程序后来失败也保留来源与元数据。

组合包（bundle）贡献一层配置，profile则描述哪些组合包按什么顺序构成一个可启动应用。二者职责不同，不应混为一种 manifest。

Profile 启动后会持续监听 profile 与 home 两个 cordis.patch.yml。即使文件或它的直接父目录尚不存在，监视器也会守住确切路径；随后创建、修改或删除文件都会触发重新组合。

串行重组

失败仍保活

Settings 的三层解析#

用户设置按 namespace 分节，每个生效值依次叠加 Schema 默认值 → 组合层 base → 用户分节。cordis.yml 仍保存部署组合；Settings 只承载允许用户编辑的子集。

3用户覆盖 · update / replace / mutate
2组合层 base · 部署方默认
1Schema defaults · 类型与表单

update 合并稀疏 patch；replace 整体替换并让缺失字段重新继承；持有脱敏视图的 UI 必须使用路径级 mutate，避免覆盖自己从未看到的 secret 字段。每次写入都带 revision，可拒绝过期页面的并发覆盖。

生效时间是产品提示

live owner 观察变更并热应用；restart owner 只在构造时读取。外部编辑无效时，运行中的 namespace 保留最后一个已验证值。

安全更新与并发收敛#

settings.describe 返回 resolved、base 与 user 三层的脱敏快照、secret 槽位状态和原始用户分节的单调 revision。secret 值不搭乘任何响应，只能沿写入请求单向进入 Host。

改一个字段

使用 settings.mutate 的路径级 set / unset，并附带最近的 expectedRevision。

页面已经过期

Host 返回 settings-conflict 和新旧 revision，不覆盖已经提交的写入；客户端重新读取后再让用户决策。

外部或断线变更

客户端在首次读取前先监听更新，并在 settings/document-updated 或连接重置后重新读取；迟到的旧响应不能覆盖较新的发布值。

不要用脱敏结果重建整个分节

网络 descriptor 从未包含 secret 明文；据此调用 replace 会把不可见的 secret 当成缺失并删除。当前脱敏 walker 也不能证明所有 union、intersection 或 transform 内的 secret 都安全，因此暴露到协议的 namespace 只应使用可验证遍历的 schema。

Schema 草稿、覆盖与客户端校验#

settings.describe 把 Host 使用的 schemastery schema 序列化给浏览器，schema-form 再将其重建为活校验器。页面因此能在写入前用与 Service Definition 同源的规则校验整份用户分节草稿。

不可变路径编辑

setPath 物化中间对象；deletePath 删除用户层字段，使解析值重新继承组合 base 与 schema 默认值。

覆盖按存在性判断

字段只要出现在原始用户草稿中就算已覆盖，即使它恰好等于默认值；这与 Settings 的分层语义一致。

无法解析就降级

nodeAtPath 只沿 object 属性和 dict inner 探测节点；找不到路径时返回 undefined，功能表单必须进入明确的降级路径。

当前没有通用 React 表单生成器，各功能围绕草稿辅助函数手写控件。校验返回整份草稿的第一条失败消息及 $.path，不会自动把多项错误分发到每个字段。

序列化 Schema 是可执行信封

schemastery 重建回调时会执行动态函数，因此只能接受提供当前页面的同一受信任 Host 所发送的 schema。secret 控件仍必须保持只写：初始为空，只展示是否已配置，空草稿不能清除已有密钥。

设置文件的热重载与最后可用快照#

settings-file 用一份 YAML 或 JSON 文档承载所有 namespace。启动时存在但非法的文档会让插件明确失败；运行期外部编辑若不可读、不可解析或无法通过某个 namespace 校验，则告警并保留对应的最后可用值，不拖垮进程。

写前重新读取

每次 persist 都在锁内先读取最新磁盘文本并发布差异，再基于它渲染，因此能并入 watcher 防抖窗口、漏报事件和其他进程写入。

YAML 叶子级修改

只改动变化的 map 叶子，保留未触碰节点的注释、锚点与排版；数组和其他非 map 值整体替换，JSON 则整体重新序列化。

同一操作队列

watcher 刷新与各 namespace 写入逐个执行；ready 时再对账一次启动竞态，内容等于最后文本的自写事件直接抑制。

删除设置文件会发布空用户文档，让所有 namespace 回退到 base 与 schema 默认值。卸载会先关闭 watcher，再等待已排队和进行中的文档操作完全停稳，此后不再发布。

Watcher 不是持续轮询

读取路径不会自行重复 stat；若底层 watcher 真正漏掉事件，外部变更要到下一次文件信号、下一次写入或重启时才会被并入。磁盘已经非法时，产品写入会拒绝，而不是覆盖用户尚未修复的文本。

Web UI 的中文／英文偏好由 LocaleRuntime 管理。Host 值保存在 $DSH_HOME/settings.yaml 的 locale.preference；插件激活后异步读取并替换浏览器的暂定选择，因此 Settings 暂时不可用也不会阻塞页面。

navigator首次浏览器提示没有显式 Host 值时按主子语言标签匹配；应用不支持浏览器请求的语言时回退到 zh。
remote仅进程内选择Settings API 仅允许回环请求，因此远程浏览器可以切换当前运行期语言，但不能把选择写入 Host 文件。

依次查当前 namespace 的活跃语言与 zh，再查 common 的活跃语言与 zh，最后显示原始 key。

不是所有界面与已注册文案都会实时切换

上游双语文档如何保持成对#

DeepSeek Harness 把英文与简体中文视为同权文档：每一对由同目录的 foo.md、foo.zh.md 和 foo.i18n.yaml 组成，必须在同一个变更中一起对齐，而不是把某一侧当作永远优先的真源。

内容快照

i18n 记录保存两侧最后一次确认一致时的完整 Git blob hash，可精确恢复并只修补发生变化的部分。

结构门禁

CI 检查配对完整性、语言切换行、标题、列表、表格、链接和逐字节一致的代码块；任一侧单独变化都会失去同步。

语义评审

hash 和结构相同只能证明有人确认过当前配对，不能证明翻译忠实、术语准确或行文自然，这些仍由双语评审负责。

运行时 Locale 与文档配对是两条独立链路

前者决定浏览器界面当前显示什么语言，后者保护仓库 Markdown 的长期一致性。二者都支持中英文，但没有共享存储、事件或模型上下文。

凭据引用与热轮换#

配置文件只保存形如环境变量名的 CredentialRef，明文由 Credentials provider 管理。LLM Adapter 在每次请求前重新解析引用，不跨操作缓存，因此轮换后的密钥会在下一次请求生效，无需重启。

resolve

只向受信任消费方返回非空值及来源层；空字符串始终视为未配置。

describe

UI 只看到 configured、source 与 writable，永远拿不到凭据值。

set / unset

只修改 provider 管理的可写层；被只读环境变量遮蔽时明确拒绝。

不要把 Secret 放进 Settings

Secret schema 字段在所有网络 descriptor 中都必须脱敏。模型配置引用凭据名，而不是复制 API Key。

本地凭据文档的权限与信任边界#

本地 provider 把受管值保存为 $DSH_HOME/.credentials.yaml 中从引用名到字符串的纯 YAML mapping。非 mapping 根、非法 POSIX 名称、非字符串、空值、重复键或语法错误都会整体拒绝，不会静默跳过坏条目。

仅属主权限

目录以 0700 创建，文档以 0600 原子提交。POSIX 上发现任何 group/other 权限位都会在解析内容前失败，并提示 chmod 600。

补丁式写回

写入在锁内重读并修改已解析文档，保留未触及条目的格式和注释；删除条目也会删除紧邻其上方、属于该条目的注释。

整体热替换

外部编辑成功后先替换完整快照，再逐引用发布 credentials/updated；删除的磁盘条目不会残留在内存。

运行期文档非法或不可读时告警并保留最后可用快照，文件不存在则视为空存储；启动期同样的问题会明确失败。Windows 无可用 POSIX mode 检查，因此跳过权限位验证，而不是伪造安全结论。

0600 挡不住同 UID 的 Agent

bash 与文件工具以同一 OS 用户运行，workspace-write 主要限制修改而非所有读取；现有沙箱不会特别隔离这份文档。Harness 只是不把解析路径告诉模型、也不把受管密钥放进进程环境。这是审慎设计，不是强隔离；需要阻止 Agent 读取提供方密钥时，应使用进程外钥匙串或 KMS 类 provider。

getFrom 可以拒绝某些来源层，但不能改变剩余层的可信顺序。变量名按平台规则匹配：POSIX 区分大小写，Windows 不区分大小写，避免同名变量因拼写大小写而错误越级。

文件系统目标、观测与原子写入#

文件系统能力把服务定义、后端、观测策略和模型工具拆开。路径先解析为带显示路径的不透明目标；消费者不得解析 target key，也不能假设它一定是本地绝对路径。

Observed present

读取记录后端版本；后续写入或编辑只在版本仍匹配时原子提交。

Observed absent

确认不存在只授权 create-if-absent，不会授权对缺失文件执行 edit。

Never observed

默认策略拒绝盲目编辑，防止覆盖 Agent 尚未读取的外部变化。

编辑不是“先读再写”的外部组合：版本检查、字面匹配、换行规范化和原子替换都在同一个后端临界区完成。窗口化读取即使只返回部分行，也会记录完整文件版本；过大的原始字节读取则明确失败，不会静默截断。

符号链接需要单独看待

整体和流式读取都拒绝非法 UTF-8、含 NUL 的二进制样本及非普通文件；超大文件可分片解码，由调用方限制保留窗口。

字面编辑

原子发布不等于跨进程串行

每目标变更锁只在当前进程内有效。其他进程的替换只有在元数据版本变化时才会被守卫发现；若文件系统重写后没有更新任何版本组成字段，陈旧检查仍可能漏过。

文件 I/O 没有伪造的超时保证

read、write 与 edit 只在系统调用边界尽力响应取消，不公开 timeoutMs；进行中的 fsync 或 rename 不能被 JavaScript deadline 强行停止。

观察记录属于当前 Session 生命周期#

Observation Policy 不提供服务，也不执行文件 I/O；它监听 fs/observed，并在单槽 write-intent 与 edit-intent 事件上把每个 Session 对目标的未见、确认缺失或版本存在状态转换为提供方 CAS 守卫。

未见时写与编辑不同

write 会尝试 createIfAbsent，若文件其实存在则以 FS_NOT_OBSERVED 失败；edit 直接要求先读。确认缺失后仍可安全创建，但 edit 返回 FS_NOT_FOUND。

观察不会跨恢复保留

状态以 Session 对象为 WeakMap 键，只驻留当前进程；插件重载、Session 恢复或新 Activation 都必须重新读取，旧日志中的 read 结果不会自动恢复新鲜度授权。

只有工具读取发布观察

直接调用 ctx.fs 读取不会触发 fs/observed，因此不能授权后续受保护编辑。成功的模型 read、write 或 edit 才会更新当前目标状态。

这是单槽决策，不是授权链

write-intent 与 edit-intent 按注册顺序由第一个决策器完整裁决，默认策略不会调用 next。权限、审计与沙箱仍应放在工具执行流水线或后端，而不是叠加到这个槽位。

策略插件可选，但移除会改变安全姿态

工具依赖的是 ctx.fs 提供方而非策略服务，所以卸载策略不会让工具失效；它会让 write 回到无条件创建或覆盖、edit 回到无条件字面替换。部署应显式加载默认观察策略。

Glob、Grep 与结果预算#

文件发现工具使用 npm 随包交付的 ripgrep 二进制，并通过 Subprocess seam 以固定 argv 启动；不依赖宿主预装 rg，也不经过 shell。启动时强制 no-config，避免继承的 RIPGREP_CONFIG_PATH 注入预处理器。

glob

查找文件路径并包含 hidden/ignored 文件；不含斜杠的 pattern 会匹配任意深度 basename。

grep

按 rg JSON 解析正则匹配并按文件分组，避免依赖冒号拆分。

spill

内联页面达到路径、匹配或行字节上限时，尽力保存完整格式化结果。

原始 stdout 超过传输预算会以 SEARCH_RAW_OUTPUT_OVERFLOW 失败并要求缩小查询；退出码 1 只是成功的空结果。搜索进程的 cwd 必须与文件系统工作区共置，否则返回路径无法保证能被 read 继续读取。

Shell 与持久 Terminal#

两者都能运行命令，但生命周期不同。默认使用 Shell 完成有边界的一次性操作；只有任务需要交互式 stdin、REPL、开发服务器或持续终端状态时，才打开 PTY Terminal。

Shell foreground

等待命令结束，分别报告退出码、信号、超时与调用方取消；非零退出是正常结果，不是基础设施异常。

Shell background

立即转成通用 job；没有执行器超时，通过增量游标读取输出，并可请求终止整个进程组。

PTY Terminal

保留 shell 状态和 scrollback，支持发送输入、分页读取、信号、列出与显式关闭。

返回不代表命令退出

terminal_send 因 inferred_idle 或 timeout 返回时，顶层 PTY 仍可能运行。应检查 session status，并在不再需要时调用 terminal_close。

Harness 会清除子进程环境中的凭据及继承的 DSH_* 名称，再合并本次受管环境快照。输出超过内存预算时只内联尾部，并用私有 spill 文件保留完整流的恢复信息。

一次性 Bash、持久 Bash 与 PowerShell#

bash-localPOSIX 一次性进程每次启动新的非登录 bash -c，不读取 rc，也不保留 cd、export 或函数；前台有超时，后台转交 Jobs 且不设执行器超时。
bash-persistent每 Agent 复用 PTYcwd、环境、激活环境、函数和 shell 后台任务跨调用保留；适合连续命令，但显式 exit、取消或超时都会丢弃整个 shell 状态。
pwsh-localPowerShell 一次性进程每次以 NoLogo、NoProfile、NonInteractive 启动；命令必须使用 PowerShell 方言与原生路径，不经过中间 shell 翻译。

持久 Bash 不是后台 Job 的替代品

一次性 Bash 的 run_in_background 会把独立进程句柄交给通用 Jobs；持久 Bash 则只让 shell 自己保留后台任务状态，不提供 Job 所有权、完成通知或独立收集接口。长期服务应选择受管 Job。

PTY 会话如何就绪、取消与关闭#

Terminal seam 为每个成功打开的终端签发不透明 id，但权限主体是发起操作的确切 Agent。即使另一个 Agent 获知 id，也不能读取、发送信号或关闭该终端；Agent 或服务销毁时必须等待后端进程树和未发布的 spawn 完全停稳。

01Open

02Send

同一会话最多一个活跃 send。Provider 结合私有提示符、前台 stdin 等待、静默回退和绝对超时判断何时返回。

→
03Close

关闭停止新信号和就绪轮询，等待完整会话终止，再把活跃 send 结算为 session_exit；失败不会假装已经清理完成。

等待原因不是进程状态

inferred_idle 只表示观察到就绪证据，timeout 只表示等待预算耗尽；两者都不能证明顶层 PTY 或前台命令已经退出。

取消发送真实 SIGINT

系统先取消排队输入，再向当前前台进程组发信号，不用写入字节 0x03 模拟 Ctrl-C；后续 send 等它完全结算，避免收到迟到字节。

后台发送仍有独占席位

terminal_send 的后台模式会在返回 Job id 前同时预留 Job 和该终端的唯一 send；job_kill 向前台进程组发送 SIGINT。

打开终端后不能偷偷切换有效沙箱模式

同一 Owner 存在开放 PTY 或正在 spawn 时，若配置变更会产生不同的实际模式，sandbox/mode 事件会在提交前被拒绝。先关闭终端再切换权限，防止旧进程继续持有更宽访问。

Terminal 是进程本地、逐行的能力

Harness 重启后不会恢复会话，也不支持全屏备用缓冲区 TUI、调整大小或跨 Agent 共享。输出只有在工具返回有界 MOTD、增量或 scrollback 页时才进入模型历史。

子进程、流与进程树终止#

Subprocess seam 为 Bash、LSP、PTY 和 ACP 提供同一个底层进程世界。Spawn spec 没有隐藏默认值：argv、cwd、三条 stdio、环境、宽限期和取消信号都由调用方明确给出，argv 永远不经过 shell 解释。

pipe协议流把原始 Readable/Writable 交给 LSP JSON-RPC 或 ACP ndjson 等协议消费者。
inherit直接诊断子进程输出直接进入 Harness 自己的描述符。
collect有界收集内存只保留尾部，可选 spill 保存有上限的完整流。

收集读取使用全流字节 offset，多个读取者不会抢走彼此的数据。终止以整棵进程树为范围：POSIX 先发 SIGTERM，等待 grace period 后升级 SIGKILL；Windows 使用 tree termination。最终 outcome 只报告退出码和信号，超时或取消原因由拥有 deadline 的调用方分类。

普通 spawn

POSIX 使用 detached 进程组执行 TERM → grace → KILL；Windows 调用 taskkill /T /F。退出后的管道排空也受 grace 限制，后代持有描述符不能无限拖住结果。

PTY spawn

同步 Host exit

Node exit 回调会对仍活跃目标做无 Promise、无计时器的强制清理，但只能覆盖仍能执行 JavaScript 的退出路径。

完整输出 Spill 也有完整性门槛

文件位于权限 0700 的每进程临时目录，随机文件本身为 0600。若某条流超过 spill 上限，Provider 会丢弃已经不完整的文件，只返回截断尾部；已完成的 spill 不会自动删除。

环境清理不是秘密泄露防线

规则只匹配变量名，PASSPHRASE 等未命名模式仍会继承；显式 env 还可以有意重新加入凭据。SIGKILL、native crash、断电等无法运行 JavaScript 的故障也必须由 supervisor、容器 init 或操作系统负责清理。

Windows 进程树终止是尽力而为

taskkill 的缺失、竞态或目标已消失都会被吸收，存活探测退回直接子进程边界。Terminal 精确成员检查仅支持 Linux 与 macOS；setsid 或过早脱离父链的守护进程仍可能逃出可观察范围。

LSP 精确代码导航#

文本搜索适合普通浏览；当同名符号含义不清，或修改前必须确认精确定义、实现和引用时，使用只读 lsp 工具。它只公开四种闭合操作：

goToDefinition跳转定义

定位当前符号的定义位置。

findReferences查找引用

返回引用并始终包含声明本身。

goToImplementation查找实现

从接口或抽象符号定位实现。

hover类型信息

读取语言服务器给出的 Markdown 或纯文本说明。

模型输入使用从 1 开始的 UTF-16 行列坐标；没有对准符号可能得到空结果。Provider 按文件扩展名确定性选择，没有匹配项时返回 LSP_UNAVAILABLE。LSP 是可选能力，不属于 Agent loop 主干。

临时打开文档，复用 Workspace Server#

stdio Provider 按 Server id 与规范 Workspace 目标惰性 single-flight 一个语言服务器进程。每次查询独立按扩展名选路；Provider 注册会原子预留 id 与全部扩展名，任何冲突都不会留下部分路由。

每次查询读取当前文件

轮到请求执行时才从 ctx.fs 流式读取源码，发送版本 1 的完整 didOpen，完成语义查询，并在 finally 中 didClose。第一版因此不需要 didChange、内容缓存或文档 LRU。

同 Workspace 串行，不同 Workspace 并行

逐 Workspace 可取消队列覆盖读取、打开、查询和关闭完整生命周期，防止共享文档状态交错。工具默认 60 秒的预算也覆盖排队时间，而不只是协议请求。

传输故障最多重试一次

若池化进程在只读查询前或期间损坏，Provider 等待旧实例完全 dispose，再用新进程重试一次；语言服务器正常返回的错误不会触发重试。

查询源必须位于规范 Workspace 内

Provider 在打开前拒绝缺失、非普通文件、非 UTF-8、超大或位于 Workspace 外的源文件。结果位置可以指向外部；相对化时使用 Provider 返回的 resolvedWorkspaceUri，而不是猜测宿主路径。

LSP 既不授权编辑，也不提供沙箱

LSP 读取不会发出 fs/observed，因此不能满足先读后写策略；客户端也拒绝 workspace/applyEdit。配置的语言服务器仍是受信任进程，隔离必须由同一执行世界的文件系统与 Subprocess Provider 提供。

已接纳命令写入配对的 command/run 与 command/done 日志事件。

语法错误或未知命令不会写日志。Agent scope 中的同名定义会遮蔽全局命令；插件卸载时注册自动撤销。

输入触发器与模糊发现#

浏览器的 ui-input-trigger 在光标处按词边界和 guard tier 检测 /、@ 等触发器，再把分组候选与 pick 回调路由到注册 source。前置加号也复用同一控制器，只以合成 selection 打开 command source，不建立第二套菜单。

候选竞争

source 按 order 和注册顺序分组；新查询会取消旧请求并以 generation 阻止迟到结果覆盖当前菜单，单个 source 失败只记录诊断。

键盘裁决

空格与 Enter 按注册顺序询问 source，第一个明确应答胜出。命令菜单支持不区分大小写的子序列模糊排序，但真正提交仍要求精确命令名。

可访问焦点

菜单采用 combobox 模式，焦点留在 textarea，高亮通过 aria-activedescendant 表达；指针选择在 mousedown 完成，避免失焦竞态。

只属于浏览器呈现层

触发检测、菜单、launcher 和 notice 本身不进入会话日志，也不增加模型 token。只有 pick 之后执行的 Host 命令或插入到普通提示词中的引用文本，才产生各自领域的后续效果。

Codex 与 Claude Code Hooks#

Hooks 桥接器把现有 Codex 或 Claude Code command hook 配置映射到 Harness 的类型化拦截点。它们是兼容层；需要完整类型、更多控制或稳定扩展时，应直接编写 Cordis 插件。

SessionStart注入上下文

会话开始时运行；当前实现是脱离执行，可能错过首个请求。

UserPromptSubmit提示词门禁

可以拒绝输入，或给已接受输入追加带来源的上下文。

PreToolUse工具前决策

Codex 子集支持阻塞；Claude Code 子集还可返回 ask。

PostToolUse / Stop反馈与续行

工具后可阻塞或追加反馈；Stop 阻塞会 steer 下一步。

不是完整协议复刻

桥接器只运行同步 command hook，且各自只支持官方协议的一个子集。配置在进程加载时读取一次；不支持的事件或字段不会自动获得原产品语义。

退出状态、结果合并与审计日志#

共享 Hook Protocol 是两个桥接器复用的库，不是 Cordis 插件。桥接器负责方言 payload 与 Decision 映射；共享层负责 matcher、stdin 执行、输出解码、最严格合并、会话记账和脱离任务排空。

只有退出码 2 默认阻塞

exit 2 使用 stderr 作为阻塞原因；其他非零退出和执行器基础设施故障不会阻塞 Agent。runHook 把故障规范成结果而不抛出，并转发取消信号与单 Hook 超时。

多个结果按最严格者合并

权限优先级固定为 deny、ask、allow；continue:false 一旦出现就保持停止。阻塞原因以空行连接，additionalContext 与 systemMessages 按配置顺序累积。

方言匹配规则并不相同

Codex matcher 始终是未锚定正则；Claude Code 对纯字母数字、下划线和竖线模式使用字面交替，其他模式才作为正则。无效表达式在配置阶段隔离。

Hook 调用有成对审计事件

轮次内调用追加 hook/invoked 与 hook/result，并按 handler id 配对；它们只进入日志，不改变模型表层。stderr 摘要按配置截断，空值省略。SessionStart 位于首轮之前，因此不写这对事件。

脱离执行也必须完全停稳

SessionStart 和部分 Subagent Hook 不会阻塞对应扩展点，但桥接器跟踪完整运行链。插件 dispose 会先发出 abort，再等待 Hook 进程与 continuation 全部结算，避免已卸载上下文继续产生副作用。

Session 内定时提醒#

schedule_create 支持延时一次、绝对时间一次和固定速率重复三种规则。记录持久在原 Session 中，到期后排队一个普通 follow-up；不会发送外部通知，也不会唤醒 cold Session。

after_seconds延时一次接受正整数秒数，创建时换算为 UTC 目标。
at绝对时间必须显式提供 RFC 3339 偏移量或 IANA 时区。
every_seconds固定速率至少 300 秒；跳过的周期只补发最新一次。

提醒只在拥有它的 Agent live 且完全 idle 时交付，从不打断当前轮次。一次性提醒优先；多个到期的重复提醒会合并进同一个 follow-up。交付是尽力而为的至少一次，不是恰好一次。

从持久规则到普通后续轮次#

schedule/change 是提醒状态的唯一权威：create 保存完整记录，delete 与一次性 dispatch 终结 id，重复 dispatch 则携带统一判断时刻并推进下一个目标。Timer、列表状态和 follow-up 都是可重建投影。

重复提醒不回放积压

Every 规则始终与创建时刻锚定。Session 忙碌或 cold 时错过多个周期，只选择最新一次已到期 occurrence，并直接推进到第一个未来目标；多条逾期规则合并成一轮。

Fork 保留历史但不接管任务

普通 Session 回放完整 Schedule 日志；fork 只折叠 seed 边界之后的新变更，因此可看到父级历史，却不会继承父 Session 仍活动的提醒。

Dispatch 不是完成回执

它只证明稳定 framing 已同步进入 follow-up 队列并记录，不证明模型成功回答或用户已经阅读。页面也没有独立提醒回执或外部通知渠道。

每次管理操作先确认持久状态

list、create、delete 与到期判断都先越过共享 Session flush 屏障；成功创建或实际删除后再刷盘确认。无法确认时返回 persistence_uncertain，不猜测内存尾部是否已经耐久。

至少一次意味着可能重复

follow-up 获准入队后、dispatch 检查点完成前若崩溃，恢复可能再次发送同一提醒。绝对本地时间还必须显式提供时区：夏令时缺口会拒绝，重叠时选择较早一次。

插件只为加载后新建的 live 根 Agent 安装工具，不会扫描已经存在的 Agent，也不给运行时子 Agent 安装。插件卸载会停止新工作并排空进行中的预检，但不会删除持久提醒。

Workflow 与 Ralph#

workflow 让模型编写 JavaScript 编排脚本，按阶段启动多个 Subagent 并返回结构化 JSON。它适合用户明确要求的大型多 Agent 编排；一两个委派仍应使用普通 Subagent。

Dynamic Workflow

脚本可使用并行与流水线组合器扇出任务；父级同步等待，并在所有路径上清理 worker 与 child。

Ralph

固定前台循环，每轮启动一个没有对话 seed 的全新 Agent，以共享工作区和有界报告交接状态。

Goal

同一 Agent、同一 Session 内跨轮持续推进，适合普通长期目标，不等同于 Ralph。

完成声明仍需验证

Ralph 的 complete 或 blocked 来自 worker 报告，没有独立评估器。普通 child 失败会终止运行而不会自动重试；取消后局部输出也不会伪装成成功。

结果结算之后还要等待完全停稳#

Workflow 启动前会把 meta 与 args 当作普通 JSON 数据校验，不通过执行脚本文本来获取身份。每个 agent 调用都归属于必填 parent，并沿 Subagent seam 继承 cwd、谱系和深度。

Result 永远兑现而不 reject

脚本完成、取消和错误都解析为封闭 stopReason；只有 completed 的 value 可当作成功。消费工具把其他终态映射为 isError，绝不把局部返回值包装成成功。

Fatal 错误不能被组合器吞掉

无效 agent 选项、Schema、上限、启动失败或取消会产生 fatal WorkflowError，parallel 与 pipeline 必须重新抛出。只有普通 child 失败或阶段内脚本错误可成为逐项 null。

Dispose 拥有最终清理责任

消费方在 finally 中调用 dispose：必要时取消脚本，在有界宽限期后强制结算，并等待 worker 与所有 child 完全停稳，因此卡死脚本不会让父级永久挂起。

Chat 记录只投影顶层运行

根调用写 run-start 和配对的成员事件；只有取得 result 且 dispose 完成后才写 run-end。嵌套 transport 不写记录，append 失败则停止后续记账，留下空日志或合法连续前缀。

Ralph 的长期记忆只在工作区与有界交接

每轮是无父对话 seed 的全新 Agent，上一份结构化报告必须满足状态语义与字符上限，否则整次运行失败而非截断。Round 上限控制数量，不限制 token、费用或墙钟时间。

Token 计量#

Token Meter 回放当前会话的耐久日志，生成一次不可变的请求压力与 surface 定价快照。它区分完整请求/响应压力 totalTokens 和仅当前模型表层的启发式总量 surfaceTokens。

usage baseline

最近成功请求具有相同规范 envelope，且 Provider usage 足够覆盖启发式锚点。

estimated baseline

没有可安全复用的 usage 时，用固定启发式重新估算完整 envelope 与 surface。

surface delta

相对匹配基线的有符号变化，可同时表示上下文增长与压缩后的缩减。

每个 surface node 记录事件 seq 和估算 token，但数组顺序才是模型表层的权威顺序；压缩替换节点的 seq 可能比排在它后面的旧节点更大。

会话统计条与逐轮耗时#

Chat 统计条把两类权威组合在一起：token 账目读取通用 tokenUsage 投影；轮次、步骤、LLM 与工具墙钟时间、平均 TTFT 和解码吞吐读取 Host 从全日志计算的 sessionStats。计费输入是未缓存输入、cache read 与 cache write 之和。

全日志统计不随分页变化

完整 sessionStats 独立于浏览器已加载窗口，因此加载更早历史或压缩移除可见 Assistant 节点，都不会改写总轮次、耗时和 token 分组。

缺失样本不参与平均

缺少 timing 边界或 usage 的步骤从 TTFT 与吞吐计算中退出；界面不会用零值或猜测填补并拉低平均数。

逐轮 footer 只依赖窗口事实

已结算轮次可在“用时”后显示首步骤 TTFT 与轮次聚合 tok/s，但只有该轮 timing 位于连续加载窗口内时才呈现，缺少的数字各自省略。

统计条过长时会省略，但只有内容真的被裁切，悬浮 tooltip 才承载完整文本；没有组合 token-meter 的部署会整组隐藏 token 分组，而不是显示零。

窗口回退不是全会话统计

未组合 sessionStats 的应用只能从可见 Assistant timing 与工具 call/result 配对折算。更早未加载节点不计入，所以数字会随历史页加载而增长；不能把这条兼容回退当成持久总量。

如何解读 Context Meter

输入框旁的占用圆环只在“预计下次请求 token”和当前模型容量都已知时出现。标题使用 projectedTokens：从最近一次 Provider 输入用量出发，再按此后 surface 的新增、替换或压缩做启发式增减。

pressureTokens

最近一次已完成请求的输入压力，等于未缓存输入、cache read 与 cache write 之和；流式输出期间不会变化。

projectedTokens

预计下一次提示词规模。压缩一落地就会下降，无需等待新一轮 Provider usage。

contextBreakdown

按系统提示词、工具和消息给出约略组成，固定使用“4 字符约 1 token”加结构开销。

百分比不是账单，也不是准入闸门

预计 token、模型容量和组成明细来自独立的后写覆盖投影，并非同一次请求的原子快照。CJK 文本和大型 JSON Schema 可能被明显低估，明细相加也不保证等于标题数字。

统计栏的计费输入为未缓存输入、cache read 和 cache write 三项之和，缓存命中率用 cache read 除以该总量；reasoning token 已包含在输出中，不能重复相加。缺少完整 timing 或 usage 的步骤会从 TTFT 和吞吐计算中退出，而不是用猜测值补齐。

Trajectory 调试视图#

Trajectory 把用户、助手、工具与嵌套子工具事件按轮次排成可检查的执行轨迹。选择一行可查看 token、耗时、输入、输出与计时；独立压缩显示在轮次之间，带编号的压缩仍留在所属轮次。

长历史按需加载

拖选闭区间会筛出与它重叠的记录；滚轮缩放，放大后右键拖动平移。助手条分别呈现已记录的 TTFT 与解码时间。

流式跟随尊重阅读

初始状态与流式更新停在尾部；用户向上滚动后暂停跟随，新事件不会抢走旧记录的检查位置。

Trajectory 与 Chat 各自投影

Trajectory 从共享 Session 原始事件组装自己的记录，也保留因取消而冻结的助手与工具步骤；它不读取或修改 Chat 会话快照。搜索、折叠、选择与请求汇总只覆盖当前已经加载的窗口。

进行中不虚构耗时

部分响应和运行中的工具只显示开始标记与运行状态，完成前不会绘制假定时长。时间线与记录选择也只存在于当前页面，不提供可分享的锚点深链接。

如何解读遥测的交接与送达#

Harness 的职责止于把逻辑记录非阻塞地交给后端 SDK。协调器不能用本地游标证明远端已经接收，也不拥有 SDK 的批处理、重试、排队与丢弃策略。

序号缺口可能是设计结果

每个 turn 与 step 组合只捕获第一条 assistant/chunk，作为流已开始的信号；后续内容分片主动丢弃，因此 ledger 的 event seq 不连续不等于传输丢包。

共享状态只是策略披露

后端披露 full、feedback-only 或 disabled，供反馈确认界面说明当前部署策略；它不承诺某条记录已经送达或会被保留。

关闭会等待 SDK 静止

销毁前先捕获 shutdown 信号，再等待后端排空已入队记录；shutdown 拒绝只记为警告，不会让应用退出失败。

Ledger 与 Ops 的去重方式不同

Ledger 可用 session id 与 event seq 组成的身份去重；agent-error 和 shutdown 属于告警信号，刻意没有 event seq，接收端应容忍重复而不是把它们累计成审计条目。

每个 Harness Home 的匿名身份#

Harness 会为每个 DSH_HOME 生成随机 UUID v4，供 Session telemetry、直接反馈确认和 DeepSeek Provider 请求共同关联。它保存在 .anonymous-user-id，不从 hostname、网络地址、Git remote 或其他身份材料派生。

Per home

不同 Harness Home 拥有不同身份，不提供跨 Home 关联。

Best effort

Home 不可写时仍返回仅进程内 UUID，不阻断模型请求或反馈。

Resettable

删除身份文件后，下次启动会生成新值，旧身份无法恢复。

关闭遥测不等于关闭该标头

DSH_TELEMETRY_DISABLED 只停止遥测导出，不禁止反馈确认或 DeepSeek 请求中的 x-deepseek-harness-user-id。配置自定义 DeepSeek gateway 时，该 gateway 也会收到此值。

运行时 Invariants#

Invariant Registry 让每个包注册自己拥有的运行时约束，例如事件必须成对、状态转换必须合法。检查断言权威事件流或可变数据关系，而不是简单确认某个服务或方法存在。

失败可归因到包

违规会抛出稳定 code 为 INVARIANT 的错误，并携带完整 npm package name。每个 installer 在独立 child fiber 中运行，卸载后不会遗留监听器或 trace 状态。

部署可以用 allowlist 和 blocklist 正则选择检查范围，blocklist 优先。模式在服务启动时严格校验并在生命周期内固定，确保后续插件加载与 HMR 行为确定。

Invariant 注册为什么是原子的#

每个完整 npm 包名在同一注册表中只能有一个活跃贡献。注册表拥有 installer 的子 fiber，配套插件同时持有 effect disposer；任一侧卸载都会清理监听器、trace 状态与名称保留。

被过滤仍保留名称

即使 enabled、allowlist 或 blocklist 让检查不运行，包名仍被占用，两个插件不能悄然认领同一归属。

异步安装必须先结算

installer 可声明所需服务并执行同步或异步检查；只有它成功完成后，注册才成立。

失败释放全部状态

安装阶段抛错会原子销毁子 fiber 并释放名称，因此修复后的插件可以重新加载，而不会撞上残留注册。

过滤项是正则源码，不是斜杠字面量

模式区分大小写，默认不锚定；需要精确匹配时自行加入起止锚点。配置不会解析 /pattern/flags 写法，空白、重复、无效或首尾带空格的条目会让服务启动失败。

每条已完成 Assistant 消息可以保存好评或差评及可选备注。它是本地 Storage Domain 中的可编辑 sidecar，不是 Session 事件、模型上下文或自动遥测。

每次更新携带 opaque version；冲突直接返回权威当前值供 UI 对账。

生命周期隔离

Sidecar 绑定 Session 的 createdAt 与 cwd；Fork 不复制父会话反馈。

Web UI 首次 hover 或 focus 时才延迟读取整段会话的反馈，避免对每条消息单独请求。删除不存在的反馈是幂等成功；备注按 UTF-8 字节限制。

消息反馈为什么不是上传动作#

点赞、点踩和备注只修改 message_feedback Storage Domain 中的本地伴随记录；它不会追加 Session 事件、进入模型上下文或触发遥测交接。不可变的 Session 级 feedback/record 是另一项约定，不能与这里的可编辑记录混为一谈。

先提交目标，再写伴随记录

对 live Session 写入前先执行 flush checkpoint，随后从序列零物理复读日志并再次验证目标，确保被评价的消息先于 sidecar 耐久存在。

Web 暴露范围更窄

Host 可接受每条合格的 append-origin 助手消息；当前控件只出现在 Conversation 中已定稿 Turn 的收尾助手正文，Trajectory 与 waterfall 视图不显示它。

并发保证止于单个 Host

每个 Session 的操作在当前进程内串行，但 Storage Domain 没有跨进程条件写；多个 Host 共用同一存储根时不保证 compare-and-swap 或防止丢失更新。

其他标签页不会立即同步

Sidecar 不发布实时帧。另一标签页要等到重连，或下一次写入收到 version-conflict 并用权威值对账后，才会看到新评分。

08
持续执行委派、计划与长上下文

Subagent 委派#

Subagent seam 让父 Agent 通过具名 Provider 委派工作。Provider 可以在同一进程、独立进程、ACP、Codex 或 Claude Code 中运行，但父级看到的启动与结果约定保持一致。

Foreground前台一次性

父级等待最终结果，返回前总会释放子级运行资源。

Background task后台一次性

立即返回 job id，之后通过通用 Task 接口收集或取消。

Continuable可继续子级

拥有持久 Session，可接收后续消息并在需要时冷恢复。

同级委派可以并发执行，结果仍按模型调用顺序提交。子级继承父级显式沙箱覆盖，但审批策略固定为 never，避免无人处理的提权请求。

进程外 Subagent Provider 如何选择#

ACP、DSH SDK、Codex 与 Claude Code Provider 都为每次运行创建隔离的子进程活动。它们只接收独立任务和父会话的绝对 cwd，不继承父对话；也不声明 persona、tool filter、depth limit 或 output schema 等启动期能力，要求这些能力的请求会被本地 seam 明确拒绝。

ACP跨产品互操作驱动任意兼容 ACP Agent，收集已提交 agent_message_chunk；权限按配置自动允许或拒绝，并映射协议 stop reason。
DSH SDK完整 Harness 子运行时启动由 cordis.yml 组合的对等 Harness，从 Session 事件选择最终文本，并用最后一个持久 turn/end 映射结果。
Codex临时线程与单轮通过 app-server 等待 turn/completed，只接受 final_answer 或兼容回退文本；无人值守审批默认不予批准。
Claude Code一次性 SDK Query只接受正常结束且非错误的 success result；读取 cwd 下的原生用户、项目和本地设置，交互请求不会转交 Harness UI。
发布前必须完成握手

Provider 只有在子进程、协议初始化和远端会话或线程就绪后才交出 Run。此前失败或取消会先回收全部已取得的资源，再拒绝 start。

父级只得到最终投影

推理、工具活动、中间消息、stderr、用量和工作区差异不会复制进父 Session。DSH 子运行时的完整 transcript 也只留在自己的持久化根。

清理与结果彼此独立

dispose 幂等地发出协议取消或关闭，再通过 EOF、平台终止和强杀等待整棵进程树退出；结果失败与清理失败分别报告。

凭据必须显式跨进程

子环境先清除疑似凭据和继承的 DSH_* 名称，再合并 Provider 的 env。Codex 与 Claude Code 仍使用宿主安装、账户和原生设置；插件不会安装 CLI、登录、选择模型或隔离这些设置。

取消不回滚已经发生的副作用

每次运行都可能在共享 cwd 修改文件或访问外部系统。取消只争取成为结果竞态的 aborted 并确保进程停止，不会撤销已经完成的写入；这些 Provider 也没有内建墙钟超时或进程池。

可继续 Subagent 的 Activation 生命周期#

可继续子级的持久 Session 是身份与历史；Activation 则是该 Session 当前驻留在进程内的一段运行期。同一 Session 至多有一个 Activation，但它可以执行多个 FIFO 轮次，并在自己的后代仍运行时继续驻留。

Running：在原 Activation 入队

子级正在准入、执行轮次或唤醒 Inbox 时，followup 进入同一个 FIFO，不会修改已经进行中的轮次。

Waiting：唤醒原 Activation

子级自身已停稳但仍拥有未释放后代时，followup 唤醒现有 Activation，而不是创建第二个运行化身。

Cold：恢复新 Activation

没有在线 Activation 时，管理器从持久描述符恢复一个新实例。消息一旦被 Inbox 接受，调用方后续取消不会撤回该轮次或销毁子级。

父级等待子级优先释放

只要 ownedChildren 非空，受管理父级就不能 settle。子级必须完全停稳、释放所有后代、尝试最终 flush 并 dispose 自身 Handle 后，父级所有权才解除；持久子会话不会随进程内 Activation 拆卸而删除。

Interrupt 不是 Dispose

中断在线子级只对当前 driver 发出取消并立即返回，不等待完全停稳；Activation、尚未领取的 Inbox 工作和已发布后代都会保留。之后的唤醒消息会继续处理被暂停的 FIFO。

主动报告与结算通知不是同一件事#

可选的 report 工具只安装进可继续的进程内子级作用域。接收方不能由子级指定：运行时从持久 parentSession 推导唯一的直接父级，并要求发送方与父级此刻都在线。

Wakeup：开启父级后续轮次

默认策略用 parent followup 投递一个普通新轮次；它不会 steer 正在运行的父级轮次。

Quiet：只注入后续上下文

Quiet 使用 parent inject，不立即发起模型请求；父级繁忙时，内容会等待下一个安全日志位置。

报告不代表子级结束

一次报告不会结束当前轮次或结算 Activation。提示词建议结束前报告，但运行时允许零次或多次调用，最终回答也不会自动变成报告。

结算通知由管理器署名

对每个已向调用方返回过 id 的子级，Activation 结算时都会在释放父级所有权之前发送 subagent-settled，说明终止原因和最终助手内容；它与子级自写的 subagent-report 使用不同来源，二者可能同时出现并分别消耗父级 token。

Accepted 不是已读或耐久回执

Report 返回的 MessageId 只证明父级已接受消息，不证明父级已读、完成轮次或刷盘；没有离线 mailbox、幂等键与重试协议。工具在接受后的 post-execute 阶段仍可能报错，所以失败也不能反向证明消息未送达。

不唤醒子级的持久目录发现#

listChildren 与 listDescendants 直接合并在线 Session 存储和可选持久目录，并通过 descriptor 投影读取身份；它们不会创建、加载或恢复任何 Agent，也不依赖 Session Query 服务。

Children：只看直接子级

按 createdAt、再按 id 稳定排序。服务结果可包含一次性子级，但模型侧 list_agents 只保留可继续子级与无法读取的 diagnostic。

Descendants：穿过完整会话树

稳定 pre-order 遍历会穿过普通 Session 与一次性 child，再为保留条目显示持久 parent id 和相对 depth；因此 parent 可能是输出中省略的中间节点。

状态描述可操作性，不描述结果

Running 表示 driver 活跃，idle 表示在线但处于轮次之间，ready 表示仅存于存储且可恢复；ready 不是终态，也不代表有结果等待收集。

权限仍在执行时校验

目录中的持久身份和 lineage 只是候选信息。只有调用方的直接可继续 child 可接受 send_message；更深后代只能作为 interrupt_agent 候选，真正操作仍由在线所有权与鉴权检查决定。

目录没有 cursor 或数量上限

list_agents 每次返回完整投影，descendants 会按整棵树线性增长。长期父级拥有大量持久子级时，每次调用都会承担完整列表的 token 成本。

todo_write 属于当前 Agent 会话，每次调用都提交完整列表快照，而不是增量修改。条目只有三种状态：

输入区的 Todo 计划条#

TodoDock 读取 Host 计算的 todos 投影，而不是扫描当前可见消息。当前计划是最近一次 todo/write，且它之后不能已有更晚的 turn/start；新一轮开始会清空旧计划投影，turn/end 则保留刚完成的清单。

空列表不占位置

面板收到空列表时自我隐藏；有内容时默认折叠，表头显示计划标题和各状态数量。

计数只展示非零项

已完成、进行中、待处理按“·”连接，例如“1 已完成 · 2 进行中 · 1 待处理”；数量为零的分类直接省略。

Dock 顺序由 slot 固定

Todo 以 order 0 位于 Goal 与 Queue 之前；当 composer 接管链隐藏输入区时，整个 dock 也一起隐藏。

todo_write 工具调用本身仍由 ui-tool 在消息流中渲染；TodoPanel 只接收纯列表和会话选择，不承担日志折叠或工具状态合成。

长 Todo 目前只能看单行预览

过长条目会以省略号截断，当前没有换行或展开入口；需要保留可读性时，应把任务拆成简短、可验证的条目。

持久 Goal#

Goal 用于一个需要跨多个轮次持续推进的同会话目标。它与普通 Todo 不同：Goal 有 phase、revision、Round 上限和明确的暂停、恢复、完成与阻塞生命周期。

create→active↔pause / resume→complete

Goal Round 只在 Agent idle、目标仍 active 且有剩余容量时追加；人类消息优先且不消耗 Round。恢复会话或 fork 后，自动续行默认停用，必须由用户明确恢复。

完成需要证据

模型必须读取精确 goal id 与 revision 后再更新。困难或不确定不是阻塞；只有同一阻碍连续达到配置阈值后才能报告 blocked。

Goal Round 何时才真正消耗额度#

驱动器先为下一编号预留一条携带当前 goal id 与 revision 的消息，但预留本身不增加 roundsStarted。只有该 goal 来源的 user/message 被 Inbox 领取并通过 pre-step 复核，才算一次已准入 Round。

陈旧预留不占编号

Goal 在领取前被编辑、暂停、完成或换 revision 时，旧消息会被拒绝；编号没有缺口，后续仍从当前 roundsStarted 加一。

人类工作始终让自动轮次让路

人类消息先进入 Inbox 或与预留落在同一待处理批次时，自动提示词会被拒绝并等待下一次 idle；人类轮次不消耗 Goal 上限。

排队前先越过持久屏障

goal 变更后，驱动器先等待 Session flush，再重新检查 revision 与竞争输入。Flush 失败会停用续行，避免用未确认状态启动下一 Round。

取消不会自动重新开跑

取消涉及已预留或已准入的 Goal 尝试时，下一次 idle 检查点会暂停目标；其他取消也会撤销进程内续行权限。暂时性 Provider 或持久化故障需要用户之后明确 resume。

maxGoalRounds 不是资源预算

它只限制已准入的自动 Round 数量，不限制 token、费用、墙钟时间或提供方配额。Provider 失败与 token 上限也不会被驱动器自动分类为完成或阻塞。

压缩尝试如何留下完整事务证据#

每次尝试先追加 compaction/start；成功路径再生成摘要、写入 compaction/summary 与替换用 user/message，最后才追加 compaction/end。三类记账事件只进入日志；真正改变模型表层的是带 replace 操作的检查点消息。

遗留 start 可以被检测

如果进程在 end 之前崩溃，日志会保留未配对 start，而不会伪造成功结束。当前生命周期中的活动锁会阻止其他压缩入口。

锁不冻结整个 Session

手动摘要等待期间仍可能接收不相关的空闲注入；提交前只复核选中的 surface span，位于该 span 之外的新上下文会原样保留。

失败码对应不同提交阶段

Changed 与 summary 保持表层不变；commit 可能发生在部分变更之后；persistence 表示内存标记已闭合但最终 flush 失败。

范围按表层位置，不按数字区间

先前替换会把高 seq 的新节点放进较旧位置，因此 shadowedRange 的 start 可能大于 end。按 surface 顺序记录的 shadowedSeqs 才是被遮蔽节点的权威集合，边界还必须保持工具调用与结果配对。

旧生命周期的遗留锁不会永久卡死

未配对 start 通常阻止新尝试，但如果它位于较新的 session/end-seed 之前，就被视为先前生命周期的陈旧证据并忽略。

不调用模型的工具结果剪枝#

可选的 Tool Result Pruner 只在压力或已确认上下文溢出触发后扫描当前表层稳定快照；低于压力的普通步骤检查绝不剪枝。每个超限结果会变成“保留头部 + 固定省略标记 + 保留尾部”。

原始事件仍可精确回放

剪枝通过新追加的 tool/result 替换表层单节点，并引用原始 seq；它只改变 content，turn、step、callId、错误、meta 和未来字段全部保留。

富内容顺序保持稳定

只统计和切分 text block，非文本块维持原相对位置。切片按 Unicode 码点执行，不会拆开 UTF-16 代理项对，但仍可能切开多码点字素簇。

一次替换后会收敛

输出严格短于触发输入且不超过 thresholdChars，因此第二次扫描不会再次替换；默认配置保留 4096 个头部码点和 1024 个尾部码点。

字符预算仍要换算回请求压力

不同模型的 token 密度不同。剪枝完成后 Token Meter 会重新测量：回到安全范围就跳过摘要，否则摘要器读取已剪枝表层继续压缩。

扫描不是全有或全无事务

如果 Session 拒绝后续某个替换，调用会抛错，但本次稳定快照中更早已经提交的替换仍然耐久。剪枝也只按语法保留头尾，不判断中间哪些行在语义上最重要。

Chat 中的压缩检查点#

浏览器在检查点自己的日志位置渲染一行折叠标记，不会用它替换上方已经加载的 transcript。自动压缩显示“上下文已压缩”；若对应 compaction/summary 事件位于当前窗口，完成行会显示被替换条目数和估算 token，并允许展开摘要。

手动命令保持身份

/compact 开始时先显示运行中的 compact 行；成功后，显式摘要引用把它折叠进检查点，同时保持同一个 React key，避免结算时闪烁换行。

配对不依赖相邻位置

压缩运行期间可能插入持久上下文，因此命令、检查点与摘要通过显式引用关联，而不是假设它们在日志里相邻。

窗口缺页仍保留标记

被引用的 summary 尚未加载时，检查点仍可见但不可展开；历史分页补齐来源后，界面才能展示摘要内容。

完成且静止时保留上下文压缩图标，只有悬浮或键盘聚焦才切换为展开/收起指示。输入被拒绝、没有可压缩历史、取消或失败时继续使用通用命令行及处理器文案，不伪装成成功检查点。

模型载荷不会重复出现在 Chat

面向模型的带框检查点内容永不直接渲染；用户看到的是可解释的标记和可选摘要，而不是同一压缩正文的第二份消息。

Guard 插件通过 tools/execute 流水线增加可靠性策略，不改变具体 Tool 的实现。当前常见的两类保护是协作式超时与重复调用提醒。

截止时间与重复链的精确语义#

只有声明预算才超时

策略零配置，只读取工具自己的 ToolDefinition.timeoutMs。未声明预算的工具原样执行；声明预算也意味着该工具承诺转发 exec.signal。

拒绝调用也参与计数

重复检测位于 post-execute，因此被 pre-execute 拒绝后仍反复提交的相同调用也会推进链；这正是需要提醒的循环。

参数键是完整规范值

对象键深度排序后再序列化，所以属性顺序不同仍视为相同；提醒中的参数预览有长度上限，但检测始终比较完整值。

用户新提示词会重置对应 Agent 的重复链；持久会话恢复会从空链开始，而 compaction 不会重置当前进程内的链。提醒只在精确达到配置阈值时注入，超过最高阈值后不会每次继续追加。

两种 Guard 都不是硬停止

Timeout 只是向协作工具发出中止信号，忽略信号的实现仍可能继续运行；Repeat Reminder 只追加带来源的 user context，保留原工具结果且不否决调用。多个 execute 包装层的注册顺序还决定截止时间覆盖整次重试还是单次尝试。

终止请求已发出，等待生产方释放资源。

✓completed / killed / failed

输出读取使用单一消费游标：流式任务每次返回上次读取后的增量，只有最终输出的任务则在结束后重复返回同一结果。任务访问按拥有者 session 授权；Agent 被释放时，其任务会被取消并等待清理完成。

取消不是瞬间完成

kill 只请求生产方终止并把状态推进到 stopping。只有生产方真正释放资源、done settle 后，任务才进入 killed 或其他终态。

浏览器中的会话搜索#

侧边栏搜索把快速本地匹配与 Host 正文检索组合成一个扁平结果列表。标题和 Workspace 子串按不区分大小写立即匹配；非空查询经过 250 ms 防抖后，再加入按相关性排序的对话内容结果与摘要片段。

输入先规范化

查询移除 NUL，最多保留 500 个 UTF-16 代码单元，并保证不会在截断处拆开代理项对。只含空白的查询不会发起正文搜索。

旧请求主动取消

每次新查询都会中止前一个 Host 请求。搜索状态属于当前 UI 所有者，不写入共享 Session 列表，因此页面必须自行抑制迟到响应。

远程失败仍可降级

正文检索失败时，标题与 Workspace 的本地匹配继续显示，并附带警告。结果最多展示 20 条，过宽查询会提示进一步缩小。

结果定位到 Session，不定位到事件

打开命中项不会清除当前查询，也不会跳到摘要对应的日志事件。当前搜索没有模糊匹配或事件深链接；正文后端采用字面 token 或短语语义。

标题是后写覆盖的持久日志状态。内置 fallback 或可选 Provider 会根据合格的人类文本消息生成标题，并记录精确的来源消息 seq；用户手动重命名后，标题会被固定，后续自动生成停止调度。

会话分支、归档与删除边界#

Fork 不会在任意半成品事件处截断。消息下方的分支操作只在已完成轮次的最后一条 Assistant 文本上启用；宿主把事件锚点推进到该位置之后的首个 turn/end，确保子会话继承完整轮次。

Fork

继承种子历史、cwd、最近模型选择和谱系，再加入源 Workspace。开放轮次不能分支，也不会悄悄退回更早轮次。

Rename

显式标题会写入日志并固定，之后的自动标题不能覆盖。Fork 后客户端会把标题尾部编号递增。

Archive

只把 Session ID 加入全局归档集合，从所有分组和搜索视图隐藏；日志与 Workspace 记账保持不变。

当前没有删除 Session 或取消归档控件

删除 Workspace 只删除注册记录，目录与 Session 日志仍保留，相关会话会进入 Ungrouped。归档同样不是删除；当前 Web UI 没有查看或恢复已归档会话的入口。

若 Fork 已成功发布子会话、但加入 Workspace 或自动改名失败，错误仍会携带并保留已创建的子会话，客户端先完成对账再报告失败，避免重试时产生重复分支。

消息底部操作何时出现#

Chat 不会给每一个 Assistant 节点复制一套操作栏。复制、时钟与分支组成的 IconActions 只挂在已结束轮次中最后一条带文本内容的 Assistant 消息下，让一个完整轮次只有一个明确操作锚点。

中间内容没有 chrome

轮次中间的叙述、纯 Think 节点，以及仍在生成步骤的轮次都不显示消息操作栏，避免把半成品误当成稳定分支点。

分支要求完整尾部

即使操作栏可见，只有同时位于已完成轮次最后一个 transcript 节点时才启用分支；成功后递增继承标题并打开子会话。

用户气泡保持只读

已发送的用户消息保留复制和时钟，但没有编辑或分支操作；当前 Host 对已消费输入也没有对应的重写语义。

失败不切走源会话

如果 fork 或自动改名失败，源会话继续保持选中。界面不会打开一个尚未完成对账的目标，也不会静默退回更早轮次重试。

归档集合如何跨标签页收敛#

归档状态是 Host 注册表级的完整 Session ID 集合。Workspace 基线、本地归档 RPC 回声和其他标签页触发的 changed 帧都会安装整份集合，而不是对旧数组追加或删除一项。

新快照覆盖过期基线

若归档集合在 workspace.list 请求进行中更新，新集合会保留并压过随后返回的旧基线，避免短暂恢复已经归档的行。

当前选择统一清空

正在查看的 Session 一旦进入归档集合，投影就切回 New Session。此规则同时覆盖本地操作、其他标签页通知和离线期间变更后的重连。

隐藏不等于移除

归档行从 Workspace 分组、Ungrouped、平铺列表与内容搜索中全部消失，但 Session 摘要仍留在运行时 store，日志与记账席位也不改变。

Archive 不弹确认框

当前 Web UI 直接提交这项非破坏性操作；失败只写入控制台诊断，列表保持原样。成功后目前没有查看或取消归档入口，因此仍应确认选中的是正确会话。

会话持久化与恢复#

内存中的仅追加 SessionEvent 日志是真源，Persistence seam 负责把同一组事件耐久保存；它没有另造一套“持久化事件”。元数据 header 与日志分开保存，记录格式版本、cwd、父会话、seed 边界、委派深度和 Agent preset。

持久化意图不等于恰好一次

工具调用可能已经产生外部副作用、但结果尚未落盘。恢复时 Harness 会写入 TOOL_OUTCOME_UNKNOWN，要求先验证状态；有副作用的 Provider 应尽量把 call id 用作幂等键。

JSONL 后端为每个会话维护可选 Zstandard 压缩的追加日志；SQLite 后端则把每个事件存成一行。格式版本过新、过旧或遇到未知的必需事件时会明确拒绝恢复，而不是静默丢失语义。

JSONL 与 SQLite 会话后端怎么选#

JSONL每会话独立工件默认写入带 checksum 的拼接 Zstandard frames，也可选择原始 JSONL；locate 与 readRaw 能暴露固定 transcript 路径和后端逐字内容。
SQLite共享事务数据库每个事件一行，批次在一个事务中提交；所有会话共享数据库，因此 locate 返回 undefined，也不提供逐会话原始工件。
Shared相同逻辑恢复约定两者都延迟到首批事件才实体化、要求连续 seq，并在冷 load 时保留有效工作、补入 interrupted closers。

副作用之前的持久性检查点#

持久化后端负责有界后台批处理，Checkpoint Policy 则独立决定何时必须完全排空。第一方运行时同时挂载两者；专用部署可以替换策略，但只装后端意味着崩溃仍可能丢失批处理窗口内的事件。

请求先耐久，再构造模型流

策略延迟包装 llm/stream。只有活动 Session 中已缓冲的请求事件全部 flush 后，下游适配器才会收到请求；拒绝检查点时 Provider 根本不会运行。

调用先落盘，再进入工具正文

顶层 tools/execute 在权限与 Guard 之后等待检查点，确保模型可见的 tool/call 已持久化。嵌套分派复用外层调用的屏障，不为内部实现重复制造检查点。

下一步先封存上一批结果

agent/pre-step 在派生新请求前持久化前一响应和有序工具结果。步骤边界失败会终止当前轮次，避免在未确认历史上继续调用模型。

取消可以阻止尚未分派的副作用

若取消在顶层工具等待 flush 时到达，包装层返回规范的 ABORTED_BEFORE_DISPATCH，不进入工具正文。并发工具检查点共享 Session 存储的串行排空流程，也不会重复分配事件序号。

检查点保护的是执行意图，不是外部事务

硬崩溃若发生在工具正文之后、结果持久化之前，日志只能证明调用已经分派，不能证明副作用是否完成。恢复会补入未知结果而不自动重试；支持幂等性的 Provider 应转发 exec.callId。

Chat 节点的增量组装#

每个 Session 把连续事件窗口交给 ConversationNodeAssembler。插件用稳定的 kind/id 在唯一 start 事件创建 State，再折叠关联 update；Assembler 统一维护 Context 索引、只读前序查询和引用稳定的 Turn/Step Location。

实时 append 只命中一次

每个新事件只对各 Definition 求值一次，并且只更新匹配的 Context，不为一条尾部事件重扫整份历史。

向前分页保留旧身份

加载更早页面时只匹配新 prepend 事件；已有 Context、节点和 keyed value 保持不变，只有前序依赖或 Location 事实变化的项才重放。

完整替换有明确边界

只有首次 open、权威 resync 或序列 gap repair 才替换完整窗口。普通内容更新只通知受影响的 node key，结构变化才重建顺序关系。

Assistant 的每个流式 chunk 都会更新 Definition State，但物化请求最多每个 animation frame 一次；final message 与 Turn/Step 关闭则立即发布。prepend 只增加行，不替换已经存在的 keyed 节点。

业务节点不能扫描 Chat 集合

Definition 只根据当前事件匹配稳定业务 id，并保证 update 可按日志 seq 回放；renderer 只消费最终 Node data 与受限 Location。否则分页和 HMR 会产生与加载顺序相关的结果。

update-only允许暂存，不能猜 start尾页只有 progress/end 时，Assembler 保留 pending Context；向前分页补到唯一 start 后再按 seq 回放，不能把它归给“最近未完成项”。
checkpoint完整值可跨窗口自启动若产品要求 start 尚未加载也能展示，terminal 或 checkpoint 必须携带足够 fallback 状态，让 Definition 独立构造结果。
visibility发布后保持同一身份一个 target Node 发布后应持续返回相同 key；暂时离开可见流使用 hidden，不要返回 null 撤销再重建。
证明 replace 正确

完整窗口应产生预期最终 State、Location data、Node payload 与 anchorSeq，且每个事件只按日志顺序折叠。

证明 prepend 等价

先加载只有 update 的尾页，再补 start，结果必须与一次完整 replace 相同；既有 keyed value 未变化时保持引用身份。

证明 append 等价

历史后实时追加得到的最终结果必须等同于完整回放；高频 delta 可按 animation-frame 合并发布，但 State 更新不能丢。

热路径复杂度属于扩展契约

注册 D 个 Definition 时，每条新事件只应做 D 次当前事件匹配和一次常数时间 Context 查找。不要遍历完整窗口、context.matches、所有 Context 或已渲染 Node；累计事实放进 State，前序依赖只在 start 中使用 reader.previous。

Chat 滚动壳与编辑器几何#

无会话、空白会话和活跃会话复用同一个根滚动容器、Hero 与编辑器子树；会话出现时，标题栏和主体只填入各自 outlet，不会替换 textarea 或编辑器 seat。Workspace 切换因此能保留草稿、焦点相关状态与 DOM identity。

滚动条槽始终预留

data-conversation-scroll 无条件保留自己的 scrollbar gutter。无论记录是否足够长、当前切到 Chat 还是 overlay 视图，输入卡片都不会横向跳动。

编辑器栈属于同一宿主

统计 dock、输入 dock 与输入栏组成 sticky 栈，和流动排版的会话视图共用滚动容器；切换视图不会换掉一棵平行的 composer 树。

草稿滚轮在边缘接力

限高 textarea 有可滚内容时先在自身滚动；到达顶部或底部后，滚轮再交给会话宿主，避免长草稿把整页滚动永久截断。

不要把预留入口当成分页功能

Assembler 已支持向前 prepend 历史并保留节点身份，但普通 Chat 的 assistant 逐消息分页目前仍只是设计 slot，尚未实现。现有 IconActions 只出现在已结束轮次最后一条有文本的 Assistant 消息下。

上下文消息的来源展开项#

写入日志的非用户消息不会伪装成普通对话气泡。Chat 默认把它折叠成 DisclosureRow：标题先显示运行时投影的角色——注入显示“上下文注入”，召回显示“跨会话召回”——再附上持久来源记录中的生产者名称。

不展开也能辨认来源

生产者标签可区分 skill 目录、Workspace 指令文件和被召回会话；来源没有名称时只显示角色，不猜测生产者。

已知形态按语义展示

instructions 在正文上方列出已对账文件；catalog 展示来源记录的条目，而不是直接倾倒面向模型的正文。

未知形态仍可检查

未声明、当前版本不认识或字段不足时使用 opaque 内容区：保留真实换行展示模型所见文本，并列出剩余来源字段。

展开内容自适应高度，最高 141px，超出后在内部滚动；它不会合成工具状态或摘要。这个 opaque 路径是正式默认协议，而非错误兜底，因此恢复、fork 或外部写入的历史即使缺少当前生产插件，也仍能渲染。

Steering 不添加虚构标记

持久或待处理的中途引导继续使用用户气泡样式；transcript 唯一的 steering 线索是它位于轮次中途。界面不会写入日志里不存在的来源或状态。

实时 Think 行与阅读保护#

Think 行默认折叠，但流式阶段并非停在一条过时摘要上。当 reasoning 块位于消息流尾部时，折叠标题从结算后的首行切换为当前最新的非空行，让用户无需展开就能确认推理仍在推进。

02展开让出控制

用户展开后移除移动摘要，完整推理进入普通页面流，不再由内部跟随器抢动阅读位置。

流式块结束后，标题回到左对齐的稳定首行摘要，历史记录不再自行移动。

这是展示策略，不是额外推理数据

界面只在运行时已经投影出的 reasoning 内容中选择摘要和滚动位置；它不会生成、补写或推断模型没有输出的思维过程。

非会话数据的领域存储#

设置、索引等不属于对话事件日志的数据进入 Storage subsystem。枢纽只负责注册后端和挂载数据形式，不执行 IO；领域层声明名称、格式版本、global slot、表和 zod schema，再按部署路由到 JSON 或 SQLite 后端。

JSON backend

每个 unit 原子重写一份人类可读文件，适合体量较小、更新不频繁的数据。

SQLite backend

在单个数据库中逐行存储文档，适合频繁更新和更多记录。

Domain API

同步读取权威内存态；写入先持久化，再更新内存并发出变更事件。

同一领域的写入按顺序排队。后端写入失败时内存保持不变，因此读取不会领先于介质；格式版本不匹配或已存记录不符合 schema 会在打开领域时立即失败。

JSON 与 SQLite 后端如何路由#

Storage hub 可以同时挂载多个具名后端；不存在全局“当前数据库”。Domain facility 先应用默认 backend，再按领域名称读取 routes 覆盖，因此低频、便于人工检查的数据和高频记录可以在同一进程中使用不同介质。

JSON：整 Unit 发布

一个 unit 对应一份完整 JSON 文件。每次写入都在同目录写临时文件、fsync 后原子 rename；缺失文件按空状态打开，首次写入才物化。

SQLite：每 Key 一行

每个 unit/table 映射为经过验证名称的 STRICT 表，key 是主键，value 保存 JSON 文本；一次更新只执行一条预处理语句，默认 journal mode 为 WAL。

Domain：内存是读取权威

写入在每个领域自己的 Promise 链上串行，只有后端成功达到持久状态后才替换内存并发出 domain/changed。

01Open

验证 unit 描述符、格式版本和全部已存记录；损坏介质、未知版本或 schema 不符都会拒绝打开。

02Commit

一次操作只修改一条领域记录；当前没有跨表事务、二级索引或多段 key 契约。

→
03Publish

提交后同步读取立即看到新内存态，并向同一进程发布变更；其他 Host 不会收到事件。

格式不匹配不会自动迁移

JSON unit 版本、SQLite unit 描述符和数据库 user_version 只接受当前值。当前处于预发布阶段，旧版或新版介质都会明确失败，部署方必须自行迁移或选择新的存储位置。

两个后端都不是多进程协调器

JSON 没有跨进程写锁，多个 Host 可能交错整文件替换并以后写覆盖；SQLite 没有 busy wait 或重试，其他连接持有写事务时立即失败。DatabaseSync 的同步语句还会短暂阻塞 Node 事件循环。

配置文件的原子替换与跨进程锁#

Settings 文件和本地 Credentials 使用共享的 atomic-write 原语：在目标同目录以 wx 独占创建随机临时文件，带着显式 mode 写完后再用 rename 替换目标。读取方因此只会看到旧内容或完整新内容。

抗临时路径劫持

不可预测的同级文件加独占创建拒绝跟随预埋 symlink；rename 替换链接本身，不会写穿到链接目标。

权限随新 inode 提交

新文件从创建起就使用调用方声明的 mode，替换权限过宽旧文件时无需先暴露再 chmod；Settings 和 Credentials 使用 0600。

读改写需要锁

withFileLock 以同级 .lock 文件跨进程串行化写入方，指数退避后超时失败；读取方不参与锁竞争。

写锁让不同 namespace 或不同凭据条目的并发编辑不会互相丢失，但两个写入者修改同一键仍是后写胜出。遗留锁不能按年龄自动删除，因为无法区分崩溃进程和暂停但仍存活的持锁者。

原子不等于崩溃持久

这个共享原语不对文件或目录执行 fsync，断电或系统崩溃后 rename 仍可能回退；启动时提供方会重新读取并发布磁盘状态。领域 Storage 的 JSON 后端另有带 fsync 的提交路径，不能据此反推 Settings 或 Credentials。

超大工具结果与 Spill#

当工具返回的纯文本超过内联预算时，Spill policy 保存完整 UTF-8 内容，并用首尾预览、不透明定位符、准确字节数和后端给出的检索提示替换模型结果。模型不会被迫为完整大结果支付上下文成本，但仍能按需读取。

full tool text→private spill artifact→head + tail preview→retrieval hint

本地后端使用会话 id 的摘要作为私有目录，并以排他、仅所有者可读写的方式创建随机文件。调用方提供的文件名只是命名提示，永远不会被当作路径；定位符同样是不透明句柄。

尽力而为的降级

如果磁盘满、权限不足或后端不可用，Spill policy 会保留原始内联结果，不会把已经成功的工具调用改成错误。Fork 会继承日志中的旧定位符，但不会复制或重新归属已有产物。

预算保留不等于来源不完整#

Output Retention 是一次调用内的轻量库，只回答“预算内保留了什么、又省略了多少”。ItemRetainer 为 glob、grep 和搜索来源保留前 N 个完整逻辑项；TextRetainer 为 Bash 与 Web 文本保留 head、tail 或 headTail，并生成精确或未知的省略元数据。

truncated 是预算事实

它只表示 retainer 省略了本可获得的内容。权限失败、二进制跳过、Provider 部分失败、不可读候选项和无效输入仍由工具自己的 incomplete 或错误字段表达。

文本预算按 UTF-8 字节

上限和 omittedBytes 不按字符或行计算。finish 会修剪切口处不完整的码点，首尾分别解码，不会跨被省略的中段拼出虚假字符。

完整集合可独立保存

Item retainer 可一边保留内联首页，一边让调用方继续收集完整排序结果用于 Spill；工具仍拥有分组、行号、状态、恢复指引和业务完整性。

通用 Spill Policy 能看见什么#

通用策略在 post-execute 阶段只处理超过 maxInlineBytes 的最终纯文本 content。它跳过普通 read、嵌套执行、已替换的规范 value、block 结果和任何混合内容；Provider 已经截断的正文也无法被它恢复。Code Mode 的 dispatch-log 另有同预算分支，会限制包括 read 在内的持久日志副本，但完整程序值早已跨过 worker 边界，不受影响。

通知也计入同一硬预算

策略先为省略字节数、定位符和检索提示预留空间，再把剩余字节分给首尾预览。若通知本身都放不下，它会保留原始内联结果，绝不生成一个超过上限或比原结果更大的替换。

Spill Owner 不是读取授权

Owner 只决定保存时的命名空间，定位符本身不授予访问权限。本地文件不会随 Session 自动删除，并可能被恢复或 Fork 后的日志继续引用；远程部署需要提供与执行文件系统一致的后端和取回策略。
