使用 Web UI

用 DeepSeek Harness 启动你的第一个智能编程任务。本指南将带你完成模型配置、工作区选择和首次运行。

i
开始之前

建议使用 Node.js 22.19+ 或 24+（与上游源码工作区一致），并准备 DeepSeek API Key 和一个允许 Agent 读取的本地项目。

安装与启动#

在终端中运行以下命令。DSH 会在当前目录启动服务，并打印 Web UI 的访问地址。

Terminal
$ npx @deepseek-ai/dsh web
Web UI → http://127.0.0.1:3080
公开预览版本

截至 2026-08-16，npm 的 latest 与 next 都指向 0.1.0-rc.6，而当前上游默认分支 manifest 仍为 rc.5。未指定版本的 npx 会跟随 dist-tag；自动化脚本应固定确切版本。

运行一次 Headless 任务#

Headless profile 适合 CI 或脚本：它创建一个全新的持久 Session，提交任务，等待 Agent 完全空闲并 flush 日志，然后把最后一个非空 Assistant 文本打印到 stdout。

Terminal
$ npx @deepseek-ai/dsh --profile headless "run the tests and summarize failures"

最终 turn 原因为 completed 时进程以 0 退出，否则以 1 退出。随附 Headless 组合不会启动 HTTP Server、Web Runtime 或浏览器 Client，成功路径也不会向 stderr 写入内容；缺少任务文本属于用法错误。

启动前检查组合配置#

配置问题不必等到服务启动才发现。dump-default-config 只展开 bundle 默认层；dump-config 还会叠加 profile、本机 DSH_HOME patch 和命令行 patch，并为每一行标注来源。

Terminal
$ npx @deepseek-ai/dsh --profile web --dump-default-config
$ npx @deepseek-ai/dsh --profile web --patch ./extra.yml --dump-config

Dump 不运行应用参数提供方，因此展示的是解析 Web 的 host/port 等参数之前的配置；同一次调用若还包含应用参数会被拒绝。Patch 替换目标行的整个 config，而不是递归合并字段。

配置模型#

打开右上角的 设置 → 模型，选择 DeepSeek，输入 API Key 并保存。模型变更会在下一次请求时生效，无需重启服务。

  1. 1
    进入模型设置

    点击设置图标，在侧栏选择「模型」。

  2. 2
    添加凭证

    选择服务提供方，并粘贴你的 API Key。

  3. 3
    验证连接

    保存后状态显示为绿色，即可创建会话。

凭据不会返回浏览器

API Key 是只写字段。保存后前端只会收到脱敏描述符；明文保存在 $DSH_HOME/.credentials.yaml，settings 中只保存凭据引用。

自定义提供方

公司网关或自建 OpenAI 兼容端点可通过「添加自定义提供方」配置。Provider ID 会被请求、会话、默认模型和凭据引用使用，因此保存后应视为永久标识；展示名称、URL、协议和模型仍可修改。

MISSING_CREDENTIAL在模型页保存密钥，或提供配置引用的环境变量。
UNKNOWN_MODEL重新选择已配置模型，或在自定义提供方中添加模型。
401 /models检查凭据；不提供模型发现端点时应手动录入模型。

选择工作区#

点击「选择工作区」，添加你启动 dsh 时所在的项目目录。工作区决定 Agent 能够读取和修改的文件范围。

注意

选择工作区前，会话输入框保持禁用。请勿将包含敏感凭证的目录设为工作区。

新建一个会话，然后尝试发送一个目标明确、可以验证的任务：

总结这个仓库，列出它的主要模块，并解释各模块之间的关系。

Agent 可以读取文件、执行命令并维护计划。当某项操作超出当前权限策略时，Web UI 会先请求你的批准。

Session 的仅追加事件日志#

SessionEvent 日志是一次 Agent 交互的唯一真源；模型消息历史、UI 状态和回放结果都从同一序列派生，不存在另一份单独维护的 transcript。每条事件都有连续 seq 和毫秒时间戳，payload 必须是无损 JSON。

01Turn

一次排队输入的生命周期；拒绝或空输入也可能只有 start/end 而没有模型步骤。

→
02Step

一次模型调用及其请求的工具执行；重试会打开新的编号步骤。

→
03Surface

用户消息、组装后的 Assistant 消息和工具结果形成模型可见表层。

原始 assistant chunks 会完整记录以保证流式回放；组装后的 assistant message 才进入派生历史。完整 request header 记录模型、系统提示词与工具 schema，只有配置变化时再写一份新快照，因此任意请求都能从日志重建。

权限与审批#

Harness 把沙箱模式和审批策略作为两项独立机制。权限预设只是在产品层把两者组合成一个选择器；执行时仍由各自服务单独强制。

沙箱模式

read-only只读文件变更被拒绝，读取保持可用。
workspace-write工作区写入仅工作区和平台临时目录可写；默认搭配 ask。
danger-full-access完整访问不添加文件围栏；默认搭配 never。

文件系统围栏会在目标规范化后检查可写根，并在写入前重新规范化以缩小符号链接竞态。不过它是可信进程中的策略围栏，不是针对恶意宿主代码的内核安全边界。

一次性审批

审批结果只有 allowed-once、rejected、cancelled 和 unavailable。每次决定都会写入成对审计事件；没有应答者或应答失败时默认拒绝。never 策略会在交互分发前确定性拒绝请求。

权限预设与 custom 状态#

Permission Preset 只是把沙箱模式与审批策略这两个独立强制旋钮包装成一个客户端选项。预设自身不执行隔离，也不替代审批；切换时仍通过各自服务的规范 setter 写入日志。

workspace-write

默认组合为工作区写入加 ask，适合交互式开发。

danger-full-access

默认组合为完整访问加 never，只应在受控环境中使用。

custom

当两个旋钮不匹配任何声明预设时派生显示；它不是可选择的目标。

当前值从 Session 日志中实际生效的旋钮推导，而不是盲信最后一次选择。若多个预设共享相同组合，仍匹配的最后选择优先；否则按声明顺序选择首个匹配项。重新选择当前预设不会追加任何事件。

审批的完整链路#

每一次审批请求都有全新的 ApprovalRequestId，用于把 approval/asked 与 approval/decided 配成一组。请求只携带 Agent、工具名、可选 call id 与理由；工具参数仍由已经流式展示的调用负责，避免 UI 渲染第二份可能漂移的数据。

01Policy

never 在应答者运行前直接拒绝；ask 才进入组合链。

→
02Waterfall

UI 或 ACP 应答者可认领请求，否则交给下一个；异常与非法返回值归一为 unavailable。

→
03Audit

只有 asked 与 decided 都越过日志提交点，结果才会返回调用方。

只有 allowed-once 会放行

取消信号会立即撤回问题，迟到的答案被丢弃。审批审计事件不会进入模型 transcript；模型只看到工具派生结果和最新的运行时上下文快照。

E2B 远程执行运行时#

E2B provider 让文件系统、Bash、PTY 和 LSP 共享同一个短暂远程 Linux 沙箱，而 Cordis 服务、Agent、Session 日志、LLM 请求与 SDK 缓冲仍留在宿主进程。宿主 API Key 只用于创建 SDK 连接，绝不会注入沙箱环境。

01Own

共享 owner 创建远程 cwd 和权限为 0700 的私有适配器目录。

→
02Adapt

远程 fs 与 subprocess provider 复用同一个句柄和进程命名空间。

→
03Dispose

先停止新操作并清理进程，再删除沙箱；超时同样会删除全部状态。

远程 cwd 不是同步或包含边界

本地工作区不会自动上传或同步回来；把宿主路径写进 cwd 只会远程创建同名目录。命令仍能访问沙箱中的其他路径，网络策略沿用 E2B 基础镜像。

程序化使用从 Web UI 走向 SDK

Python SDK 快速上手#

Python SDK 适合批处理、自动化流水线和把 Harness 嵌入现有服务。它要求 Python 3.10+；已发布的 SDK 自带同版本运行时，普通使用不要求系统安装 Node.js。

Terminal
$ python -m venv .venv
$ . .venv/bin/activate
$ python -m pip install deepseek-harness-sdk

最小调用由 DeepSeekHarness 管理内置运行时的生命周期。同一个实例可以复用运行时；只有要延续对话与持久 Shell 状态时才复用 session id。

Python
from deepseek_harness import DeepSeekHarness

with DeepSeekHarness(
    cwd='/workspace',
    session_root='/sessions',
) as harness:
    result = harness.run(
        '检查仓库并修复失败的测试',
        session_id='task-001',
    )

print(result.final_response)

Workspace 与 Session

cwd

选择 Agent 工作的项目目录。应当指向隔离、可恢复的 checkout。

session_root

保存 JSONL 会话日志、工具调用和组装后的模型请求。

session_id

决定是否延续同一段对话以及持久 Bash 进程状态。

安全边界

官方最小 Python 示例使用 danger-full-access，Bash 和编辑器可修改运行时进程能访问的路径。只在可丢弃的 checkout 或容器中运行。

可扩展架构一切皆插件

创建第一个插件#

Harness 由 Cordis 驱动。最小插件是导出 apply 函数的 TypeScript 模块；框架在依赖就绪后传入上下文对象。

my-plugin.ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context) {
  console.log('[hello-plugin] loaded')
}

本地开发时，通过 patch 层加载绝对路径，并以 Web profile 启动：

Terminal
$ pnpm dsh web --patch ./scratch-plugin/cordis.yml

开发一个 Tool#

工具插件通过 inject = ['tools'] 声明依赖，再用 defineTool 同时定义参数校验、规范输出和模型可见的渲染结果。

01声明输入

Parameters 会推导并校验 execute 的参数。

02返回规范值

execute 返回由 output schema 约束的数据。

03渲染模型内容

render 将规范值转换为模型真正看到的结果。

配置 Schema#

插件通过同名的 TypeScript Config 类型和 Schemastery schema 接受配置。默认值属于 schema；无效配置应在插件加载时立即失败，而不是运行到一半才降级。

config.ts
export interface Config {
  timeoutMs: number
  mode: 'fast' | 'accurate'
}

export const Config = Schema.object({
  timeoutMs: Schema.number().default(30000),
  mode: Schema.union(['fast', 'accurate']).default('fast'),
})
判断标准不同部署是否可能需要改变这个值？如果是，它就应该是配置字段，而不是硬编码常量。

修改 cordis.yml 会触发插件热替换：旧实例先卸载并清理 effects，新实例再使用已校验的配置加载。

事件系统#

事件是插件间松耦合通信的核心机制。Cordis 提供四种模式，它们的执行与返回规则不同：

emit同步广播

执行所有监听器，忽略返回值。

bail同步短路

首个有效返回值会停止后续监听器。

serial异步顺序

按注册顺序等待，同样支持短路。

waterfall包装流水线

监听器包装下游返回值，形成处理链。

Waterfall 的关键规则

监听器必须调用 next() 才会继续下游；不调用会有意短路整条流水线，适合拦截器和网关。

Cordis 事件通常采用 namespace/action 命名。持久化的 turn/*、step/* 和 tool/* 是会话事件类型；观察它们时应监听 session/event 并检查 event type。

插件生命周期#

每个插件运行在独立 Fiber 中。依赖未就绪时等待，加载成功后进入 ACTIVE；必需服务消失时自动卸载，服务恢复后重新加载。

PENDING→LOADING→ACTIVE→UNLOADING→DISPOSED

ctx.on()、工具注册和 ctx.effect() 都由 Fiber 追踪，卸载时自动撤销。若多个清理步骤存在先后依赖，应放入同一个 effect 的 disposer 中串行执行。

Web Client 模块与启动图#

带浏览器界面的插件通过 package.json 的 dsh.client 声明加入 Web 启动图。Host 把每个 bundle 的地址、内容哈希、依赖边和预取标记组合进 window.__DSH_BOOT__；浏览器必须先验证整张图，才会启动任何模块。

01Scan

以 cordis.yml 所在目录解析包和 client 导出，启动阶段聚合报告所有损坏项。

→
02Serve

每个 bundle 从专用插件路由返回；未知 id 明确 404，不会落入 SPA HTML。

→
03Activate

immediately 只负责预取和登记，真正的激活顺序由 Fiber 依赖等待决定。

单个 bundle 的 rev 来自内容哈希，整图 rev 会随任一行变化。开发时 HMR 重新哈希并通过 SSE 广播；生产图不含 HMR。插件元数据会按包名缓存，因此插件集合变化需重启，单纯重建 bundle 则走 rebuilt 通知。

Scope 路由与生命周期所有权#

Scope 用同一个注册上下文同时表达“哪个 Agent 能看见这项贡献”和“谁负责在生命周期结束时拆除它”。不透明的 ScopeKey 只按对象身份比较；事件使用路由载体过滤，但真实业务对象仍作为显式参数传递。

Global layer

立即存在，保存所有 Agent 都可见的具名与匿名注册项。

Scoped layer

按需创建，近层同名条目遮蔽全局项；读取本身不会意外创建状态。

Quiescent dispose

并发 dispose 会等待同一个完全停稳边界，精确撤销该 Scope 拥有的贡献。

同一层的具名条目保持插入顺序；匿名条目即使值相等也拥有独立身份。只有整个作用域层的所有 table 都为空时才回收它，避免删除一个注册表时误伤兄弟表。

Web Server 的路由与暴露边界#

GUI 的 HTTP Server 只是浏览器载体，不理解 Agent loop。请求先匹配 exact 路由，再匹配最长 prefix，最后交给唯一 fallback；重复路由或第二个 fallback 会在组装时直接报错。

127.0.0.1默认回环只供本机浏览器访问，是默认监听姿态。
0.0.0.0显式网络暴露服务本身没有 TLS、认证或 Origin 策略，会暴露给所在网络。
port: 0系统分配端口操作系统选择空闲端口，服务公开最终监听值。

静态 SPA fallback 对路径穿越返回 403、非 GET/HEAD 返回 405，未知扩展资源不会伪装成 JavaScript。关闭时同时停止监听并强制关闭 SSE 等长连接，避免插件卸载永久挂起。

TypeRT Remote 调用边界#

TypeRT 把 Host 服务方法生成成可验证的远程调用描述符。请求只发送 namespace、method 和具名 args；取消信号走传输载体，在业务参数之后注入，绝不会混进 JSON 参数。

01Describe

生成器固定参数顺序、wire 字段、lookup、context 和输入输出 codec。

→
02Bind

Gateway 把不透明 wire identity 解析回当前活的 Host 对象或作用域。

→
03Validate

调用前后都检查边界 schema，基础设施错误使用稳定分类。

Lookup provider 卸载后，wire 声明仍保留，因此请求会明确返回 unavailable，而不会把身份字符串误当普通对象。Client 只看见显式导入并挂载的 Remote namespace；业务服务实例和 JavaScript Proxy 都不会跨边界。

能力的三种角色#

当能力需要可替换提供方时，Harness 将它拆成三个角色。只有完整组合才构成一个 capability seam；单独一个角色并不完整。

01Service Definition

定义 Cordis 服务以及 Request / Result 类型。

←
02Service Provider

实现本地、远程或沙箱中的具体行为。

→
03Consumer

把能力呈现为 Tool、API 或其他用户界面。

Provider 与 Consumer 都依赖 Definition，但彼此不依赖。只有角色需要独立演进或替换时才拆包；简单工具无需预防性拆分。

LLM 适配器#

新的模型提供方通过继承 LlmAdapter 并实现异步 stream() 接入。适配器把统一请求转换成提供方 API，再把流式响应转换成 Harness 的 StreamChunk。

block-start→text/tool deltas→block-end→usage→finish
  • 每个 block-start 必须有对应的 block-end。
  • index 从 0 递增，用于标记内容块顺序。
  • usage 必须在 finish 之前；finish 必须是最后一个分片。
  • 不支持的字段应抛出带稳定 code 的 LlmError，不得静默丢弃。

流式协议、失败与重试#

文本、推理和多个工具调用可以在同一响应中交错，index 把 delta 归属到对应内容块；block-end 携带完整块。共享 BlockAssembler 同时记录原始分片并组装最终 Assistant 消息，避免各消费方自行实现不一致的 fold。

Normalized failure

抛出的传输错误和流内错误统一为可序列化 LlmFailure，按稳定 code 路由。

One call, one attempt

适配器必须关闭 SDK 自带重试；Agent 恢复会开启新的、持久且编号明确的步骤。

Frozen policy

请求选定路由时捕获不可变重试策略，后续替换 Provider 不会改变进行中的恢复。

远程流有有限的 idle timeout；上下文溢出统一映射为 CONTEXT_WINDOW_EXCEEDED，空 completion 映射为可重试的 EMPTY_RESPONSE。Provider 的 retry-after 只是事实，不是自动重试决定。

TokenUsage 计数互不重叠

未缓存 input、cache read、cache write 三项相加才是计费输入；reasoning tokens 已包含在 output 中，汇总时不能重复计算。

Agent 动态扩展运行时#

自引用 Cordis 工具让 Agent 先检查活的服务、API、事件和 Client slots，再定义并运行临时动态包。cordis_define 只做语法预检和登记；所有副作用都推迟到显式 cordis_run。

inspect先查询契约把编译期 API 目录与当前活服务取交集，避免凭空猜测接口。
define → run版本化实验Host 半先在 node:vm 中求值；Client 半必须由打开的页面确认并装载。
stop / undefine完全撤销停止会释放 Fiber 贡献；删除还会忘掉全部不可变 Package 版本。

动态包只存在于共享进程内存，不写插件文件、不修改 cordis.yml，也不会跨重启恢复。每个操作按定义它的 Session 校验归属；其他会话读取时表现为不存在。

VM 隔离不是安全边界

Host 半仍可通过获准的 fs、web、bash 等服务影响运行时，应当像授予 Bash 一样慎重。带 Client 半的 run 在无人打开页面时会一直等待，直到调用轮次取消；同步 vm timeout 也不约束逃逸出的异步函数体。

Profile 与组合包#

组合包（bundle）贡献一层配置，profile则描述哪些组合包按什么顺序构成一个可启动应用。二者职责不同，不应混为一种 manifest。

2Profile 自有 patch
1Bundle patch 列表

后应用的层按行胜出。一个 patch 会替换目标行的整个 config，而不是递归合并其中的字段。

Agent 配置设置、凭据与组装

Settings 的三层解析#

用户设置按 namespace 分节，每个生效值依次叠加 Schema 默认值 → 组合层 base → 用户分节。cordis.yml 仍保存部署组合；Settings 只承载允许用户编辑的子集。

3用户覆盖 · update / replace / mutate
2组合层 base · 部署方默认
1Schema defaults · 类型与表单

update 合并稀疏 patch；replace 整体替换并让缺失字段重新继承；持有脱敏视图的 UI 必须使用路径级 mutate，避免覆盖自己从未看到的 secret 字段。每次写入都带 revision，可拒绝过期页面的并发覆盖。

生效时间是产品提示

live owner 观察变更并热应用；restart owner 只在构造时读取。外部编辑无效时，运行中的 namespace 保留最后一个已验证值。

凭据引用与热轮换#

配置文件只保存形如环境变量名的 CredentialRef，明文由 Credentials provider 管理。LLM Adapter 在每次请求前重新解析引用，不跨操作缓存，因此轮换后的密钥会在下一次请求生效，无需重启。

resolve

只向受信任消费方返回非空值及来源层；空字符串始终视为未配置。

describe

UI 只看到 configured、source 与 writable，永远拿不到凭据值。

set / unset

只修改 provider 管理的可写层；被只读环境变量遮蔽时明确拒绝。

不要把 Secret 放进 Settings

Secret schema 字段在所有网络 descriptor 中都必须脱敏。模型配置引用凭据名，而不是复制 API Key。

Agent Presets#

Preset 是包含 agent.cordis.yml 的目录，决定一个 Agent 可见的工具、提示词和投影插件。Roster 把每个版本的组装常驻挂载一次，各会话通过 scope 父链加入，实现 agent → preset → global 的近层遮蔽。

Persona 与系统提示词组装#

系统提示词由具名、带 order 的 section 组成，并在每次模型步骤前与工具 schema、变量和动态 runtime context 一起组装。Scoped section 会遮蔽同名全局 section；重复注册或未解析模板变量会立即失败。

向用户提问#

当 Agent 缺少会实质改变结果的信息时，可以通过结构化问题暂停并等待人类回答。每个问题带稳定 id，可提供单选、多选、自由文本和补充说明；回答仍按 id 返回，避免批量提问时依赖位置。

普通选择

选项标签同时是 UI 文案和返回给模型的稳定值；说明文字只用于帮助决策。

意图只改变 UI 呈现，不改变回答协议；批准项由标签明确指定，不能靠选项顺序猜测。

自由输入

单选时“其他”会覆盖已选项；多选时可以同时保留选项与补充文本。

只能由运行时根提问

受父 Agent 管理的 Subagent 没有独立的人类应答者，因此不能发起交互请求；取消、没有 UI provider 或调用方已失活都会返回结构化错误，而不是无限等待。

文件系统目标、观测与原子写入#

文件系统能力把服务定义、后端、观测策略和模型工具拆开。路径先解析为带显示路径的不透明目标；消费者不得解析 target key，也不能假设它一定是本地绝对路径。

Observed present

读取记录后端版本；后续写入或编辑只在版本仍匹配时原子提交。

Observed absent

确认不存在只授权 create-if-absent，不会授权对缺失文件执行 edit。

Never observed

默认策略拒绝盲目编辑，防止覆盖 Agent 尚未读取的外部变化。

编辑不是“先读再写”的外部组合：版本检查、字面匹配、换行规范化和原子替换都在同一个后端临界区完成。窗口化读取即使只返回部分行，也会记录完整文件版本；过大的原始字节读取则明确失败，不会静默截断。

符号链接需要单独看待

resolve 会跟随链接以生成稳定身份；需要守住仓库信任边界的调用方应先使用不跟随最终链接的 lstat，并在解析前拒绝 symlink。

Glob、Grep 与结果预算#

文件发现工具使用 npm 随包交付的 ripgrep 二进制，并通过 Subprocess seam 以固定 argv 启动；不依赖宿主预装 rg，也不经过 shell。启动时强制 no-config，避免继承的 RIPGREP_CONFIG_PATH 注入预处理器。

glob

查找文件路径并包含 hidden/ignored 文件；不含斜杠的 pattern 会匹配任意深度 basename。

grep

按 rg JSON 解析正则匹配并按文件分组，避免依赖冒号拆分。

spill

内联页面达到路径、匹配或行字节上限时，尽力保存完整格式化结果。

原始 stdout 超过传输预算会以 SEARCH_RAW_OUTPUT_OVERFLOW 失败并要求缩小查询；退出码 1 只是成功的空结果。搜索进程的 cwd 必须与文件系统工作区共置，否则返回路径无法保证能被 read 继续读取。

Shell 与持久 Terminal#

两者都能运行命令，但生命周期不同。默认使用 Shell 完成有边界的一次性操作；只有任务需要交互式 stdin、REPL、开发服务器或持续终端状态时，才打开 PTY Terminal。

Shell foreground

等待命令结束，分别报告退出码、信号、超时与调用方取消；非零退出是正常结果，不是基础设施异常。

Shell background

立即转成通用 job；没有执行器超时，通过增量游标读取输出，并可请求终止整个进程组。

PTY Terminal

保留 shell 状态和 scrollback，支持发送输入、分页读取、信号、列出与显式关闭。

返回不代表命令退出

terminal_send 因 inferred_idle 或 timeout 返回时，顶层 PTY 仍可能运行。应检查 session status，并在不再需要时调用 terminal_close。

Harness 会清除子进程环境中的凭据及继承的 DSH_* 名称，再合并本次受管环境快照。输出超过内存预算时只内联尾部，并用私有 spill 文件保留完整流的恢复信息。

子进程、流与进程树终止#

Subprocess seam 为 Bash、LSP、PTY 和 ACP 提供同一个底层进程世界。Spawn spec 没有隐藏默认值：argv、cwd、三条 stdio、环境、宽限期和取消信号都由调用方明确给出，argv 永远不经过 shell 解释。

pipe协议流把原始 Readable/Writable 交给 LSP JSON-RPC 或 ACP ndjson 等协议消费者。
inherit直接诊断子进程输出直接进入 Harness 自己的描述符。
collect有界收集内存只保留尾部，可选 spill 保存有上限的完整流。

收集读取使用全流字节 offset，多个读取者不会抢走彼此的数据。终止以整棵进程树为范围：POSIX 先发 SIGTERM，等待 grace period 后升级 SIGKILL；Windows 使用 tree termination。最终 outcome 只报告退出码和信号，超时或取消原因由拥有 deadline 的调用方分类。

LSP 精确代码导航#

文本搜索适合普通浏览；当同名符号含义不清，或修改前必须确认精确定义、实现和引用时，使用只读 lsp 工具。它只公开四种闭合操作：

goToDefinition跳转定义

定位当前符号的定义位置。

findReferences查找引用

返回引用并始终包含声明本身。

goToImplementation查找实现

从接口或抽象符号定位实现。

hover类型信息

读取语言服务器给出的 Markdown 或纯文本说明。

模型输入使用从 1 开始的 UTF-16 行列坐标；没有对准符号可能得到空结果。Provider 按文件扩展名确定性选择，没有匹配项时返回 LSP_UNAVAILABLE。LSP 是可选能力，不属于 Agent loop 主干。

自动化命令、钩子与编排

斜杠命令#

用户命令由插件注册，交互式客户端负责发现并针对确切 Agent 执行。输入形如 /plan、/export；处理器直接返回 UI 结果，不创建用户消息、不启动模型轮次，也不产生工具结果。

发现

UI 获取名称、说明和可选输入提示，不接触处理器函数。

执行

注册表解析名称并保留命令后的原始输入，同时传入取消信号。

审计

已接纳命令写入配对的 command/run 与 command/done 日志事件。

语法错误或未知命令不会写日志。Agent scope 中的同名定义会遮蔽全局命令；插件卸载时注册自动撤销。

Codex 与 Claude Code Hooks#

Hooks 桥接器把现有 Codex 或 Claude Code command hook 配置映射到 Harness 的类型化拦截点。它们是兼容层；需要完整类型、更多控制或稳定扩展时，应直接编写 Cordis 插件。

SessionStart注入上下文

会话开始时运行；当前实现是脱离执行，可能错过首个请求。

UserPromptSubmit提示词门禁

可以拒绝输入，或给已接受输入追加带来源的上下文。

PreToolUse工具前决策

Codex 子集支持阻塞；Claude Code 子集还可返回 ask。

PostToolUse / Stop反馈与续行

工具后可阻塞或追加反馈；Stop 阻塞会 steer 下一步。

不是完整协议复刻

桥接器只运行同步 command hook，且各自只支持官方协议的一个子集。配置在进程加载时读取一次；不支持的事件或字段不会自动获得原产品语义。

Session 内定时提醒#

schedule_create 支持延时一次、绝对时间一次和固定速率重复三种规则。记录持久在原 Session 中，到期后排队一个普通 follow-up；不会发送外部通知，也不会唤醒 cold Session。

after_seconds延时一次接受正整数秒数，创建时换算为 UTC 目标。
at绝对时间必须显式提供 RFC 3339 偏移量或 IANA 时区。
every_seconds固定速率至少 300 秒；跳过的周期只补发最新一次。

提醒只在拥有它的 Agent live 且完全 idle 时交付，从不打断当前轮次。一次性提醒优先；多个到期的重复提醒会合并进同一个 follow-up。交付是尽力而为的至少一次，不是恰好一次。

Workflow 与 Ralph#

workflow 让模型编写 JavaScript 编排脚本，按阶段启动多个 Subagent 并返回结构化 JSON。它适合用户明确要求的大型多 Agent 编排；一两个委派仍应使用普通 Subagent。

Dynamic Workflow

脚本可使用并行与流水线组合器扇出任务；父级同步等待，并在所有路径上清理 worker 与 child。

Ralph

固定前台循环，每轮启动一个没有对话 seed 的全新 Agent，以共享工作区和有界报告交接状态。

Goal

同一 Agent、同一 Session 内跨轮持续推进，适合普通长期目标，不等同于 Ralph。

完成声明仍需验证

Ralph 的 complete 或 blocked 来自 worker 报告，没有独立评估器。普通 child 失败会终止运行而不会自动重试；取消后局部输出也不会伪装成成功。

07
可观测性成本、遥测与质量反馈

Token 计量#

Token Meter 回放当前会话的耐久日志，生成一次不可变的请求压力与 surface 定价快照。它区分完整请求/响应压力 totalTokens 和仅当前模型表层的启发式总量 surfaceTokens。

usage baseline

最近成功请求具有相同规范 envelope，且 Provider usage 足够覆盖启发式锚点。

estimated baseline

没有可安全复用的 usage 时，用固定启发式重新估算完整 envelope 与 surface。

surface delta

相对匹配基线的有符号变化，可同时表示上下文增长与压缩后的缩减。

每个 surface node 记录事件 seq 和估算 token，但数组顺序才是模型表层的权威顺序；压缩替换节点的 seq 可能比排在它后面的旧节点更大。

Session Telemetry#

Telemetry 把会话 ledger 事件和无日志归宿的 ops 信号投影成外发记录，再交给 OpenTelemetry 等 Provider。它完全位于模型请求之外，不会改变 Agent loop。

01Capture

Ledger 镜像会话事件；Ops 承载 agent-error 与 shutdown。

→
02Redact

部署方 waterfall 变换导出副本；规则抛错时 fail-closed 扣下该条。

→
03Emit

后端非阻塞入队；批处理、重试、留存和丢失策略归 SDK。

尽力而为，不是审计真源

记录可能丢失或重复，接收端应按 (session.id, event.seq) 去重 ledger。脱敏只修改导出副本，权威 Session 日志永不改写。

每个 Harness Home 的匿名身份#

Harness 会为每个 DSH_HOME 生成随机 UUID v4，供 Session telemetry、直接反馈确认和 DeepSeek Provider 请求共同关联。它保存在 .anonymous-user-id，不从 hostname、网络地址、Git remote 或其他身份材料派生。

Per home

不同 Harness Home 拥有不同身份，不提供跨 Home 关联。

Best effort

Home 不可写时仍返回仅进程内 UUID，不阻断模型请求或反馈。

Resettable

删除身份文件后，下次启动会生成新值，旧身份无法恢复。

关闭遥测不等于关闭该标头

DSH_TELEMETRY_DISABLED 只停止遥测导出，不禁止反馈确认或 DeepSeek 请求中的 x-deepseek-harness-user-id。配置自定义 DeepSeek gateway 时，该 gateway 也会收到此值。

运行时 Invariants#

Invariant Registry 让每个包注册自己拥有的运行时约束，例如事件必须成对、状态转换必须合法。检查断言权威事件流或可变数据关系，而不是简单确认某个服务或方法存在。

失败可归因到包

违规会抛出稳定 code 为 INVARIANT 的错误，并携带完整 npm package name。每个 installer 在独立 child fiber 中运行，卸载后不会遗留监听器或 trace 状态。

部署可以用 allowlist 和 blocklist 正则选择检查范围，blocklist 优先。模式在服务启动时严格校验并在生命周期内固定，确保后续插件加载与 HMR 行为确定。

消息反馈#

每条已完成 Assistant 消息可以保存好评或差评及可选备注。它是本地 Storage Domain 中的可编辑 sidecar，不是 Session 事件、模型上下文或自动遥测。

目标验证

只接受持久日志中 append-origin、非空的 assistant message，部分中断输出没有反馈入口。

乐观并发

每次更新携带 opaque version；冲突直接返回权威当前值供 UI 对账。

生命周期隔离

Sidecar 绑定 Session 的 createdAt 与 cwd；Fork 不复制父会话反馈。

Web UI 首次 hover 或 focus 时才延迟读取整段会话的反馈，避免对每条消息单独请求。删除不存在的反馈是幂等成功；备注按 UTF-8 字节限制。

08
持续执行委派、计划与长上下文

Subagent 委派#

Subagent seam 让父 Agent 通过具名 Provider 委派工作。Provider 可以在同一进程、独立进程、ACP、Codex 或 Claude Code 中运行，但父级看到的启动与结果约定保持一致。

Foreground前台一次性

父级等待最终结果，返回前总会释放子级运行资源。

Background task后台一次性

立即返回 job id，之后通过通用 Task 接口收集或取消。

Continuable可继续子级

拥有持久 Session，可接收后续消息并在需要时冷恢复。

同级委派可以并发执行，结果仍按模型调用顺序提交。子级继承父级显式沙箱覆盖，但审批策略固定为 never，避免无人处理的提权请求。

Todo 列表#

todo_write 属于当前 Agent 会话，每次调用都提交完整列表快照，而不是增量修改。条目只有三种状态：

pending

尚未开始

in_progress

正在推进

✓completed

已经完成

完整列表写入 todo/write 会话事件，支持日志回放和 UI 投影。是否允许多个任务同时处于 in_progress 由部署配置决定。

持久 Goal#

Goal 用于一个需要跨多个轮次持续推进的同会话目标。它与普通 Todo 不同：Goal 有 phase、revision、Round 上限和明确的暂停、恢复、完成与阻塞生命周期。

create→active↔pause / resume→complete

Goal Round 只在 Agent idle、目标仍 active 且有剩余容量时追加；人类消息优先且不消耗 Round。恢复会话或 fork 后，自动续行默认停用，必须由用户明确恢复。

完成需要证据

模型必须读取精确 goal id 与 revision 后再更新。困难或不确定不是阻塞；只有同一阻碍连续达到配置阈值后才能报告 blocked。

上下文压缩#

Basic Compaction 在上下文压力达到阈值时，把较早的完整历史单元替换为结构化检查点，同时逐字保留近期尾部。默认阈值为模型上下文窗口的 80%，近期保留预算为 16%。

older historytool resultsearlier turns
→
<compacted-summary>structured checkpoint
+
recent turnscurrent work

超大工具结果可先经过不依赖模型的剪枝；若压力仍高，再调用摘要模型。摘要只保存文本，不保留私有推理或遗留工具调用。压缩会替换历史，因此会移动 KV Cache 的可复用边界。

工具 Guardrails#

Guard 插件通过 tools/execute 流水线增加可靠性策略，不改变具体 Tool 的实现。当前常见的两类保护是协作式超时与重复调用提醒。

⏱
Timeout Policy

从 Tool Definition 读取 timeoutMs，通过 exec.signal 通知截止，并返回结构化 TOOL_TIMEOUT。

协作式，不是硬终止
↻
Repeat Reminder

按 Agent 统计同一工具和规范化参数的连续调用，在 3、5、8 次等阈值注入逐级提醒。

提供建议，不阻止调用

不受跟踪的记录类工具对重复链透明，因此在两次相同调用之间写 Todo 不会掩盖循环。各 Subagent 的重复链彼此隔离。

后台任务#

长时间运行的 Bash 与 Subagent 共用后台任务运行时。启动后会立即得到形如 bash-1 或 subagent-2 的 job id，再通过统一接口查看状态、增量读取输出、等待完成或请求终止。

running

生产方持有执行资源，任务可读取新输出。

stopping

终止请求已发出，等待生产方释放资源。

✓completed / killed / failed

终态不可逆，并记录结束时间与详细原因。

输出读取使用单一消费游标：流式任务每次返回上次读取后的增量，只有最终输出的任务则在结束后重复返回同一结果。任务访问按拥有者 session 授权；Agent 被释放时，其任务会被取消并等待清理完成。

取消不是瞬间完成

kill 只请求生产方终止并把状态推进到 stopping。只有生产方真正释放资源、done settle 后，任务才进入 killed 或其他终态。

会话检索与日志导出#

可选的 Session Query 工具让 Agent 从既往工作中找回上下文，而不必把所有历史塞进当前请求。搜索先返回标题和最佳匹配摘要，再按需读取事件、关系或会话谱系。

01session_search跨会话发现相关工作
→
02event_search缩小到会话内事件
→
03trace / read取得谱系、关系或原始数据

跨会话访问要求目标与调用方的 cwd 严格相同；当前会话的搜索会截止到调用步骤之前，避免工具匹配自身。搜索文本按字面量、不区分大小写并灵活匹配空白，过滤条件之间为 AND，同一列表内为 OR。

导出完整审计材料

Web UI 的 Session log 按钮或 /export 会下载包含根会话、子会话和附件的流式 ZIP。命令只在用户命令平面执行，不创建模型轮次，也不消耗模型 token；下载位置由浏览器决定。

结构化跨会话引用#

宿主可以把选中的历史 Session 作为结构化引用附在新消息上，而不是把 UI 的 @mention 语法传入核心。Session id 是权威身份，label 只是快照显示信息；候选项使用最新持久标题，并按当前工作目录亲和度排序。

01Discover

只搜索 session id、cwd 与标题，不扫描 transcript 正文。

→
02Snapshot

入队前读取所有引用并施加数量与字节预算，拒绝自引用。

→
03Attach

移除宿主 mention token，保留可读消息，并追加一个不可信聚合上下文。

错误通过稳定 code 区分无效引用、源读取失败、预算超限和取消。准备结果是不可变快照：源 Session 后续变化不会悄悄改写已经排队的目标消息。

会话标题的生成与固定#

标题是后写覆盖的持久日志状态。内置 fallback 或可选 Provider 会根据合格的人类文本消息生成标题，并记录精确的来源消息 seq；用户手动重命名后，标题会被固定，后续自动生成停止调度。

Fallback

没有 Provider 时仍可从合格输入生成确定性的基础标题。

Provider

异步生成会记录提供方、模型路由、系统输入、消息输入与输出上限。

User rename

显式重命名会抢占正在生成的修订；主动 refresh 才会重新解锁生成。

服务接纳结果时会验证来源 seq、规范化非空文本并执行 UTF-8 字节上限。即使辅助 LLM 最终失败，请求记录仍能还原当时模型实际看见的输入与路由。

会话持久化与恢复#

内存中的仅追加 SessionEvent 日志是真源，Persistence seam 负责把同一组事件耐久保存；它没有另造一套“持久化事件”。元数据 header 与日志分开保存，记录格式版本、cwd、父会话、seed 边界、委派深度和 Agent preset。

01后台批量追加

同步事件通知只复制到会话控制器，固定窗口内的事件合并成耐久批次。

→
02语义检查点

模型请求、顶层工具副作用与下一步开始前执行 flush，失败则阻止继续。

→
03冷恢复

崩溃留下的开放轮次不会被截断，而是补记 interrupted 结束事件后回放。

持久化意图不等于恰好一次

工具调用可能已经产生外部副作用、但结果尚未落盘。恢复时 Harness 会写入 TOOL_OUTCOME_UNKNOWN，要求先验证状态；有副作用的 Provider 应尽量把 call id 用作幂等键。

JSONL 后端为每个会话维护可选 Zstandard 压缩的追加日志；SQLite 后端则把每个事件存成一行。格式版本过新、过旧或遇到未知的必需事件时会明确拒绝恢复，而不是静默丢失语义。

会话投影与冷读取#

Session Projection 把仅追加事件日志折叠成供客户端直接消费的完整领域状态。每个领域只注册同步的 init → apply → view 纯计算单元；框架统一订阅已提交事件，客户端从不自行重放领域事件。

01Fold

无关事件必须返回同一 state 引用，从而不触发下游工作。

→
02Snapshot

所有 key 共享一个 asOfSeq 水位线，输出先通过各自 schema。

→
03Cache

状态版本与 seq 写入耐久缓存，冷会话只回放缺失尾部。

缓存是性能层而不是真源：版本变化或日志因崩溃修复而缩短时，旧行会失效并回退到完整重放。写后缓存失败只记录警告，下一次检查点或冷读会自愈；插件卸载后，其投影 key 会从快照中消失。

非会话数据的领域存储#

设置、索引等不属于对话事件日志的数据进入 Storage subsystem。枢纽只负责注册后端和挂载数据形式，不执行 IO；领域层声明名称、格式版本、global slot、表和 zod schema，再按部署路由到 JSON 或 SQLite 后端。

JSON backend

每个 unit 原子重写一份人类可读文件，适合体量较小、更新不频繁的数据。

SQLite backend

在单个数据库中逐行存储文档，适合频繁更新和更多记录。

Domain API

同步读取权威内存态；写入先持久化，再更新内存并发出变更事件。

同一领域的写入按顺序排队。后端写入失败时内存保持不变，因此读取不会领先于介质；格式版本不匹配或已存记录不符合 schema 会在打开领域时立即失败。

超大工具结果与 Spill#

当工具返回的纯文本超过内联预算时，Spill policy 保存完整 UTF-8 内容，并用首尾预览、不透明定位符、准确字节数和后端给出的检索提示替换模型结果。模型不会被迫为完整大结果支付上下文成本，但仍能按需读取。

full tool text→private spill artifact→head + tail preview→retrieval hint

本地后端使用会话 id 的摘要作为私有目录，并以排他、仅所有者可读写的方式创建随机文件。调用方提供的文件名只是命名提示，永远不会被当作路径；定位符同样是不透明句柄。

尽力而为的降级

如果磁盘满、权限不足或后端不可用，Spill policy 会保留原始内联结果，不会把已经成功的工具调用改成错误。Fork 会继承日志中的旧定位符，但不会复制或重新归属已有产物。
